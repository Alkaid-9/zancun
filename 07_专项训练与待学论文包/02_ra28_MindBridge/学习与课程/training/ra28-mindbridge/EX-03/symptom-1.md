# Bug Report #1：多轮对话后助手"失忆"，只记得会话开头的内容

**报告人**: 内测同学（学生端试用反馈） + CI 值班
**严重度**: 用户可感知的核心体验问题
**分支**: `training/ex03`

## 现象描述

一位内测同学做了一次较长的连续咨询（十几轮往返）。前几轮体验正常，但从大约第 9-10 轮开始，助手的回复越来越"答非所问"：

- 同学最近两三轮明明在说"这周和室友闹矛盾"，助手却还在回应会话最开头提到的"上个月的考试压力"，并且反复重复开头几轮已经给过的建议；
- 同学补充的新信息（新的情绪变化、新的事件）在后续回复里完全没有被引用；
- 会话轮数越多，这种"卡在开头"的感觉越明显，几乎像是助手把最近说的话全部丢掉了。

短对话（少于 8 轮左右）看不出异常。

另外 CI 值班注意到：同一分支上跑仓库自带的单元测试套件，有 1 个用例失败（基线 commit 上全绿）。不确定是否与上面的反馈是同一件事，一并记录在这里。

## 复现步骤

环境说明：无需 MySQL/Redis/Ollama，模块级即可复现。以下命令假设已检出 `training/ex03` 分支；`<CHECKOUT>` 代表检出目录（如为 git worktree，Python 解释器请用主仓 venv 的绝对路径）。

```bash
cd <CHECKOUT>/mindbridge-py
/mnt/d/Workspace/mindbridge/mindbridge-py/.venv/bin/python -m unittest discover -s tests
```

观察：17 个用例中 1 个失败（基线 9e1e239 上同命令全部通过）。失败用例的断言输出里能看到具体期望，可作为排查起点。

## 期望行为

- 无论对话多长，助手都应该记得**最近几轮**说过的内容；较早的内容可以被归纳、压缩，但不应该反过来只记得开头、丢掉最近。
- 单元测试套件在本分支上应全部通过。
