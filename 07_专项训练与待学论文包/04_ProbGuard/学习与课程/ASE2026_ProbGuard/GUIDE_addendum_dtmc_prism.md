## §一 先读三行(所有人)

1. **先读笔记 ⓪ 节**:同一仓有三套格式事实(V-HEAD 现行代码 / V-产物 仓内现成 dtmcs / V-README 文档宣称),照抄任何东西前先确认取哪层——这是全笔记唯一的"必读前置"。
2. **HEAD 跑不通是前提不是坑**:笔记通篇只描述格式,不担保可执行;要跑,走 teardown §5 复现路线(P0 起步)。
3. 标注约定:〔反推〕= 由产物数字反推的旧版行为,未经代码考古证实;"待复现窗实测" = 语法/数值未跑过 PRISM 验证。两类都不得当已证事实外引。

## §二 按场景使用

### 场景 1|我在补 T5 谓词表 v0(16 谓词)的管线字段

读:**§⑨ 检查表**(6 列定义)→ §3.1(谓词 JSON 形状与 `lhs_op_rhs` 命名)→ §2.3(观测 dict 硬约束:所有 lhs 键每快照齐全)。
做:给 v0 每行补 `bit_index / lhs / op / rhs / bool_var / unsafe 掩码 /(可选)absorbing`;时间窗谓词先按 §2.3 clock 注入约定改写成普通原子;**冻结行序**(位串 schema 本体)。
自检:16 行 op 全在 OP_MAP 六种内;bool_var 无重名;unsafe 掩码至少一行非空(否则 §⑧ filter 出空集,PCTL 无查询对象)。

### 场景 2|我在开 W-复现窗(LP-01),要跑通离线通道

读:⓪(层告警)→ §7.3(冒烟命令,用样例 B 的现成文件)→ §4/§6.1(P2 学习通道的验收对照:概率行分母 n_i+k_i·α、浮点分数样式、虚拟态行)。
做:P0 冒烟后把实测 `Result:` 值回填维护手册台账 L3;顺手实测 §7.2 的 `filter(printall, …, true)` 语法(台账 L1)。
注意:样例 B 是**旧版产物**,别拿它对照 HEAD 重跑输出——对照物是样例 A 与 §6.3 对照表。

### 场景 3|我在写 CompanionAbstraction(T5 换域原型)

读:**§⑨ 六项义务**(5 抽象方法 + de facto `to_json`)→ §3.4/§3.5(FINISH 特判、sorted 修正)→ §4-1/2(两针修正:分子 α 条件化+归一断言、Fraction 化)→ §7.3(弃用 init 改写,离线预计算表)→ §⑧(unsafe 集走 AV 版 filter,具身版是坏的)。
做:参照 teardown §6.1 的方法对照表写子类(预估 150-250 行);`state_interpret` 采用 AV 字典形状(§5.3),否则 filter 不可用。
自检:encode 不改写输入观测;`valid_trans(FINISH,·)=False`;启用剪枝后必开归一断言。

### 场景 4|我在写论文/提案/对外材料,要引用 ProbGuard 的导出格式

读:⓪ + §6.3 对照表。
纪律(与维护手册 §五同源):任何"ProbGuard 导出格式为 X"的句子必须带层声明(HEAD 代码/仓内产物/README 宣称);〔反推〕项引用时保留"由产物反推"限定;不得写"已验证可跑"(本窗未运行)。
