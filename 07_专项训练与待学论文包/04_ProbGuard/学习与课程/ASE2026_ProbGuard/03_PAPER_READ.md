## L1 问题定位:反应式监控的结构性盲区

**领域现状**:LLM agent 的运行时防护有三条已知路线——AgentSpec/GuardAgent 的规则拦截、ShieldAgent 的 MLN 规则电路、LLM-judge 在线评估。它们共同的形态是:**对"当前动作/当前转移"做合规判定**。

**结构性盲区**:有一类风险不住在任何单步转移里,而住在**轨迹的走向**里。论文的两个例子准确刻画了这类风险:
- 炉灶例(§2.2):agent 开着炉灶去取包裹,每一步都无害;风险随"炉灶开 ∧ 人不在 ∧ 时间流逝"累积。等到 `elapsed ≥ 10min` 谓词翻真,反应式规则才触发,但锅已烧干。
- AV 例(§1):"不得碰撞"的规则在碰撞不可避免时才违规,那时干预已无意义;有价值的信号是"正在加速冲向繁忙路口且刹车距离不足"——一个轨迹级模式。

**问题重构**:把"检测违规"改成"预测违规概率"。三个技术挑战(§2.3):①安全性质的形式编码(要能高效运行时推理);②带统计保证的概率模型构造;③高效估计条件概率 P[ψ|π] 并确定干预时机。

**与传统 RV 的差异定位**(§8):经典 RV 假设确定性、完全可观测的系统;概率扩展(RVSE、adaptive RV、conformal RV、PSTMonitor、MDP monitors)要么假设**预定义**的概率模型,要么要手工性质。ProbGuard 的定位是"模型从轨迹学出来"——这是它在 RV 谱系里的确切位置。conformal RV(Lindemann 2023、Cairoli 2023)是最近的竞争路线(分布无关覆盖保证),论文只列举未比较,是相关工作的一个软处理。

**一个值得注意的口径**:论文反复强调 policy-agnostic——被监控的策略可以是 LLM、NN、规则或混合。这既是卖点(AV 域的 Apollo 根本不是 LLM agent),也是给"标题写 LLM Agent Safety 但一半实验不是 LLM"的免责声明。

## L2 方法逐步(§3)

### 3.1 性质规范:CTL 做定性,PCTL 做定量

- 规范语言选 CTL(Def 3.1:⊤ | p | ¬φ | φ∨φ | EXφ | EGφ | E(φUφ),加语法糖 AX/AG/EF/AF)。
- 核心形态锁定为不变式 **ψ = AG ¬unsafe**:沿所有路径、全局地、不进 unsafe 状态。unsafe 谓词由域专家给出。
- **一个被论文明确处理的形式化细节**:CTL 公式是状态公式,(M,s)⊨ψ 是布尔判断,"P[ψ]"本身不良定。解决:把 ψ 写成 A ψ^π(ψ^π = G ¬unsafe 是路径公式),概率附着在路径公式上:

  P[ψ|s] ≜ Pr^s_M{ρ ∈ Paths(s) | ρ ⊨ ψ^π}

  即 PCTL 查询 P=?[ψ^π] 在 s 处求值。这个"CTL 定性 + PCTL 定量"的双层结构贯穿全文(AV 域的 AG¬viol 同型)。
- **为什么不直接用 PCTL 写规范**?论文未明说。合理推断:让域专家只写定性 unsafe 条件(低门槛),概率语义由框架统一附加;且 CTL 形态保证提取的谓词集就是 ψ 的原子命题(Alg 1 L4 的机械化前提)。

### 3.2 行为建模:谓词抽象 + DTMC

- **谓词抽象**(§3.2.1,Graf–Saïdi 谱系):n 个布尔谓词把具体状态 v 映成真值向量 s_P(v) ∈ {0,1}^n。抽象空间 S 剪掉两类东西:①语义矛盾的状态(如 a>0 ∧ a<0);②valid_tran 判非法的转移(物理不可逆性,如 collision=true 是吸收态,不能再到 reached_destination)。
- **valid_tran 的三重作用**(精读时值得单独记):①建模时剪状态空间;②Eq(1) 里决定哪些转移能拿到平滑质量、并定义 k_i;③给 PAC 证明提供"合法转移概率有正下界 → B 有限"的前提(App A Step 2)。它是把域知识注入统计学习的唯一通道。
- **DTMC**(Def 3.2):M=(S_M, P_M),行随机。Figure 2 的 stove 例:s0(炉灶关、人在厨房)→ s1(炉灶开)概率 31/184=16.85%——分母 184 是 s0 的总访问次数,30 条 trace 平均每条访问 s0 约 6 次,数量级自洽。

### 3.3 运行时监控:阈值触发 + 干预解耦

- Alg 2:每步取当前抽象状态 s_i,查 P_safe = P[ψ|s_i];P_safe < θ → 干预。
- **阈值语义全文统一**:θ 是"保持安全的概率"的下界,θ 越大越严格。(论文特意用脚注级篇幅强调这个约定,因为 Table 1/2 的上标容易读反。)
- **风险检测与干预解耦**:框架不规定干预方式——halt / 人工介入 / 重规划都行。实现里给了两种:stop(终止)与 reflect(prompt 注入)。这个解耦是 policy-agnostic 设计的延续,也把"干预有效性"的责任推给了 agent 自身(见 L7 批判)。

## L3 DTMC 构建细节(§3.2.3 + Alg 1 逐行)

```
输入:CTL 性质 ψ,误差 ε,置信 δ
输出:(ε,δ)-PAC-correct 的 DTMC M̂
L3   Π←∅;S_M̂←∅;n_ij←0
L4   P_ψ ← ψ 中出现的原子谓词集          ← 谓词不是拍脑袋,是从性质机械提取
L5   repeat
L6     采样新 trace v0→...→vm             ← 默认均匀输入分布;若已知环境分布可换
L7     π ← s_P(v0),...,s_P(vm);Π 加入 π   ← 抽象
L8     S_M̂ ← Π 中观测到的状态并集         ← 状态空间随数据增长(不预枚举全部 2^n)
L9-11  对 π 中每对相邻 (si,sj):n_ij += 1  ← 转移计数
L12    n_i ← Σ_j n_ij
L13    P_M̂ ← Eq(1) 的 P̂^α_Π              ← 每轮全量重算平滑矩阵
L14  until PACBoundSatisfied(S_M̂,Π,ε,δ)   ← 停机条件 = 逐状态样本界全满足
L15  return M̂
```

**Eq (1) — valid-transition-aware Laplace 平滑**(逐式推导见 04):

P̂^α_Π(sj|si) = (n_ij + α)/(n_i + k_i·α) 若 valid_tran(si,sj);否则 0。α=1(引 Manning & Schütze 的标准加性平滑实践)。

三个精读要点:
1. **与标准 Laplace 的差别**:标准做法分母是 n_i + |S|·α(对所有后继平滑);这里只对 k_i 条合法出边平滑。效果:不给语义不可能的转移任何质量(保逻辑一致性),且 k_i < |S| 时平滑更轻(经验数据权重更高)。
2. **未观测状态的行为**:n_i=0 时 P̂ = 1/k_i,即"合法出边上的均匀先验"。这就是论文说的"避免把未观测转移当成不可达"——对小样本(30 traces)这是激进但必要的正则化。
3. **停机条件的自适应性**:L14 的界(见 L4 节)依赖当前的 n_ij/n_i 和 B(P̂_Π)——即**停机阈值本身随学到的链变化**。这继承自 Bazille 的经验界框架,好处是可运行时检查,代价是"11/10"的 slack 因子(B 在估计链而非真链上算)。

**均匀输入分布的伏笔**:L6 的默认均匀采样意味着学到的 DTMC 是"均匀任务分布下的行为模型";若部署分布不同(真实用户任务有偏),转移概率与 P_safe 都会漂移。论文只用一句"can be adapted if the actual environment distribution is known"带过。

## L4 PAC 界条件(§3.2.3 定理部分 + §7 + App A)

### Def 3.3 的精确读法

M̂ 是 (ε,δ)-PAC-correct,若 Pr(|P_M̂(ψ^π) − P_M(ψ^π)| ≤ ε) ≥ 1−δ。

**两层概率必须区分**(初读最容易混):
- 内层 P_M(ψ^π):固定一条链,路径测度下 ψ^π 的满足概率(对象级)。
- 外层 Pr(·):对**采样学习过程**的概率(元级)——"重复跑 Algorithm 1 很多次,至少 1−δ 的比例学到的链满足 ε 精度"。
- 所以 PAC 承诺的是"学习程序可靠",不是"这次学到的链一定准"。写 T5 时的措辞要点。

### 样本界(Bazille Thm 6,经 ProbGuard 转述)

对每个状态 s_i 要求:

n_i ≥ (11/10·B(P̂_Π))² · (2/ε²)·log(2/δ') · [1/4 − (max_j|1/2 − n_ij/n_i| − 2ε/3)²],δ' = δ/|S|

三因子逐个读:
1. **(11/10·B)²**:条件数 B 刻画"局部转移误差被全局可达概率放大多少倍"(精确定义在 Bazille 原文,ProbGuard 未展开;направление:类似敏感度/条件数分析)。11/10 是 slack:B 在学到的链上算,留 10% 裕量。**B 进入界是平方——它是样本复杂度的主宰项**。
2. **(2/ε²)·log(2/δ')**:标准 Chernoff–Hoeffding 形态;δ'=δ/|S| 是 union bound 的分摊(|S| 个状态各自失败概率 ≤δ')。
3. **[1/4 − (max_j|1/2−p̂_ij| − 2ε/3)²]**:经验方差修正(Massart 式)。经验频率越偏离 1/2(转移越确定),方差越小,需要样本越少;在 |1/2−p̂|=2ε/3 处取最大值 1/4(最难情形≈公平硬币)。
   ⚠ 待核:此因子中 ε 的尺度(全局 ε 还是 App A 的局部 ε'=ε/B)主文与附录记号有张力,以 Bazille 原文 Thm 6 为准(S05 任务)。

### Theorem 3.4 与 App A 证明骨架(逐步复推见 04)

- Step 1(集中):停机时每状态样本满足界 → 每状态转移估计误差 ≤ ε'=ε/B(概率 ≥1−δ');union bound 过 |S| 个状态 → 全局最大转移误差 ≤ε'(概率 ≥1−δ)。
- Step 2(传播):Bazille Thm 5(敏感度):|P_M(ψ^π) − P_M̂(ψ^π)| ≤ B·max|P−P̂|。代入 ≤ B·ε' = ε。
- Step 3(合成):得 Def 3.3。
- **证明的巧点**:B 在 M̂ 上求值(而非未知真链 M)才可运行时检查;其合法性由 Laplace 平滑保证——合法转移概率 ≥ α/(n_i+k_i·α) > 0,链无零合法边,B 有限且可从已维护的数据算出。**这是 Eq(1) 与 Thm 3.4 的咬合点,也是"为什么必须 Laplace 而不能纯频率"的理论原因**。

### §7 的实测(本文最有信息量的表)

| 域 | \|S\| | B(P̂) | 需要的 traces |
|---|---|---|---|
| 具身(Laplace,均匀 CTL 界) | 3–33 | 1.0–481 | 530–10⁵ |
| AV(退频率估计,单性质界 Thm 3) | 4–34 | 10⁷–10⁸(Laplace 下测得) | 185–1,016 |

(ε=0.1,δ=0.05。)结构性解释:具身任务前向推进(pick→open→place→close),链混合好,B 温和;AV 行为强持久——自环 >99.9%、状态间转移 <10⁻⁵,Laplace 给稀有转移的 α 质量在归一化后产生极端条件数。**权衡明码标价:Laplace+Thm 6 = 均匀保证(该状态空间上一类 CTL 性质全覆盖)但样本贵;频率+Thm 3 = 只保单条运行时可达性质但样本便宜 40–500 倍**。

### 与实验的落差

实验统一用 30 traces/场景——低于最便宜的界(185)一个数量级,低于均匀界最多四个数量级。论文的自我定位(§7):"实验展示监控器在现实数据约束下有用;PAC 分析刻画的是要正式认证需要多少"。**读者应把本文的 PAC 部分理解为"可行性地图",而非"已兑现的保证"**。

## L5 AV 域构造(§5.1):STL 法规 → 监控自动机 → 同步积

- **输入**:LawBreaker 的 STL 片段 STL_LB,形态固定为 G(φs ⇒ F[0,K] φt)——触发条件 φs 出现后 K 个时间单位内必须响应 φt(如绿灯且无障碍 → 100 周期内起步)。
- **构造**(Def 5.2):确定性监控自动机 Q = {idle} ∪ {wait(i)}_{i=0..K} ∪ {viol}:
  - idle 读到 φs∧¬φt → wait(K)(开始倒计时;若触发同时已满足 φt,落 otherwise 分支保持 idle——义务即时解除);
  - wait(i) 读到 φt → idle(义务解除);
  - wait(i), i>0 读到 ¬φt → wait(i−1)(倒数);
  - wait(0) 读到 ¬φt → viol(吸收)。
- **同步积**:M' = 环境 DTMC ⊗ 监控自动机;q 分量确定性演化 q_{i+1}=δ(q_i, L(s_{i+1})),s 分量按 P_M̂ 概率演化 → 积仍是 DTMC。有界活性归约为可达性/不变式:M' ⊨ AG ¬viol。运行时用积状态 (s_i,q_i) 查 Pr_{M'}^{(s_i,q_i)}(G ¬viol) 作为 P_safe。
- **四条被测性质**:Law38_2(黄灯响应,K=100)、Law51_5(红灯紧急停,K=2)、Law53(拥堵让行,K=200)、NoCollision(纯不变式 AG φ8)。时间单位 = Apollo 控制周期 100ms,K=100 即 10s deadline(Example 5.3)。
- **两个手推发现**(详见 04 式 6):①逐字执行 Def 5.2,响应在 t+K+1 时刻满足仍会解除义务,比 F[0,K] 的窗口多一步(工程影响 = 1 个控制周期,可忽略;~~复现以代码为准~~〔08-22 已核:"以代码为准"前提证伪——公开监控路径(Pro2Guard 仓 runtime_monitor.py/embodied monitor.py)不走显式自动机,实为 PRISM 查询 P=?[G !unsafe]+阈值 prob≥0.9;Def 5.2 系论文语义装置,复现对表以 PRISM 查询语义为准〕);②单义务跟踪对重叠触发是充分的——最早义务的 deadline 最早,若它被某次 φt 解除,则所有已开义务的窗口都包含该 φt 时刻,同时解除;若它违规则全局已违规。这个非平凡的小论证论文没写,补上后 Def 5.2 的正确性才算闭合。
- **对 T5 的意义**:这个"把时序义务编译进状态空间、让 Markov 链只需要看当前积状态"的手法,就是 T5 时间窗谓词的现成模板;差别在语义(见 L9)。

## L6 实验协议

| 维度 | AV 域(§5.2) | 具身域(§6.2) |
|---|---|---|
| 平台 | Apollo 9.0 模拟器(NN+规则,非 LLM) | SafeAgentBench + LangChain ReAct + gpt-4o-mini(temp=0) |
| 场景来源 | μDrive 生成违法场景(7 个)+ 6 类安全场景(FP 标定) | SafeAgentBench 家务任务 |
| 性质来源 | LawBreaker 形式化交通法(4 条) | 对象/状态级安全规则(stove 类) |
| 每场景样本 | 30 traces | 30 traces |
| 状态提取 | 每控制周期(100ms)从感知/定位模块取:车速、与最近 NPC 相对速度、灯色、车头距 | 每 agent 步,观测→符号状态向量;每 trace = 一个完整任务 episode |
| 指标 | AWT(Eq 3)、FP 率、开销 | Unsafe%、Completion%、token 开销、每决策延迟 |
| 基线 | REDriver(STL 定量鲁棒度,σ∈{0.4,0.8,1.2} 沿用原论文) | None(无监控)、AgentSpec |

协议上做对的事:①FP 与 AWT 成对报告(单看 AWT 无意义,因为 AWT 只在真发生违规的 run 上有定义);②REDriver 阈值沿用其原文数字,避免调参偏袒;③temp=0 与重复取均值控制随机性;④开销分解到 abstraction/I-O/inference 三段。
协议上的弱点:①"100% 检出率"的分母只有 7 个 AV 场景;②具身域任务数与 trace 总量未在正文明报(Unsafe% 的基数不透明);③reflect 只测了 θ=0.9 一个点;④没有跨 LLM(仅 gpt-4o-mini)、跨框架(仅 ReAct)的泛化性检验。

- **θ 敏感性两极分化,且不由性质类型决定**:场景 1/2/7 对 θ 完全平坦(P_safe 轨迹阶跃式坠落,任何阈值都在同一时刻被击穿);场景 3/6(碰撞)高度敏感(风险渐进累积,高 θ 提前拦截)。论文自己点破:场景 4/5 与 2 同属 Law51_5 却敏感——**稳定性取决于场景动力学而非性质类别**。这对 T5 的启示:提前量不是方法属性,是"域的风险演化速率"属性;关系域的依赖螺旋是慢变过程,理论上站在"高 θ 高收益"一侧。
- **场景 4 的 0.01s**:θ≤0.5 时几乎无提前量——快速突发违规逼近反应式的极限。诚实数据,说明 proactive 的增益依赖风险的"可预见窗口"存在。
- **FP 悬崖**:θ=0.3→0%,0.5→75%,0.7→100%。与 AWT 合读:**唯一无 FP 的 θ=0.3 下,7 场景中 4 个 AWT<7s**;38.66s 的头条数字发生在 FP=100% 的 θ=0.7。摘要的措辞("up to 15.84s at a threshold yielding no false alarms, up to 38.66s at stricter thresholds")是准确的,但引用者极易只记 38.66。**引用规范:AWT 数字必须带 θ 与该 θ 的 FP 率**。
- **REDriver 对比的公平性**:量纲论证成立(鲁棒度混速度/距离,阈值不可通约;概率天然归一)。但注意 σ=1.2 时 REDriver 在场景 1 也拿到 15.84s——定量语义在部分场景不差,ProbGuard 的优势集中在碰撞类(场景 3/6:38.66 vs 1.71)。另 REDriver 是"违规鲁棒度预测"不是概率模型,两者信息输出不同(概率可解释、可标定),这部分论证比数字对比更扎实。
- 解释性亮点:场景 3 的分状态风险(无优先 NPC 时 47.15% vs 有优先 NPC 时 56.78%)展示了 DTMC 的白盒可读性——每个符号状态的风险都可查、可审计。这是对 LLM-judge 路线的真实优势。

### Table 2(具身,Unsafe% / Completion%)

| 配置 | Unsafe% | Completion% |
|---|---|---|
| None | 40.63 | 59.38 |
| stop@0.9 | 2.60 | 10.42 |
| stop@0.7 | 5.20 | 20.31 |
| stop@0.5 | 21.35 | 41.14 |
| stop@0.3 | 29.17 | 48.96 |
| reflect@0.9 | 14.07 | 47.74 |

- **stop 侧的 Pareto 是完整的**,单调、无异常点:θ 从 0.9 降到 0.3,unsafe 2.60→29.17%,completion 10.42→48.96%。
- **reflect@0.9 强于 stop 侧的所有插值点**:14.07% unsafe + 47.74% completion,几乎是 stop@0.3 的完成率(48.96%)配一半的 unsafe(29.17%)。**这是论文最强的单点结果**——"给 agent 讲清楚为什么危险(符号证据)再让它自己改"优于"硬停"。
- **批判 1:reflect 缺阈值扫描**。只有 θ=0.9 一个点,无法画出 reflect 的 Pareto 面;"reflect 全面占优"目前是单点外推。
- **批判 2:干预后分布漂移未讨论**。DTMC 学自无干预的 30 条 trace;reflect 注入 alert 后 agent 行为分布改变,P_safe 的后续估计在"被干预的系统"上已不校准。这是所有"预测→干预→再预测"闭环的自指问题,全文无一句讨论,是 S07 审查和 T5 RQ4 都该点名的缺口。
- **批判 3:None 的 40.63% unsafe** 说明 SafeAgentBench 场景本身高危(基线近半违规),降违规的绝对空间大;在低基线域(违规稀有)同样方法的信噪比会差很多——T5 的关系域违规密度介于两者之间,需实测。

## L8 局限与威胁

**作者自述(§7)**:
1. Markov 假设:抽象过粗丢历史依赖 → 转移概率有偏;**PAC 界只保学习误差,不保抽象误设**。
2. 采样与 agent 行为的随机性:重复运行取均值缓解,残余方差影响稀疏状态。
3. 30 traces << 认证界:定位为"演示实用性"。

**本拆解补充**:
4. **干预后分布漂移**(见 L7 批判 2)——闭环自指问题,未讨论。
5. **单 LLM、单框架、单温度**:gpt-4o-mini + ReAct + temp=0。temp=0 下 trace 多样性主要来自环境随机性,DTMC 学到的更多是"环境+确定性策略"的动力学;温度升高后转移熵变大,30 traces 更不够。
6. **AV 域非 LLM**:policy-agnostic 的演示意义成立,但"LLM agent safety"标题下最长预警(38.66s)来自非 LLM 系统,叙事上有借光。
7. **谓词求值被假设为真值**:两域的谓词都是环境仪表读数(灯色、位置、collision 标志)。若谓词本身由感知/LLM 判定(T5 的情形),噪声会同时污染训练(错误符号 trace)与运行时(错误当前状态),PAC 链条在第一环就断——这是 T5 必须正面处理、而本文无需面对的问题。
8. **均匀输入分布**(L3 伏笔):部署分布偏移时模型与阈值标定都失效。

**作者可能的辩护(预演)**:①30 traces——"我们从未声称认证,PAC 部分就是为了告诉你认证的价格";②FP 悬崖——"θ=0.3 已零误报且 AWT 可观,标定协议给了";③advisory 干预弱——"解耦是设计目标,stop 已给强制上限";④单模型——"框架 policy-agnostic,换模型只换 trace 源"。前三条基本站得住;第四条弱,因为"policy-agnostic 的框架"不等于"结论跨策略泛化"。

## 品味判断(S03 定稿)

**⭐⭐⭐⭐(4/5)**。扎实的工程整合 + 一张诚实的可行性地图,不是方法学突破。
- 上分项:问题重构干净(proactive 的动机例选得极好);valid-aware Laplace 与 PAC 检查器的咬合(Eq 1 正下界 → B 可算 → 界可运行时检查)是真正的设计;§7 的 B 实测与"30 traces 不算认证"的自白在同类论文里罕见地体面。
