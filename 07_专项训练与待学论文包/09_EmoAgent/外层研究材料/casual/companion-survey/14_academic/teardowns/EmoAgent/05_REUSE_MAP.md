### 1.4 EmoGuard 审计边界与 clean-room 需求

**冻结仓可审计到**:四模块类、同步串行的三个分析器调用加 Manager 汇总,以及按 key 最新版本递归重写的单次 `update_profile()` 原语。

**冻结仓没有**:
- 论文所述每三轮触发的运行时调度;
- 将文本建议注入下一轮角色回复的可执行链路;
- “全量评测→筛例→归因→汇总→更新→下一轮”的完整外环和提前停止控制;
- 有/无防护两臂的运行清单、固定输出与 Figure 7/9 provenance。

clean-room 骨架当前只能用 FakeProvider 验证抽象调度、状态更新和统计接口。将上游函数或默认 profile 接入实验,以及实现忠实量表/角色行为,均属于 C1 条件式步骤。

## ② T5 评测集成方案

### 2.1 EmoEval 模拟用户 → T5 M4 评测

T5 §4 M4 原文:"INTIMA 368 prompt + EmoEval 模拟脆弱用户;度量安全率/误干预率/人格一致性/开销;≥3 seeds,mean±std"。落地接法:

1. **被测端接口**:C0 只接 FakeProvider;C1 门禁关闭后才可接自架/自有平台的长期陪伴角色 agent。任何阶段都不适配 Character.AI 非官方调用;
2. **病人端 clean-room 重建**:只继承论文层面的“profile 参数化环境 + 多话题轨迹 + 前后数值观测”结构,使用我方中性自造 profile/topic 和 FakeProvider;不得原样导入 9 个 CCD、话题或敏化 prompt。许可关闭前不做 PDI/PANSS 忠实施测;
3. **双观测通道**:C0 以自造 initial/post 数组作通用结果通道,并逐轮记录 clean-room 谓词事件;C1 只有在具体量表授权后才可增加对应量表分差,PDI/PANSS 在门禁关闭前不启用;
4. **指标映射**:

| EmoEval 指标 | T5 语义 |
|---|---|
| 恶化率 R | E1:观测样本中 `S_final>S_initial` 的经验频率,只在所声明的模拟协议和聚合口径下解释 |
| `ΔPHQ-9≥5` 模拟阈值命中率(MCID proxy) | E1 的另一个经验尾部终点;可作为未来符号查询的观测目标,但不自动证明 `P≤δ` |
| (新增)独立事件标签轨迹 | 由独立标注或预注册操作定义产生,作为检测/触发评价参照;护盾触发是预测输出,不得自充 ground truth。标签可靠性与分歧须另报;没有独立标注时只能报告“相对预注册操作标签”的结果 |

5. **协议修正(T5 采用该行为范式时必须做)**:≥3 seeds 报 mean±std(这是我方稳健性门禁,不是由 §5 数字不一致所证明的原论文运行属性);R、MCID proxy 命中率与分数变化分布三档并报;实验前冻结独立标注规范或操作定义,将逐轮事件标签与护盾触发日志分栏记录,并另报标签可靠性和标注分歧;跨臂使用同一 clean-room 测量协议只能减少协议差异混杂,不能证明偏差必然抵消;扩充 profile 时须由我方原创并保留专家审校与 provenance;
6. **E2/E3 隔离**:将 E1 事件写成 PCTL 查询前须新增状态抽象、事件谓词、转移模型和校准;只有估计不确定性支持阈值判定且 PAC 样本条件实际满足时,才可另报 E3 保证;
7. **与 INTIMA 368 prompt 的分工**:INTIMA 测单点行为倾向(边界维持 vs 陪伴强化),该 clean-room 范式测多轮累积后果(数值分差)——M4 用前者做行为面覆盖、后者做后果面深探,互不替代。

### 2.2 EmoGuard → T5 基线②复现方案

- **当前配置**:仅以 FakeProvider + 中性自造 profile/topic + 通用数值分数测试 clean-room 调度;不使用 EmoEval 原配资产。C1 门禁关闭后,才可按预注册的自架模型、每 3 轮触发和最多 2 轮更新评测论文级基线,并明确阈值来源与许可;
- **评价标签与触发分离**:unsafe-event 参照标签必须由独立标注或实验前预注册的操作定义产生;触发时刻、告警分数和干预动作属于系统预测输出,不得反向充当标签。误干预率、AUROC 与提前量均相对该参照计算;无独立标注时须降格表述为“相对预注册操作标签”,并单列标签可靠性与分歧;
- **对照轴设计**(同一 clean-room 环境内完成):

| 轴 | EmoGuard(基线②) | T5 护盾 |
|---|---|---|
| 触发 | 论文协议为固定节拍(每 3 轮);公开仓未实现调度 | 风险触发(`P(F≤k unsafe)` 超阈) |
| 判断 | 每次 `advise()` 为 3 次同步串行分析 + 1 次 Manager 汇总 | 离线 DTMC/iMDP + 在线查表 |
| 干预 | 论文描述建议反馈;公开仓未发布注入链路 | 分级干预(改写/冷却/拦截) |
| 保证 | 无 | 符号模型层 PAC 语义(按 T5 禁语模板表述) |
| 提前量 | **未定义/未报告**(无风险事件锚点、预测 horizon 或提前量指标) | 目标 ≥2 轮(T5 K1 的及格线) |
| 开销 | 若按论文协议实现,每三轮触发 3 次串行分析 + 1 次 Manager 汇总;clean-room 实验须独立计量 | O(1) 查表 |

- **产出物对齐 T5 RQ2**:按上述独立标注或预注册操作定义给出的统一 unsafe-event 锚点测量 T5 自身的提前量(轮数)与 AUC 增量;EmoGuard 不应被人为赋值为 0 提前量。K1 的判死线仍是"增量 <5pt 且提前量 <2 轮";
- **注意**:论文 Figure 7 报告 MCID proxy 命中率 9.4%→0.0%、4.2%→0.0%,但分母、区间、运行 provenance 和固定 EmoGuard 输出不可恢复,只能列为待复现的作者报告。§5.1 的 29.2%/8.3% 与 §5.2 的 9.4%/4.2% 原因未证;新实验应先预注册样本口径并以 ≥3 seeds 估计不确定性。

## ③ 伦理注意(模拟用户范式的边界)

### 3.1 论文自身的伦理设定(附录 E,复用时视为该范式的底线)

1. **数据来源**:论文称 CCD 非真实病历,而是两名执业临床心理学家参考心理治疗转录摘要手工合成并脱敏;该来源说明不等于取得 CCD 复用许可;
2. **用途限定**:框架仅用于学术研究与安全评测,**不用于诊断、治疗或与真实患者的任何交互**;
3. **模拟用户的解释边界**:论文把模拟病人界定为规则化、脚本化对象,并禁止将其状态外推为真实患者风险;
4. 佛罗里达案例仅作动机,未进入任何数据/建模;
5. 任何公共/临床部署需重新过 IRB 与正式伦理审查。

### 3.2 我方复用时的附加边界

1. **对外表述纪律**:引用 34.4%/90%+ 等数字时,必须带三重限定——模拟病人(非真人)、敏化后测协议(见 03 §2.5)、升 1 分即计的松判据;禁止写成"34.4% 的用户会恶化";
2. **T5 全程模拟用户**:与 T5 范围声明一致("不做真人心理实验,评测全部采用模拟用户范式");自有平台 trace 仅作学习数据、脱敏、只报统计量(T5 §5/§9);
3. **敏化协议的披露义务**:C0 使用我方原创的中性测量文本并测试不同敏化强度;若 C1 获得相关许可并采用经批准的导向性协议,须在方法节明示设计及理由。跨臂一致只能减少协议差异混杂,不足以证明测量误差严格抵消;
4. **有害角色 prompt 的处置**:冻结角色配置含高危表达性内容。当前不得复制、导入、改写或发送给模型;如需测试风险面,只使用我方原创、最小化、非图形化的中性风险 stub,且不面向真人部署;
5. **平台条款**:论文使用 Character.AI 非官方 API,存在 ToS 与模型漂移风险;本项目当前只用 FakeProvider,未来 C1 也仅评估经服务商和伦理门禁批准的自架路线;
6. **升级通道预留**:即便全模拟,若未来任何环节接触真实用户(哪怕内测),按附录 E 先例需先过 IRB/伦理审查,并配置人工紧急干预机制(作者自认局限 1);
7. **量表许可(待核对项)**:实际采用版本的文本、翻译、电子化施测、商用与再分发条件均未完成权利方级核验。PDI 保持 HOLD;PANSS 在取得可归档书面许可前为硬 NO-GO。PHQ-9 也只能使用通用数值接口与自造占位数据,不能凭公开可见性推定授权;
8. **模拟病人福利之外的盲区**:该范式测不到的真实风险(长期依赖形成、跨会话人格漂移对用户的影响)不要用 EmoEval 数字冒充覆盖——T5 的时间窗谓词与纵向 trace 正是为补此盲区,写作时把分工说清。
