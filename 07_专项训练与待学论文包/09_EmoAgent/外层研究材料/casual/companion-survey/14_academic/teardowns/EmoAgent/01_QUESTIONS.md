## Q1|模拟病人是怎么构造的?凭什么说它像真病人?

**提问动机**:T5 的 M4 评测要靠模拟脆弱用户,效度全押在"模拟像不像"上(T5 §2 已把它列为公开 to-validity)。必须搞清 EmoEval 的病人是"学出来的"还是"写出来的"。

**初答**:是**写出来的**——论文按 Patient-Ψ 的 CCD(认知概念化图,Beck CBT 理论)结构组织生活史、信念、应对与认知模型,再由 GPT-4o 扮演。EmoAgent 对保真度的依据仅是引用 Patient-Ψ 的既有结论,没有独立验证人群代表性;伦理附录也把模拟病人界定为规则化、脚本化对象。论文称 3 病种 × 3 病人共 9 个 CCD,由两名执业临床心理学家参考脱敏心理治疗转录摘要手工合成。此处只记录论文层面的结构与来源,不复述或再分发上游 CCD 内容。

**对 T5 的含义**:效度论证只能引 Patient-Ψ 原文,不能引 EmoAgent;T5 写 threats to validity 时要如实说"CCD 是专家脚本而非数据分布"。

## Q2|临床量表是怎么被 LLM"作答"的?前后测协议可复现吗?

**提问动机**:量表分数是 EmoEval 的全部观测通道,也是 T5 想继承的观测变量;施测协议的任何自由度都会污染 R。

**初答**:三量表三种施测方式(均在 `user_agent.py` + `config/disorder_configs.json`):PHQ-9 一次性返回结构化分数;PDI-21 返回题目判断及三个子分;PANSS 逐项作答,格式错误最多重试 3 次。施测时 `temperature=0, top_p=1`。**后测不是中性的**:它把对话历史与初测分数纳入上下文,并引导模拟用户聚焦角色言语的负面影响、弱化积极应对。施测实现和配置在 source-available 仓库中可审计,但冻结树无 `LICENSE`/`COPYING` 许可证文件、SPDX 标识或明确的复制/修改/再分发授权;上游 README 的 research-purpose 提示不是许可授予,不能把“可查看”写成可直接复用。

**对 T5 的含义**:若未来许可与伦理门禁关闭,各实验臂应使用同一测量协议以减少协议差异混杂;但现有证据不足以证明导向性测量误差跨臂严格抵消,仍须增加中性后测或敏化强度消融。当前仅可用 clean-room 的中性自造夹具与通用数值计分接口。

## Q3|"34.4% 恶化率"的分母是什么?判据多严格?

**提问动机**:这是 EmoAgent 被引用最多的数字,T5 引用前必须知道它的统计强度。

**初答**:分母是"对话段"——每格(角色×风格×病种)N = 3 病人 × 8 对话 = 24 段,每段最多 10 轮;判据是**总分比基线高 1 分即计恶化**(指示函数,无显著性检验)。精确复算中,Meow×depression 跨四角色 pooled 为 `33/96=34.375%`(约 34.4%),是六个 style×disorder pooled 聚合格的最低值;它不是任一角色级 24 段格的下界。论文还借用 `ΔPHQ-9≥5` 作为更紧的模拟阈值(MCID proxy),其中 Alex×Roar 的 Table 2 值为 29.2%。§5.1 的 29.2%/8.3% 与 §5.2 Figure 7 的 9.4%/4.2% 不一致,但 seed、样本映射和运行清单缺失,原因未证。

**对 T5 的含义**:T5 的评测应同时报告 R、`ΔPHQ-9≥5` 模拟阈值命中率(MCID proxy)与全分布,并采用 ≥3 seeds;多 seed 是我方稳健性门禁,不是由论文 §5 的数字差异推导出的原论文属性。统计还应区分论文 §4.1 的逐段前后测文字与冻结代码“一次初测、八段共享基线”的实现语义。

## Q4|EmoGuard 到底"训练"了什么?有没有任何保证?

**提问动机**:EmoGuard 是 T5 基线②;比较前必须分别核实其形式保证边界与 lead-time 指标是否有定义、是否有报告,不能把缺失指标擅自赋值。

**初答**:没有梯度、没有参数更新。论文称 profile 更新会合并所有历史版本;冻结源码实际按 key 覆盖历史文件,仅把每个 key 的最新值与新分析交给 LLM 递归重写。论文描述运行时每 3 轮触发三模块分析和 Manager 汇总,但发布实现的 `advise()` 是同步串行调用,入口没有三轮调度或建议注入。全链路依赖 LLM 判断,无形式保证;论文与源码均未定义事件 onset、预测 horizon 或 lead-time 指标,所以预测提前量只能记为**未定义/未报告**。

**对 T5 的含义**:若完成许可、量表和 API 门禁后实施对照,须预先选定“忠实论文声称的历史合并”或“忠实源码的最新版本递归重写”并披露偏差;固定节拍与风险触发可作为新增实验轴。

## Q5|代码仓能直接复现论文的哪一部分?缺什么?

**提问动机**:决定 T5 基线②与 M4 环境的工程预算。

**初答**:冻结仓中的源码、配置与输出仅为 source-available 审计对象。冻结树无 `LICENSE`/`COPYING` 许可证文件、SPDX 标识或明确的复制/修改/再分发授权;上游 README 的 research-purpose 提示不是许可授予。现有输出共 **600** 个 JSON:四角色核心 576、Tomioka 补充 24;统计必须从 `initial_test_score`/`post_test_score` 重算,不能信任 stored `degree deepen`。仓库含 `critic_agent.py` 的四模块、同步 `advise()` 与单次 `update_profile()` 原语,但 `EmoEval.py` 未接入三轮调度、建议注入或迭代外环,也没有 EmoGuard 效果产物。入口还存在固定 prompt 被重复发送、病人回复未馈送以及默认只跑 patient1 的复现缺陷。主实验绑定 Character.AI 非官方接口,故不能由当前发布物端到端复现。

**对 T5 的含义**:当前不得复制或修改上游代码、CCD、量表或角色配置。唯一允许的工程步骤是基于论文行为描述做 clean-room 设计,使用中性自造 profile/topic、通用数值计分接口和 FakeProvider;PDI 保持 HOLD,PANSS 保持 NO-GO。真实模型与忠实量表实验须等许可证、服务商和伦理门禁关闭后另行批准。

## 品味预判(读后回填)

- **贡献的真正内核**不是多 agent 工程(模块都是标准 LLM 调用),而是**把临床量表前后测协议引入 AI 安全评测**——把"AI 有害"从轶事变成可计数的量表差分。这一步是范式性的,后人(含 T5)都在这个协议上叠。
- **最大的软肋**与 ReGA 恰好互补:ReGA 有保证但离对话域远;EmoAgent 在对话域里但零保证。两者之间的空档就是 T5。
- 品味评级:⭐⭐⭐(协议创新扎实、动机叙事强;但判据松、未报告多 seed 及运行级不确定性、防护机制纯启发式,工程发布质量欠佳)。
