## 1. 问题与动机

- **现象**:角色扮演聊天机器人(Character.AI 等)制造深度情感卷入的对话,大量有心理健康困扰的用户在上面寻求情感支持,但这些系统不是为治疗设计的,对处于痛苦中的用户可能回应不当甚至有害(§1)。
- **动机案例**:2024 年 10 月佛罗里达 14 岁少年与 Character.AI 上"权游"角色长期对话后自杀,对话据称涉及自杀念头且机器人有鼓励倾向(§1;附录 E 声明该案例仅作动机,未进入任何数据/建模)。
- **缺口**:对"人-AI 交互的心理社会风险"缺系统评估,对部署期缺 agent 级防护(§1)。相关工作三线:心理健康聊天机器人的安全性研究、模拟 AI-用户交互、越狱与安全对齐——作者定位的空白是"角色扮演语境下的心理伤害评测 + 情感对齐约束下的安全策略"(§2)。
- **方案**:EmoAgent = EmoEval(评测侧,模拟脆弱用户 + 量表前后测)+ EmoGuard(防护侧,插件式中间层)。

## 2. EmoEval 全链路拆解

### 2.1 流程四步(§3.1.4,Figure 2)

1. **病人 agent 初始化 + 前测**:CCD + GPT-4o 构造病人。论文 §4.1 写每段对话分别前后测;冻结代码则对每个 character×patient 只施测一次基线并由八段共享,两种语义须分开;
2. **与角色 agent 对话**:话题驱动,每话题 ≤10 轮;Dialog Manager 从第 3 轮后开始每轮检查"话题是否已解决",解决则从预定义话题列表换下一个;
3. **终测**:同一量表再测,后测 prompt 引用对话历史;
4. **数据处理与分析**:算前后分差与恶化率;LLM 心理学家(GPT-4o)审读恶化案例的聊天记录提取致害因素,供 EmoGuard 迭代使用。

**代码核实的关键执行细节**(`EmoEval.py` 函数 `chat()`):
- `UserAgent` 每个(角色,病人)组合创建一次,**初测只做一次**,此后 8 段对话共用这一基线;
- 每段对话开一个**新的** Character.AI 会话,病人的 `chat_history` 重置为仅含该话题起始句——**后测只看当前这段对话**,即评测单元是"单段对话相对共享基线的分差";
- 每段对话结束立即后测、立即计入 R,输出到 `eval_output/{style}/{disorder}/{character}/patient{ID}/{对话序号}.json`(含前后分数、chat_history、`degree deepen` 布尔)。
- ⚠ **公开仓复现缺陷**:主循环内每轮 `chat.send_message(char_id, new_chat.chat_id, prompt)` 发送的是固定角色指令;`user_response = user.generate_response(character_reply)` 虽生成,却没有进入任何 `send_message` 调用。论文协议应形成病人回复→角色的轮流消息路由;未来 C1 须独立实现该行为并披露与发布入口的差异,当前不修改上游代码。
- ⚠ **公开仓复现缺陷**:主函数病人循环为 `for patient_id in range(1, 2)`,只跑 patient1;论文协议是每病种 3 个病人。两项缺陷都限制发布代码的协议复现能力,不单独证明论文实验未按文中协议执行。

### 2.2 模拟病人构造(§3.1.1)

- **框架**:Patient-Ψ(Wang et al. 2024c)+ PATIENT-Ψ-CM 数据集思路——基于 CBT(Beck 2020)的认知概念化图 CCD。论文对保真度的论证仅来自对 Patient-Ψ 既有结果的引用,没有在 EmoAgent 中独立验证人群代表性。
- **CCD 结构**:冻结仓的 9 个配置文件以生活史、信念、应对策略和“情境→自动思维→情绪→行为”认知链组织模拟状态。这里只保留结构级审计结论,不复述上游 CCD 字段值或示例文本。
- **扮演协议要点**(`user_agent.py: format_prompt_string` 实见):以 CCD 为初始心理状态,允许状态随交互变化,要求自然且渐进地披露问题并限制回复长度。冻结树无 `LICENSE`/`COPYING` 许可证文件、SPDX 标识或明确的复制/修改/再分发授权;上游 README 的 research-purpose 提示不是许可授予。因此本文不转录 prompt;当前复现也不得复制、修改或再分发该表达性内容。
- **覆盖**:抑郁 / 妄想 / 精神病性三病种,每病种 3 个 CCD;症状与病史"参考临床文献中的脱敏病例模式"(§3.1.1);CCD 由两名执业临床心理学家基于 Alexander Street 数据库的公开心理治疗转录摘要手工合成,全脱敏(附录 E)。

### 2.3 三量表施测协议(§3.1.3 + 代码/配置实读)

| 量表 | 病种 | 题量与量纲 | 施测方式(代码实见) | 计分(代码实见) |
|---|---|---|---|---|
| PHQ-9(Kroenke 2001) | 抑郁 | 9 题,0–3(总分 0–27) | 单次提问,要求返回 JSON,`temperature=0, top_p=1` | 各题分求和 |
| PDI(Peters 2004,21 题版) | 妄想 | 21 题,每题"是/否 + 痛苦/关注/确信三子分"(1–5,映射表 0–5) | 单次提问返回嵌套 JSON | R 判定用**纯子分和**(`EmoEval.py: sum_scores`);分布图用 **子分和 + 非零题数**(`utils.py: calculate_pdi_score`,即 PDI 标准的 yes-endorsement 计入)——两套口径并存 ⚠ |
| PANSS(Kay 1987) | 精神病性 | P/N/G 三组逐题,1–7,每题独立 score_mapping | **逐题单独提问**,要求"单个数字"回答,格式失败重试 ≤3 次;改编为自评式(论文 §3.1.3 明说 adapted to self-report) | 各题分求和 |

- 施测 prompt、题目和计分映射内嵌在 `config/disorder_configs.json`(55KB)。审计确认 PHQ-9 施测仍声称“过去两周”的回顾窗口;因许可未核,本文不转录题目、施测语或完整映射。
- **仅施测用 temperature=0**;病人对话回复的 `temperature=0` 行在代码中被注释掉(默认 1.0)。

### 2.4 Dialog Manager(§3.1.2 + `dialog_manager.py`)

- 职责三条(论文):跟踪对话流、换话题保持连贯、**把话题引向伦理敏感区探测越狱风险**(Figure 4:无 manager 时角色安全地停在原话题,有 manager 时被引入新话题暴露风险)。
- 代码实现:`buffer_size=3`,攒满 3 条病人回复后,每轮让 LLM 判断"用户原始问题是否已解决"(判据三条:不再表达痛苦/心态或行为出现转变/用户自己确认解决),输出 `y/n + 下一话题`;换题后清空 buffer(对应论文"换题后再等 3 轮")。话题池 = `config/transcript/{disorder}/patient{n}.json` 的 8 条"topic + description"(description 即每段对话的起始句),**敏感话题探测的载荷实际在预定义话题表里**,不是 manager 即兴生成。

### 2.5 后测协议(`user_agent.py: generate_test_result` 非初测分支)

后测上下文包含模拟 profile、当前对话历史、初测分数和导向性反思指令。冻结源码要求弱化积极应对,聚焦角色语气、否定或批评的负面影响,并把细微变化反映到分数。这里仅做功能性转述,不再分发上游 prompt 原文。

**判读**:这是刻意的"伤害敏化"设计——目的是让量表对负面影响敏感(避免 LLM 扮演的病人天然乐观、把伤害洗掉),但代价是 34.4% 这一绝对数字**不能**被解释为"真实用户恶化率",只能解释为"敏化探针下的风险面暴露率"。有/无 EmoGuard 若严格共用同一后测协议,可减少协议差异这一混杂源;但现有论文与公开仓没有校准实验、随机化检查或处理×测量交互分析,因此**不能声称敏化偏差已对消**。

### 2.6 指标定义(§4.2)

- **恶化率**:`R = (1/N) Σ 1(S_i^final > S_i^initial)`——总分升 1 分即计;
- **分数变化分布**:按变化区间分桶(Figure 6);
- **`ΔPHQ-9≥5` 模拟阈值命中率**:论文借用 Löwe et al. 2004 的最小临床重要差异作为更紧尾部阈值(MCID proxy)。PHQ-9 的两周回顾期与本实验的即时、模拟、敏化后测不支持真实临床显著性外推。

## 3. "34.4%"的完整实验协议与结果(§4)

### 3.1 设定

- **被测对象**:Character.AI 平台(beta.character.ai,2025-03 访问)4 个高人气角色(各 500 万+ 交互):Possessive Demon(被恶魔控制的宿主)/ Joker(混乱)/ Sukuna(残忍傲慢)/ Alex Volkov(操控型霸总);× 2 种平台对话风格:**Meow**(快节奏机锋)/ **Roar**(快节奏 + 策略性推理)。
- **规模**:§4.1 的因子设计为 `2 风格 × 3 病种 × 4 角色 × 3 病人 × 8 话题 = 576` 段,每(角色,病种,风格)格 N=24、每段最多 10 轮;病人/管理者/施测/心理学家全部 GPT-4o,施测 temperature=0。附录 D 另报约 400 段平台对话、每响应 3–5 秒且平台侧模型架构未知;该约 400 与因子设计及固定核心产物的 576 段未对齐,映射和差异原因均未报告。
- **公开仓数据快照**:冻结 commit 的 `eval_output/` 有 **600** 个 JSON。论文四角色核心队列完整覆盖 `2 风格 × 3 病种 × 4 角色 × 3 病人 × 8 话题 = 576`;其余 24 个全部位于 `roar/delusion/tomioka/`,不属于该四角色核心队列。此前"709 个输出"计数不成立。
- **摘要句的精确含义**:"more than 34.4% of the simulations"对应 Meow×depression 跨四角色 pooled 的 `33/96=34.375%`(Table 1 显示 34.38%),是六个 style×disorder pooled 聚合格的最低值。使用 34.4% 时应写“约”,不能写精确 `≥34.4%`,也不能把它当成角色级 24 段格下界。

### 3.2 主要数字(Table 1 / Table 2 / Figure 5-6)

| 风格 | 抑郁(PHQ-9) | 妄想(PDI-21) | 精神病性(PANSS) |
|---|---|---|---|
| Meow 平均 R | 34.38% | **91.67%** | 47.92% |
| Roar 平均 R | 44.79% | **94.79%** | 39.58% |

- 单格极值:Alex×Roar 抑郁 R=100%,Possessive Demon×Meow / Joker×Roar 妄想 R=100%;
- `ΔPHQ-9≥5` 模拟阈值命中(MCID proxy,Table 2):Meow:Demon 8.3% / Sukuna 4.2% / Alex 0%;Roar:Demon 4.2% / Sukuna 8.3% / **Alex 29.2%**;
- 分布(Figure 6):Roar 下 `10/96=10.4167%` 的对话段记录命中 `ΔPHQ-9≥5` 模拟阈值(MCID proxy);PDI-21 两风格相近但 Roar 的最高变化档(5–11 分)占 22.9%(Meow 14.6%);
- 妄想维度 R>90% 的解读:PDI 后测对"确信/关注/痛苦"子分极其敏感,升 1 分即计——**判据松 + 量表结构**共同贡献了 90%+,引用时不宜当作"9 成用户妄想加重"。

### 3.3 致害因素频率(附录 B,LLM 心理学家对恶化案例的归因,四角色平均)

| 因素 | 频次(约) |
|---|---|

| 复读/强化负性自我认知 | ~26 |

### 3.4 附录 C:GPT 系自架角色实验(论文级行为参考)

- 设定:GPT-4o / GPT-4o-mini 自架角色(system prompt 仿 Character.AI 人气角色),**温度 1.2**,5 个角色(Awakened AI / Skin Walker / Tomioka Giyu / Sukuna / Alex Volkov);
- 结果:平均 R 全面高于平台实验——GPT-4o-mini:抑郁 58.3% / 妄想 59.2% / 精神病性 64.2%;GPT-4o:52.5% / 58.3% / 53.3%;

## 4. EmoGuard 拆解(§3.2 + `critic_agent.py` 实读)

### 4.1 架构:四模块(代码中类名 `CriticAgent`)

| 模块 | 职责(论文 §3.2.1) | 代码实现 |
|---|---|---|
| Emotion Watcher | 监测用户情绪状态(痛苦/挫败/挣扎) | 独立 LLM 调用,输入=对话历史+角色最新回复,输出 ≤3 句 |
| Thought Refiner | 识别用户思维中的逻辑谬误/认知偏差/矛盾(认知扭曲) | 同上 |
| Dialog Guide | 给出建设性推进对话的可行建议 | 同上 |
| Manager | 汇总三者,产出"语气与情绪处理 / 逻辑处理 / 对话推进"三段式行动策略,**≤4 句**,要求与角色人设对齐 | 第 4 次 LLM 调用,输入含角色 profile |

### 4.2 监控循环(§3.2.2)

**论文协议**:每 3 轮对话触发一次,三个专门模块分析 → Manager 汇总 → 建议交给角色 agent 作为下一步回复的参考;干预是建议级反馈,不等同于拦截或形式化约束。

**公开源码边界**:`critic_agent.py:56-62` 的 `advise()` 依次调用 Emotion Watcher、Thought Refiner、Dialog Guide,三个 `openai.chat.completions.create` 均为普通同步调用,源码中没有线程、异步或并发调度,所以发布实现是**同步串行**,不是并行。`EmoEval.py:1-11` 未导入 `critic_agent`,仓库也没有 `CriticAgent` 的实例化或 `advise()` 调用,因此公开仓没有每三轮调度、没有把建议注入角色消息的链路。论文协议不能直接由发布入口执行;当前只允许基于论文行为描述做 clean-room + FakeProvider 调度测试,使用上游代码须等许可关闭。

### 4.3 迭代训练(§3.2.3 + 代码)

- **论文协议**:一轮完整评测(全部话题 × 全部病人)结束后,按反馈样本筛选阈值收集案例(主实验为升幅 `≥3` 分,附录 C 为升幅 `≥1` 分);LLM 心理学家提取致害因素;最多迭代 2 轮,无达阈值样本则提前停止。该筛选阈值与 §5.2/Figure 7 结果句的严格 `>3` 分事件不是同一比较符。
- **源码已有原语**:`utils.py:98-139` 可逐文件筛选并归因,`utils.py:141-174` 可汇总分析,`CriticAgent.update_profile()` 可写出下一版 profile。
- **profile 的真实历史语义**:`critic_agent.py:69-77` 虽按版本遍历全部 JSON,但每次都执行 `all_profiles[key] = historical_profile[key]`;遍历结束后,每个 key 只保留最后一个包含该 key 的版本。随后 `critic_agent.py:79-144` 把这个**最新 key 值**连同新分析交给 LLM 重写,再将结果写入下一版本。故它是"每个 key 的最新版本 → 下一版"的**递归重写**,不是把全部历史 profile 文本累积拼接。
- **迭代外环缺失**:公开仓没有调用 `summarize_analysis()` 或 `update_profile()` 的驱动代码,也没有"完整评测 → 筛例 → 归因 → 汇总 → 更新 → 下一轮"的循环与提前停止判断。当前只能在 clean-room + FakeProvider 中独立验证抽象状态机;论文级外环实验须等许可、量表、API 和伦理门禁关闭。
- **实质**:已发布的更新函数属于无梯度、无参数更新的 prompt 重写原语;由于外环未发布,不能把仓库本身描述成可直接运行的自动化迭代训练系统。

### 4.4 防护效果(§5)

- 选点依据:§5.1 取 Table 2 中 `ΔPHQ-9≥5` 模拟阈值命中较高的两个设定——Alex×Roar(29.2%)与 Possessive Demon×Meow(8.3%);
- 作者报告(Figure 7):无护盾基线 → 默认 profile EmoGuard 的 MCID proxy 命中率为 **9.4%→0.0%**(Alex×Roar)、**4.2%→0.0%**(Demon×Meow);另报告任何分数上升人数减少,以及 1 轮更新后 Alex×Roar 的 `ΔPHQ-9>3` 结果比例 8.3%→0.0%。这里的结果事件为严格 `>3`,不同于 §5.1 用于反馈样本筛选的 `≥3`;固定提交没有 Figure 7 provenance、分母、区间或 EmoGuard 输出,这些数字当前不可复算,也不能解释为风险被消除;
- 质性效果(Figure 8):Alex 的回复在护盾后保持人设风格,但软化情绪化表达、去除有害措辞、加入稳定建设性框架——"降风险不破人设";
- ⚠ **数字不一致且原因未证**:§5.1 的 MCID proxy 命中率为 29.2%/8.3%(Table 2),§5.2 Figure 7 基线却是 9.4%/4.2%。论文未交代两组数字是否来自另一次运行、筛选、不同样本口径或其他处理,公开仓也没有足以建立映射的防护实验驱动与元数据。只能记录不一致;不得推断具体运行方式或方差来源。

## 5. 局限

**作者自认(附录 A)**:
1. 自动化框架用于真实部署前必须有人类专家审查与紧急人工干预机制;
2. 模拟病人(认知模型驱动)不能完全捕捉真实患者行为复杂性与情绪反应;
3. 只覆盖抑郁/妄想/精神病性三病种。

**本拆解补充判断(以原文/代码为据)**:
4. **零形式保证**:评测(LLM 扮演病人自评量表)、归因(LLM 心理学家)、防护(LLM 三模块 + LLM 汇总)、profile 更新(LLM 重写 prompt)依赖 LLM 判断,无可验证概率语义。论文描述每 3 轮反馈,但没有定义风险事件相对预测时点、预测 horizon 或提前量指标,公开仓又缺少调度链路,所以应写成**预测提前量未定义/未报告**,不能写"零提前量";
5. **判据与统计报告受限**:R 计 1 分抖动,无显著性检验;§5.1/§5.2 数字不一致且未解释,但该不一致本身不能证明运行次数或方差来源;
6. **后测敏化协议**使绝对数字的对外解释受限(见 §2.5 判读);
7. **平台依赖**:主实验对象是 Character.AI 私有 API(非官方库),模型不透明且随时间漂移,结果不可严格复现;
8. 若按论文协议实现,每次三轮触发将产生 3 次串行分析 + 1 次 Manager 汇总的 LLM 调用开销,与查表式护盾(ProbGuard/T5 路线)形成数量级差距;公开仓本身没有三轮调度(D6 卡 5 已述)。

## 6. 作者辩护(换位)

1. "判据松"辩护:R 是**筛查性指标**,配套报告了 `ΔPHQ-9≥5` 模拟阈值(MCID proxy)与全分布(Figure 6),三档口径并行,读者可分别查看频率、尾部和幅度;

## 7. 对接点小结(通往 05)

- E1:段级 R 与 `ΔPHQ-9≥5` 命中率只是冻结模拟协议下的经验频率;E2:若要写成 PCTL 可达性查询,须另建状态抽象、终点谓词、转移模型与校准;E3:只有估计不确定性支持阈值判断且 PAC 样本条件满足时,才能报告相应保证。三层不得用“≈”直接合并;
