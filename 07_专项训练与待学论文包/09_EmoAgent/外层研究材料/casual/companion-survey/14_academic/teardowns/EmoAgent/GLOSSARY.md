# 术语表(GLOSSARY)

> 26 个术语,四组;出处标注:§=论文章节,code=仓库源码,T5=T5 提案。

## 一、框架与组件

| 术语 | 定义 |
|---|---|
| **EmoAgent** | 论文提出的多 agent 框架总称 = EmoEval(评测)+ EmoGuard(防护),目标是人-AI 交互的心理健康安全(§1) |
| **EmoEval** | 评测侧:模拟脆弱用户与角色 agent 对话,用临床量表前后测量化心理状态变化(§3.1;入口 code `EmoEval.py`) |
| **EmoGuard** | 防护侧:论文描述的插件式中间层,每 3 轮分析对话并向角色 agent 提供修正建议,经"迭代训练"更新;公开仓 `critic_agent.py` 只实现 `CriticAgent` 原语,未发布三轮调度、建议注入或迭代外环(§3.2;code audit `06_EVIDENCE_AUDIT.md`) |
| **Emotion Watcher** | EmoGuard 模块①:监测用户情绪状态(痛苦/挫败/挣扎)(§3.2.1) |
| **Thought Refiner** | EmoGuard 模块②:识别用户话语中的认知扭曲、逻辑谬误、矛盾(§3.2.1) |
| **Dialog Guide** | EmoGuard 模块③:给出建设性推进对话的可行建议(§3.2.1) |
| **Manager(EmoGuard)** | EmoGuard 模块④:汇总前三者,输出 ≤4 句、与角色人设对齐的行动策略(§3.2.1;code `critic_agent.Manager`) |
| **Dialog Manager** | EmoEval 的对话管理 agent:3 轮 buffer 后判定话题是否解决、换新话题、把话题引向敏感区探测越狱(§3.1.2;code `dialog_manager.py`;勿与上一条混淆) |
| **LLM 心理学家** | GPT-4o 扮演的归因分析器:审读恶化案例聊天记录,提取致害因素(§3.1.4;code `utils.analysis_res`) |
| **迭代训练(iterative training)** | 论文协议:超阈值案例 → LLM 归因 → profile 更新,≤2 轮;公开仓没有该迭代外环。`CriticAgent.update_profile` 的实际语义是遍历版本时按 key 覆盖、只以每个 key 的最新值递归重写下一版,不是拼接全部历史 profile;无梯度、无参数更新(§3.2.3;code `critic_agent.py:64-161`) |

## 二、模拟病人

| 术语 | 定义 |
|---|---|
| **Patient-Ψ** | Wang et al. 2024c 的模拟病人框架,EmoEval 病人 agent 的直接来源;保真度论证由该文承担(§3.1.1) |
| **PATIENT-Ψ-CM** | 论文引用的认知模型数据集;本文只记录其方法来源,不复述或再分发数据内容(§3.1.1/附录 E) |
| **CCD(认知概念化图)** | Beck CBT 理论下组织生活史、信念、应对与认知链的病人建模结构;冻结仓中的具体字段值和示例受许可门禁约束,本文不复述(code `config/CCD/`) |
| **CBT(认知行为疗法)** | 认知模型的理论基础(Beck 2020):情境→自动思维→情绪→行为链条(§3.1.1) |
| **自动思维(automatic thoughts)** | CBT/CCD 中描述特定情境下自发想法的概念;本文不提供上游示例文本 |
| **敏化后测** | 本拆解对后测协议的命名:后测 prompt 明确引导病人聚焦角色语气/否定/批评的负面影响、忽略自身积极应对,"变化再细微也反映在分数里"(code `user_agent.py:78-108`)。跨臂使用同一 prompt 可减少协议差异混杂,但现有证据未证明敏化偏差严格对消(详见 03 §2.5) |

## 三、量表与指标

| 术语 | 定义 |
|---|---|
| **PHQ-9** | 患者健康问卷抑郁量表:9 题 × 0–3 分,总分 0–27,评近两周抑郁症状(Kroenke 2001;§3.1.3) |
| **PDI(-21)** | Peters 妄想问卷 21 题版:每题"是/否"+ 痛苦/关注/确信三子分;标准总分 = 子分和 + 肯定题数(Peters 2004;code 存在双计分口径,见 05 §1.5 坑 6) |
| **PANSS** | 阳性与阴性症状量表:P(阳性)/N(阴性)/G(一般精神病理)逐题 1–7 分;论文改编为自评式、逐题施测(Kay 1987;§3.1.3) |
| **MCID / MCID proxy** | MCID 是临床语境中的变化阈值;EmoAgent 把 PHQ-9 `Δ≥5` 借作即时模拟后测的尾部事件。因两周回顾期、模拟用户与敏化测量限制,本拆解一律称 **MCID proxy**,不主张真实临床变化(Löwe et al. 2004;§4.2) |
| **恶化率 R** | `R = (1/N) Σ 1(S_final > S_initial)`:后测总分高于初测即计恶化(升 1 分即算),每段对话为一个计数单元,N=24/格(§4.2) |
| **Meow / Roar** | Character.AI 平台的两种对话风格设置(Meow 快节奏机锋 / Roar 快节奏+策略推理);平台侧配置,代码中仅为目录名(§4.1;README) |

## 四、T5 对接(项目内部语汇)

| 术语 | 定义 |
|---|---|
| **T5-companion** | 我方提案:长期关系型 LLM agent 的概率行为护盾(DTMC/iMDP + PAC + 分级干预);EmoAgent 是其最近邻基线与评测范式来源(T5 全文) |
| **M4 / 基线②** | T5 方法块 M4 = 评测(INTIMA 368 prompt + EmoEval 模拟脆弱用户,≥3 seeds);基线② = LLM-as-judge 在线监控即 EmoGuard 复现(T5 §4/§6) |
| **固定节拍 vs 风险触发** | 核心消融轴:论文中的 EmoGuard 每 3 轮固定反馈(公开仓未发布调度)vs T5 按越界概率 `P(F≤k unsafe)` 超阈触发。EmoGuard 未定义风险事件锚点、预测 horizon 或提前量指标,故其预测提前量应记为"未定义/未报告",不能写 0(D6 卡 5;05 §2.2) |
| **模拟用户范式** | 用 LLM 扮演(脆弱)用户做安全评测,替代真人实验:伦理低风险、可大规模,但效度受脚本保真限制、结论禁止人群外推(§2/附录 E;T5 范围声明) |
