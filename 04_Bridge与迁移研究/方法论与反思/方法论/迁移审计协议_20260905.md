# 迁移审计协议：从跨域联想到可证伪研究候选

**版本**：v0.1
**日期**：2026-09-05
**状态**：`ADAPTER-PROTOCOL`
**角色**：扩展现有 `PROBLEM_SOLVING` 的跨域迁移步骤；不替代冻结的 Learning-Research OS，不自动批准方向、实验或能力结论

## 1. 目的

本协议训练和约束 `Transfer Judgment`：把“两个东西好像很像”的 sense，筛成有机制证据、可观察、可干预、可证伪且成本可控的研究候选。

协议处理的不是“联想是否漂亮”，而是：

1. 源方法为什么有效；
2. 该机制是否存在于目标域；
3. 哪种 representation 能识别并保留下游决策需要的信息；
4. 显式结构相对未知结构改变了什么决策；
5. 哪个低成本实验能区分迁移机制与竞争解释。

## 2. 核心区分

### 2.1 方法与 operator

- **方法迁移**：搬运具体算法、模型或实现。
- **operator 迁移**：保留研究动作，但在目标域重新选择对象、关系、representation、验证和干预。

具体方法不能搬，不代表 operator 不能迁；operator 能迁，也不代表具体方法有效。

### 2.2 四种“像”

- **词像**：共享术语。
- **形状像**：流程图或现象相似。
- **机制像**：源方法成立的必要条件在目标域也成立。
- **决策像**：识别机制后，可以用相似干预改变目标系统。

前两者只能生成候选，不能支持迁移主张。

### 2.3 三层 representation 审计

- **Existence**：目标结构是否客观存在且具有足够稳定性？
- **Identifiability**：给定现有观测，能否把它与竞争结构区分开？
- **Sufficiency**：该表示是否保留目标预测、验证或干预所需的信息？

`存在 != 可识别 != 对下游充分`。

## 3. 分级

| 等级 | 最低证据 | 默认动作 |
|---|---|---|
| L0 词汇相似 | 共享关键词 | DROP 或仅记灵感 |
| L1 现象相似 | 共享重复、瓶颈、并发等现象 | PARK |
| L2 结构相似 | 对象、关系、约束有明确映射 | 进入机制剥皮 |
| L3 机制相似 | 有源证据，且目标域满足关键前提 | 进入 representation 审计 |
| L4 干预相似 | 显式结构改变一个具体决策 | 设计预测和反例 |
| L5 可验证迁移 | 有低成本 discriminating test | 可进入研究队列 |

等级是证据状态，不是 idea 质量的主观评分。

## 4. 九道审计门

### G0｜Sense 定界

写清：

- source domain / method；
- target domain / object；
- 第一眼相似之处；
- 目前最多只能说什么；
- 类比明显不能延伸到哪里。

**失败条件**：只能给出共享术语，无法给出对象和关系映射。
**动作**：`DROP` 或保留为未审计灵感。

### G1｜Source Evidence：源机制证据

先证明源方法确实依赖所声称的机制：

- 源方法的输入、输出、目标和约束是什么？
- 论文原文、消融、定理、失败案例或实现行为提供了什么证据？
- 所谓机制是作者结论、我们的解释，还是仅凭叙事反推？
- 若移除该机制，源方法应出现什么变化？是否有证据？

**失败条件**：把方法组件名称当作有效机制，或把本地 surrogate 当成论文算法。
**动作**：`PARK-SOURCE-UNVERIFIED`。

### G2｜Mechanism Peeling：机制剥皮

填写：

\[
\text{source phenomenon}
\rightarrow
\text{why it works}
\rightarrow
\text{necessary/sufficient conditions}
\rightarrow
\text{abstract mechanism}
\]

同时列出：

- 机制的必要条件；
- 可能只是伴随现象的部分；
- 最容易混淆的竞争解释；
- `analogy stops here`。

**失败条件**：抽象后只剩“feedback”“graph”“compression”等普适词。
**动作**：退回 G1 或 `DROP-TOO-GENERIC`。

### G3｜Target Preconditions：目标域验尸

检查：

1. 目标域是否存在对应对象？
2. 对应关系和约束是否真实存在？
3. 机制所需稳定性、重复性、干预接口是否存在？
4. 哪些目标域特性会破坏源机制？

**失败条件**：只能建立比喻，不能建立对象-关系-约束映射。
**动作**：`DROP-MECHANISM-MISMATCH`。

### G4｜Representation：存在性、可识别性与充分性

填写：

- latent structure 候选；
- 所需 observables；
- observation schema；
- representation 候选；
- 哪些不同真实结构会产生相同观测；
- representation 丢失了什么；
- downstream task 需要保留哪个 invariant。

必须至少构造一对：

- 表面 adjacency 相同但真实 dependency 不同；或
- 顺序不同但真实 dependency 相同。

**失败条件**：结构虽可能存在，但日志无法区分；或 representation 对目标决策不充分。
**动作**：`PARK-UNIDENTIFIABLE` 或重新设计 instrumentation。

### G5｜Decision Delta：显式结构改变什么决策

禁止只写“有助于理解”。必须填写：

```text
Without recovered structure: 决策 D0
With recovered structure:    决策 D1
Decision delta:               D1 - D0
Measured consequence:         指标 M
```

决策候选包括：monitor、verify、compile、repair、schedule、allocate、diagnose、control。

**失败条件**：无法指出结构使哪个动作发生变化，或只能生成 visualization。
**动作**：`PARK-NO-INTERVENTION`。

### G6｜Discriminating Prediction：新预测与竞争解释

至少写：

- `H_transfer`：若迁移机制成立，应观察到什么；
- `H_alt`：若只是 adjacency、频率、规模、logging artifact 或其他混杂，应观察到什么；
- 区分两者的 intervention；
- 成功、失败和不确定结果各意味着什么。

一个合格预测应具有以下形式：

> 在条件 C 下，改变 X 后，representation 或系统结果 Y 应按方向 Z 改变；竞争解释则预测不同结果。

**失败条件**：无论出现什么结果都能事后解释为“支持”。
**动作**：`DROP-UNFALSIFIABLE`。

### G7｜Cheap Falsification：最便宜证伪

先找能杀死 idea 的最小实验，而不是先建平台。

优先顺序：

1. 手工构造反例；
2. 两个 toy workflows；
3. 复用现有 trace 和最小脚本；
4. 小规模 controlled run；
5. 最后才考虑新 logging、benchmark、formal semantics 或 runtime。

实验记录必须包含输入、版本、prediction、单一变化因素、结果、失败案例、替代解释和 claim ceiling。

**失败条件**：在形成可证伪预测前，需要先造大规模 infrastructure。
**动作**：`PARK-COST`，不得用工程投入替代机制证据。

### G8｜Semantic Prior Art：按机制检索

搜索式按以下三元组生成：

```text
研究动作 + 作用对象 + downstream result
```

至少覆盖：

- 本领域标签；
- 不同领域中的同机制工作；
- 不同术语下的相同 representation；
- 同一 intervention 的替代机制；
- 直接否定本 idea 必要性的工作。

每篇候选记录：身份、原文证据、共享机制、关键差异、是否使 novelty 降级。

**失败条件**：只按领域名或自造术语搜索。
**动作**：检索不完整，不得作 novelty claim。

## 5. 状态机

### DROP

满足任一条件即可：

- 只有 L0/L1 相似；
- 源机制证据不成立；
- 目标域不存在必要条件；
- 无法产生可证伪预测；
- 已有工作完全覆盖研究问题且没有新的 representation、prediction 或 intervention。

DROP 不等于联想愚蠢；它表示当前证据不值得继续投入。

### PARK

用于 idea 可能成立，但缺少可获得信息：

- 源论文/实现待核验；
- observables 不足；
- translation cost 暂时过高；
- decision delta 尚不清楚；
- prior art 尚未完成。

PARK 必须记录明确 recovery condition，不能只写“以后再看”。

### PROMOTE

最低要求：

- 达到 L5；
- G1-G8 均有可审计内容；
- 至少产生新的 representation、prediction、intervention 三项中的一项；
- 有最便宜证伪方案和停止条件；
- novelty 仍只保持为“待检索/待验证”或更低的真实证据状态。

满足两项新产出，优先安排 toy experiment；三项俱全，才进入系统 prior-art、feasibility 和项目规划。

## 6. 成本不是分数，而是队列约束

启发式上可以考虑：

\[
\frac{
\text{mechanism overlap}
\times
\text{observability}
\times
\text{actionability}
\times
\text{testability}
}{\text{translation cost}}
\]

但正式决策遵循两条规则：

1. `observability`、`decision delta`、`falsifiability` 任一缺失都不能被其他高项补偿；
2. translation cost 用于安排队列和停止条件，不用于把低机制证据包装成“高风险高收益”。

## 7. 最小验收证据

一次完整迁移审计至少产出：

- 一张填写完成的 Transfer Card；
- 一条带来源的 source mechanism；
- 一张 source-target 对象/关系/约束映射；
- 一份 observables 与 representation 缺失表；
- 一个明确的 decision delta；
- `H_transfer` 与至少一个 `H_alt`；
- 一个可以失败的最小实验；
- 一个 `DROP/PARK/PROMOTE` verdict 及理由；
- 一行 claim ceiling；
- 用户在无答案条件下解释机制、反例和停止条件的记录。

只有 AI 写好文件、图画得漂亮或搜索到相似论文，不算迁移能力通过。
