## §2 训练闭环（每个练习的标准结构）

```
题面（BRIEF 内）→ 你先做（90 分钟时间盒）→ 卡死才解锁 hint（三级）
→ 提交交付物 → AI 按 rubric 批改 → 复盘一页 → LEDGER 记一行 → （如触发）铸方法论卡
```

- **时间盒**：单个 EX ≤ 90 分钟。到点未完成也提交，"没做完"本身是复盘素材（估时能力也是能力）。
- **hint 三级**：H1 方向提示（"往并发交错想"）→ H2 定位提示（"看第 X 个函数的锁范围"）→ H3 半答案（"问题是 A，你来说为什么和怎么修"）。解锁记录进 LEDGER（用了几级 hint 是自评的一部分，不是耻辱柱）。
- **批改 rubric**：每个 EX 的 BRIEF 自带（抓到/漏掉/误报三栏 + 过程分：方法是否系统化、证据是否分层）。
- **证据标签**（沿 EA-6L）：你的每条判断标 `DOC-CLAIM / STATIC-CONFIRMED / TEST-CONFIRMED / RUNTIME-CONFIRMED / UNVERIFIED`——**判断不越证据层**是所有 rubric 的公共扣分项。

## §3 答案隔离（硬规则）

1. 每个 EX 的参考答案/已知问题清单/埋雷说明，由 **Setter Agent 在你做题前的独立窗口**生成，写入训练包 `_sealed/EX-NN_answer.md`。文件名不剧透内容。
2. **你做题前禁读**：`_sealed/`、各 BRIEF 标注的"禁读清单"（通常含账本卡片的风险段、8-12 接驳评估档相关章节——那里有我提前写的结论）。诚信制，无技术锁。
3. 批改环节才开封，Grader 对照 `_sealed` + 你的交付物出批改。
4. 本总纲和 BRIEF 的题面**只描述任务不描述发现**（写 BRIEF 时的自查项）。

## §4 方法论卡（拉动式，回应"架构随项目变"）

- 卡 = 一页可复用操作程序（触发条件 + 步骤 + 常见坑 + 首铸/打磨记录）。
- **不预建**。练习中首次实战某方法论 → 复盘时铸卡 → 下个资产再用时打磨版本号。
- 已规划的首铸点（写在各 BRIEF）：盲 review 程序（ra28/EX-01）、判断代码 work 五步（ra28/EX-02）、系统化 debug 五步（ra28/EX-03）、陌生代码结构侦察（ra26/EX-01）、证据分层写作（ra26/EX-03）、形式性质翻译法（ra30/EX-03）、调研画像方法（ra2716/EX-02）。
- 卡库 INDEX 只登记已铸的卡，永不出现 "planned; not-yet-created"（EA-6L 教训）。

## §6 调度与死线降级

**周计划建议**（每周 3-4 块，首轮 4-6 周；顺序可变，包内 EX 顺序不可变）：

```
W1-W2 ： ra28 EX-01~04（样板包先行，方法论卡密集首铸）＋ ra26 EX-01
W3    ： ra26 EX-02~04（toy 报告成型）＋ ra30 EX-01
W4    ： ra30 EX-02~03 ＋ ra2716 EX-01（盲写画像）
W5    ： ra2716 EX-02~03（贴 8-25 BR-1 复核点，产 OE-1 素材包）＋ 机动
```

**死线降级**（拍板④的操作化）：距硬节点（当前 = OE-1 due 9-10）≤2 周而对应产出未成型 → 启用旧方案档该章的 Agent 执行拓扑代做产出（产出优先），被代做的 EX 转为"逆向训练"：你 review Agent 的产物（review 别人的活也是训练，且是更真实的工作形态）。降级决定记 LEDGER + task_log。

## §7 Agent 角色与派单通则

| 角色 | 职责 | 关键纪律 |
|---|---|---|
| Setter（出题人） | 生成密封答案/埋雷 patch/独立基线 | 独立窗口跑；产物只进 `_sealed/`；对用户窗口零剧透 |
| Coach（陪练） | 按 H1→H2→H3 解锁提示 | 绝不跳级给答案；记录解锁到哪级 |
| Grader（评审） | 开封对账 + rubric 批改 + 复盘要点 | 批改含过程分（方法系统性、证据分层），不只对结果 |
| 主控 | 串场 + LEDGER + 铸卡确认 | 继承 8-12 纪律：单写者、骨架+footer、90 分钟块、输入白名单 |

派单细节（各角色的输入白名单、caps）写在各 BRIEF §3，新窗口直接抄。

## §8 多窗口并行模式（8-12 用户拍板：一包一专属窗口）

**窗口拓扑**：4 个训练包各开一个专属 Cursor 窗口，各自跑完整生命周期（赛前准备 → 做题 → 批改 → 复盘）。每包的窗口协议见包内 `KICKOFF.md`——**新窗口第一条消息只需**：`读 learning/training/<包名>/KICKOFF.md，按阶段 1 开始赛前准备`。

**跨窗口约定（防冲突）**：
1. **LEDGER 单写者**：各窗口只在 `LEDGER.md` 末尾追加自己包的行，绝不改别人的行。
2. **methodology/ 铸卡**：卡文件按包内 EX 归属创建（天然不冲突）；`INDEX.md` 同样只追加行。
3. **窗口内剧透纪律**（比单窗更严）：Setter 工作必须走**子代理后台**——主控在专属窗口对话里直接分析训练对象（读码找问题/读报告抽结论）= 分析过程用户可见 = 剧透。Setter 回执只准报「完成 + 路径 + 条目数」。
4. **跨包数据流**只有一条：ra28 EX-05 的三场景 log → 复制到 `research/pm4py_toy/data/` 给 ra26 EX-03 当对照（送达与否不阻塞 ra26）。
5. **转正通道唯一**：训练产物默认留 learning/；标"衔接产出"的交付物按各 BRIEF §4 落 progress/ 并记 task_log。
6. 本协调窗（建系统的窗口）不参与训练执行；训练机制变更只改本档，由用户发话触发。

**禁止**（所有窗口通用）：跳 EX 顺序；提前读 `_sealed/`；hint 跳级；把未过批改的产物转正。
