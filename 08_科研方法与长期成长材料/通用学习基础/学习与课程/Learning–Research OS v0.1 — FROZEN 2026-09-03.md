## 3. 每日硬训练原则

昨晚最重要的改变不是再设计一个漂亮学习系统，而是：

> **每天至少接受一次"有可能把我判错"的真实训练或验收。**

注意：不是每天必须 PASS 一项新能力。一个高质量的失败日也可能非常有价值：

> 手推 90 分钟 → 被问题打塌 → 发现原模型错误 → 没有任何能力进入 Ledger

这一天依然有 hard output。

因此每天可能产生两种有效结果：

- **A. 验收通过** → 进入 Hard Evidence Ledger
- **B. 暴露真实认知缺口** → 进入 Mistake Log

只有：

> 没验证任何东西、没暴露任何东西，只是看了很多材料

才算没有 hard training output。

若当天没有 PASS、没有可迁移认知错误、没有被 falsify 的假设、也没有进入可测状态的自有实现：

> 记一行 `NO-HARD-OUTPUT`；次日第一个可自主支配的 hard block 优先用于 hard training，完成前不主动扩展新的研究支线。

这是一条调度反馈，不是惩罚。固定课程、老师临时任务和既有 deadline 不因它被阻断；记录限一行，不写事故长复盘。

## 4. 三本账

### A. Hard Evidence Ledger｜硬证据账本

只收已经 PASS 的能力。追加制，不删除历史。

每项至少记录：
- 日期
- 能力点
- 验收方式
- 证据
- 掌握深度
- 是否需要冷启动复测

例如：

> 09-03｜能独立解释 Petri net 的 place / transition / marking / firing rule
> 验收：空白纸脱稿解释 + 自己画例子 + 修改初始 marking 后重算
> PASS
> D+2 冷启动复测

Ledger 不是"今天做了什么"，而是"什么东西现在有资格说属于我的能力"。

### B. Active Check List｜当前硬验收清单

每日放 1–2 个主目标。最多第三个 bonus，避免重新长成 production queue。

每项必须事前写明 PASS 条件。例如不要写：

> 今天学习 Petri net。

而写：

> 今晚能从空白纸解释 place / transition / marking / firing rule，并手推一个自己构造的例子。

**PASS 条件冻结规则**

最好在开始主要学习前写好，最迟当天中段冻结。验收以后不得为了让自己 PASS 而降低标准。

禁止：

> 原目标：独立推导 → 推不出来 → 偷偷改成"能看懂推导" → PASS

武曲不接受赛后改 rubric。

### C. Failure / Mistake Log｜错误账本

只收：

> 暴露了可迁移认知模型错误 / recurring failure mode 的错误。

**值得收**：概念误解；推理错误；数学错误模型；实验设计错误；claim 超过 evidence；论文理解偏差；"感觉懂了其实没懂"；反复出现的代码/研究思维模式错误。

**一般不收**：一次性 typo；少打括号；无意义的小环境报错；不具有迁移价值的机械事故。

每项记录：

> 原来相信什么 → 哪个验收暴露它错了 → 为什么错 → 正确模型是什么 → 下次看到什么信号应该识别 → 什么时候复测

**错误关闭条件**

"看懂了解析"不算闭环。必须重新独立做、独立推、或独立讲清楚之后才能 close。

## 5. 冷启动复测

今天会了，不等于永久拥有。

关键能力安排 D+2、D+7 随机冷启动复测。

核心问题只有一个：

> 答案和原对话消失以后，能力还在不在？

科研能力也一样。例如 24–72 小时后重新打开 repo：
- 能否说出 representation
- 能否找到关键实现
- 能否预测改动影响
- 能否修改一个条件
- 能否解释新结果

## 6. 晚间硬验收流程

每天 23:00 已设置晚间验收。

默认流程：

> 我先自己讲 / 做 → ChatGPT 追问 1–2 层 → 改条件 / 给变体 / 提反例 → 找到真实能力边界 → PASS → Ledger / 暴露问题 → Mistake Log

两个口径：
- **武曲验收**：到底会不会。
- **巨门验收**：到底讲不讲得清。

ChatGPT 的任务不是"嗯嗯你理解得很好"，而是尝试把我问塌。

## 7. AI 使用协议

核心原则：

> AI 可以替我节约时间，但不能替我完成本来应该长在我身上的训练。

**AI 可以大量承担**：搜索；文献定位；信息核验；API / 环境问题；格式；机械代码；辅助 debug；解释；reviewer；陪练；批量实验；长时间后台任务；repo housekeeping。

**但真正想长在自己身上的部分**：数学；定义；推导；证明；核心算法；关键代码逻辑；论文核心 reasoning——

默认流程：

> 裸机先手 → AI 辅助 → 关掉答案重新做 → 冷启动复测。

禁止：

> AI 写 → AI 跑 → AI 修 → AI 说"好了" → 我产生"我做完了"的感觉。

总原则：

> 该长在你身上的那部分，谁也不能替你长。

以及：

> 我不能再把训练本身优化掉。

## 8. 人类前台 / 硅基后台并行规则

惜时不等于把每一分钟塞满。真正的惜时是：

> 能异步的不要同步等；能提前暴露的风险，不拖到 deadline 前才发现。

例如上课、通勤期间，可以让后台 Agent 跑：文件 / 原件核验；实现线索查找；环境 smoke test；数据集与 baseline 信息核验；repo 缺口扫描；批量实验；已冻结任务的机械执行。

但后台输出只是：

> 研究输入 / 风险地图 / 原始材料。

不能直接算成"我的能力已经增长"。

**并行上限**

后台同时保持 1–2 条主要验证线。防止：

> 一焦虑没时间 → 开十个 Agent → 晚上收到 60 页报告 → 全天重新陷入治理和归档 → 自己没训练。

一句话：

> 硅基可以替我抢时间，不能替我长时间。

## 9. 防守深度：核心 / 邻接 / 外围

不追求九月底全覆盖。

**核心圈｜必须硬**

最终 frozen slice 直接依赖的知识。要求能：定义；推导；实现；解释；改条件；诊断错误；live defense。

**邻接圈｜有地图**

可能包括：DFG；Petri net；Inductive Miner / IMf；alignment；fitness；precision——但这里的名单不是永久固定的。真正划分方式是：

> 等 research slice freeze 后，从它向后画 dependency graph。

直接影响实现、实验判断、结果解释、live defense 的知识 → 核心圈。主要负责上下文理解的 → 邻接圈。

**外围圈｜允许明确不会**

可以直接说"这部分我目前还没有系统学到"。目标不是伪装全知，而是：

> 核心是真的，边界也是真的。

## 10. 九月底科研 artifact 的最低标准

最好至少具备：

**① 一块真的基础** — 不是 AI 摘要。自己可以脱稿解释、手推、做变体。

**② 一块自己实现** — 规模可以很小，但关键逻辑属于自己。

**③ 一个小而完整的实验** — 最小闭环：

> question → hypothesis / prediction → input → method → baseline → metric → result → alternative explanation → verdict → claim ceiling

尤其要求**实验前先写 prediction**，避免结果出来以后人脑自动编故事。例如：

> 我预计 A 会怎样变化，为什么？如果结果相反，优先怀疑什么机制？

**④ 一份可阅读包装** — 可以是 repo、README、一页 brief、图表、简短实验报告。但包装不能跑在 ownership 前面。

**⑤ 可以 live defense** — 需要能接住：为什么选这个 representation？baseline 为什么公平？如果换一个假设呢？为什么这个 metric？结果与预期不同怎么办？alternative explanation 是什么？哪部分 AI 帮过？现有 evidence 最远允许说到哪里？

**⑥ 一份核心论文的结构化理解产物** — 对与鲁组或当前 frozen slice 直接相关的一篇核心论文，留下可追溯 paper note，至少包括：

- 论文最核心的 claim；
- 方法 / 机制到底做了什么；
- 我在看结果前的理解或预测；
- 哪些细节论文没有充分公开、我无法确认；
- 哪些是论文原文，哪些是我的推断；
- 它如何影响当前 research question / implementation / experiment；
- 当前我认为最值得质疑或验证的一点。

Paper note 的目的不是证明“我读过”，而是留下“我到底理解到了哪里、哪里仍然不知道”的证据。

真正 ownership 至少包括：

- 能明确 claim ceiling

所以：

> 月底材料宁可窄一点，但那一块真的归我。

## 13. 如果最终选择 R1：Claim Ceiling

不能写"完整复现 EdgeIM"。更准确的上限类似：

> EdgeIM-inspired component audit / bounded replication-plus learning study

研究重点：

> 在固定 downstream process-discovery pipeline 下，控制 retained size，比较不同 sampling strategy 对 model-quality、structural、conformance 等 metrics 的影响。

在冻结 hypothesis 后再决定具体指标。不要提前重新焊成 sampling + discovery + alignment + 全 pipeline 的宇宙飞船。

## 14. 联系老师时的呈现原则

不要营造"我已经非常成熟、全部准备好了"。而是让老师得到关于我的准确模型：

- 我做了什么
- 哪部分真的属于我
- 哪部分只是理解
- 哪部分还不会
- 我为什么做这个问题
- 我目前适合接什么规模的小任务

**准备一个三层边界表**：

| 层 | 含义 |
|---|---|
| **A. 我能独立解释 / 实现** | 硬核心 |
| **B. 我理解，但目前不能独立实现** | 邻接知识 |
| **C. 我知道它存在，但尚未系统学习** | 外围 |

这样老师追问时，不需要瞬间进入"完了，被发现我不会了"，而是正常暴露知识边界。

## 15. 科研 taste 的六问

以后读论文、设计实验、review 自己工作，固定问：

1. **Claim** — 最强的 claim 是什么？
2. **Evidence** — 哪个证据直接支持它？
3. **Identification** — 这个设计真的识别了我声称的东西吗？
4. **Alternative** — 还有什么解释也能产生同样结果？
5. **Falsifier** — 什么结果会迫使我修改判断？
6. **Ceiling** — 按当前 evidence，最远允许说到哪里？

MCM 旧论文可以直接作为反例训练材料。过去会写"mathematically guaranteed"，现在先问"我真的有资格说到 guaranteed 吗？"

科研 taste 不是读一百篇"如何科研"，而是在真实对象中不断练这种 claim calibration。

## 16. 学习方法：不是设计出来，是析出来

目前不继续寻找"完美学习体系"。方法通过循环产生：

> 做 → 被判错 → 记录 → 修 → 再验 → 周复盘 → 小幅更新流程

原则：

> 方法不是前置条件，是对象层运行数据析出的产物。

**防系统过拟合规则**

除非暴露重大硬故障，一周内不大改学习协议。每次周复盘最多修改 1–2 个变量。

禁止：

> 周一 Ledger v0.1 → 周二 Evidence Ontology v0.2 → 周三 Cold-start DAG v0.3 → 周五发现真正学习了 40 分钟。

## 17. 今年真正要练的能力：低反馈期持续

已经有充分证据说明：在明确 deadline、明确 traceback、明确具体问题存在时，我可以爆发、扛压力、解决问题。

薄弱处是：

> **长周期、低反馈、没人催、暂时看不到结果。**

而这恰好是考研、数学补基础、科研、形式化方法学习长期需要的能力。

因此真正训练目标是：

> 不等悬崖出现，也能留下一个小 hard output。

简单约束：

> **不得连续两天没有 hard training output。**

Hard output 可以是：一项能力 PASS；一个真正错误被定位；一个假设被 falsify；一个自己实现的组件进入可测状态；一个实验得到可解释 verdict。

不算：看了很多；AI 分析了很多；Agent 写了很多文件。

## 18. 关于重修 / 数学

重修失败是真实劣势、真实错误，不洗白。

目前 evidence 支持：

> 当时投入与学习策略失败。

目前 evidence **不**支持：

> "数学能力上限已经被测出来。"

因为尚未发生过一个干净实验：系统训练 → 足量练习 → 掌握式备考 → 仍然失败。

接下来数学重新训练本身会产生新 evidence：空白纸能不能做；变式能不能做；D+7 还能不能做；能不能解释为什么；能不能冷启动恢复。

以后改变叙事靠的是新证据，不是继续辩论"我到底笨不笨"。

## 19. 惜时的新定义

过去确实存在低反馈期缺少紧迫感、很多时间没有形成持续积累。这个事实可以记账，不需要洗掉。

但从现在开始：

> 惜时 ≠ 全天焦虑地塞任务。

惜时意味着：
- 等机器的时候不干等 
- 能异步就异步
- 风险尽早验证
- 真正需要脑子的时间保护起来
- 不为了懊恼过去浪费今天

过去的问题结算一次：

> 低反馈期没有主动制造反馈和中频交付点。

新协议：

> 硅基等待时间并行利用；人类训练时间不被 production 吃掉；风险尽早暴露；每天发生硬验收。

然后继续干活。
