# 科研方法论框架

> 从论文拆解、审计、写作的实践中提取，持续更新。
> 按阶段组织：初读 → 深读 → 审计 → 批判 → 产出。每个阶段标注必备/进阶。

---

## 阶段总览

```
阶段 0：初读（30分钟）     — 抓住论文在干什么        【必备·每篇都做】
阶段 1：结构拆解（2-3小时） — 五层结构 + 逻辑骨架     【必备·每篇都做】
阶段 2：独立审计（1-2天）   — 公式验证 + gap 发现     【核心论文做】
阶段 3：批判性深读（半天）  — 假设审查 + 贡献评估     【想发论文时做】
阶段 4：现实关联（半天）    — 可证伪性 + MAS 翻译     【暗线方向做】
阶段 5：产出（1-2天）      — 研究方向 + 文献综述      【准备写论文时做】
```

---

## 阶段 0：初读【必备·每篇都做·30分钟】

目标：快速判断这篇论文值不值得深读。

读什么：
1. 标题 + 摘要 + 关键词
2. Introduction 最后一段（贡献声明）
3. 结论第一段
4. 图表扫一遍（看趋势，不看细节）

输出一句话：这篇论文用【什么方法】解决了【什么问题】，核心发现是【什么】。

如果这句话写不出来 → 要么论文写得差，要么你还没读懂，回去再读。

## 阶段 1：结构拆解【必备·每篇都做·2-3小时】

### 1A. 五层结构（Task → Challenge → Insight → Novelty → Flaw）

**1. Task**：这篇文章解决的是什么问题？
- 尽可能形式化（目标函数、约束条件、决策变量）
- 区分"大问题"（领域级）和"小问题"（本文具体解决的）

**2. Challenge**：传统方法遇到了什么挑战？
- 每个挑战标注：建模层面 / 分析层面 / 计算层面
- 标注已有工作在哪里卡住了

**3. Insight & Novelty**：
- 3.1 Insight 被什么 Inspiration 启发？（追溯到具体文献或现实观察）
- 3.2 Insight 是什么？建模/分析/策略哪个层面？
- 3.3 Novelty 在哪？架构/方法/策略上的创新？
- 3.4 每个 Novelty 严格按格式：
  `【解决什么问题】→【受哪个 insight 启发】→【设计了什么创新点】`

**4. Potential Flaw**：
- 4.1 情境局限性：能否延伸到更多维度/条件/约束？
- 4.2 数据/模型不良性质：什么情况下方法会失效？
- 4.3 哪种困难值得深度挖掘写成 paper？

**5. Motivation 反推**：
- 用问句形式："之前的方法...，那可不可以尝试一下...？"
- 从问题本质出发，找到最合理的想到这个 idea 的方式

### 1B. 逻辑骨架分析

| 维度 | 关注点 |
|---|---|
| **问题链条** | 背景→缺口→解决方案；research gap 具体是什么 |
| **方法论细节** | 数据来源、实验设计、关键变量定义、分析方法选择理由 |
| **结果逻辑** | 哪些结果直接回答研究问题？哪些是额外发现？因果推断强度？ |
| **讨论与局限** | 作者承认的局限 + 你发现但作者没提的问题 |

每一点附论文具体依据（页码、图表编号、公式编号）。

## 阶段 2：独立审计【核心论文做·1-2天】

### 2A. 审计流程

```
1. 读原文（重点：模型设定、核心公式、附录证明）
2. 独立推导核心公式（SymPy 或手算）
3. 交叉对照手动分析（analyse_XX.md）
4. 数值验证（参数网格：单调性、边界条件、退化情况）
5. 撰写审计报告
```

### 2B. 审计报告结构

```
1. 已确认（独立验证通过）
2. 边界条件（均衡/最优解存在的参数约束）
3. 待定（需要补充材料）
4. 新发现的 Gap
5. MAS 安全钩子（暗线）
6. 实用指南（可引用 / 需谨慎 / 不要引用）
```

### 2C. 三道安全门

- 🔒 **不编造** — 每句话有出处（页码/公式编号/代码输出）
- 🔒 **不过度承诺** — 没验证的用"待定"
- 🔒 **全覆盖** — 篇幅限制不能展开的**必须标注**

### 2D. 防遗漏规则

- 超过三点未列出的 → 备注标注
- 不能展开的 → 标注【篇幅限制，未展开】
- 每个 section 结束自检：有没有漏？

## 阶段 3：批判性深读【想发论文时做·半天】

### 3A. 假设审查

**假设清单**：
- 列出所有**显式假设**（标注论文位置）
- 识别所有**隐式假设**（作者没声明但推理中暗含的前提）

**假设分类**：

| 类型 | 说明 | 审查重点 |
|---|---|---|
| 定义性假设 | 对概念/变量的界定 | 定义是否标准？有无歧义？ |
| 简化性假设 | 为数学处理方便的简化 | 放松后结论是否还成立？ |
| 实质性假设 | 对现实世界的核心主张 | 有无文献质疑？有无反例？ |
| 技术性假设 | 保证数学推导成立的条件 | 条件是否过强？能否放松？ |

**假设合理性评估**（对每个实质性+关键简化性假设）：
1. 在现实/文献中是否合理？
2. 有没有被质疑过？
3. 放松后结论可能怎么变？
4. 作者是否讨论了局限性？

**假设依赖关系**：
- 哪些假设之间有逻辑关联？
- 是否存在"假设堆叠"——多个强假设叠加后模型严重偏离现实？

### 3B. 批判性评审（模拟审稿人）

**方法论审视**：
- 研究设计是否有内部效度威胁？
- 统计方法是否恰当？
- 有无混淆变量未被控制？

**逻辑审视**：
- 数据到结论的推理链中，哪一步最薄弱？
- 是否存在过度概括？
- 替代解释是否被充分排除？

**贡献审视**：
- 实际增量贡献是什么？
- 与已有工作相比 novelty 在哪？
- 对后续研究有什么启发？

**可复现性**：
- 方法描述是否足够详细？
- 数据/代码是否公开？

### 3C. 理论贡献评估

**与已有模型的关系**：
- 是对哪个经典模型的扩展/修正/替代？
- 关键差异是什么？带来了什么新洞见？

**洞见质量**：
- 核心洞见是"显而易见"还是"非显然"？
- 非显然的洞见有没有直觉解释？还是只是数学巧合？
- 对理解现实世界有什么启发？

**技术创新**：
- 是否引入了新的建模技巧或求解方法？
- 技术贡献是否有独立的方法论价值？

**理论推进 vs 原地踏步**：
- 结论是否只是已有结论的简单推论？
- 去掉所有数学，核心观点能否用一段话表达？这个观点前人提过没？

## 阶段 4：现实关联与 MAS 翻译【暗线方向做·半天】

### 4A. 现实关联评估

**可证伪性**：
- 哪些预测可以被经验检验？
- 有没有"不可能错"的预测？
- 模型是否做出了独特的、可区分的经验预测？

**现实对应**：
- 关键参数/变量在现实中有没有对应物？
- 能否解释已知的典型化事实（stylized facts）？
- 有没有已知事实与模型预测矛盾？

**政策/实践含义**：
- 模型得出了什么建议？
- 建议是否依赖特设假设？假设不成立时建议是否仍有效？

### 4B. MAS 安全翻译（暗线专用）

对每个核心概念，回答：

| OR 概念 | MAS 对应 | 翻译是否自然？ | 需要什么新工具？ |
|---|---|---|---|
| （逐行填写） | | | |

## 阶段 5：产出【准备写论文时做·1-2天】

### 5A. 研究方向文档（RESEARCH_DIRECTIONS.md）

四方向结构：

| 方向 | 类型 | 说明 |
|---|---|---|
| A | 明线·低风险 | 论文自身的自然延伸 |
| B | 明线·中风险 | 与其他论文的交叉 |
| C | 暗线·MAS 翻译 | OR → MAS 安全 |
| D | 勘误/修正 | 论文中的错误或可改进处 |

每个方向包含：种子观察、工作标题、核心声明、工作清单、预估工作量、目标期刊。

### 5B. 文献综述 / 张力结构

**But/However 张力结构**：
- 每段综述至少一个 But/However/Yet
- 指向一个真实存在的未解决矛盾
- 论证的是：问题存在 → 没人解决 → 你来了

## 科研能力培养：每篇论文的额外训练题

### 博弈论建模训练（每篇必答）

1. 博弈结构是什么？（Stackelberg / Nash / 机制设计）
2. 均衡概念是什么？（SPNE / Nash / Wardrop）
3. 信息结构是什么？（完全 / 不完全 / 不对称）
4. 搬到多智能体系统中对应什么？

### 抽象建模训练（每篇必答）

1. 现实场景是什么？
2. 做了哪些简化假设？每个放松后会怎样？
3. 换一个场景（如 LLM agent），数学结构能否复用？
4. 复用时需要改什么？（状态空间 / 策略空间 / 信息结构 / 目标函数）

### 第一性原理训练（遇到卡点时用）

1. 最基本的构成要素是什么？
2. 从零开始，最简单的解法是什么？
3. 已有方法在哪一步引入了不必要的复杂性？
4. 有没有更底层的问题，解决了它就自动解决当前问题？

### 审稿人视角训练（阶段 3 时用）

读完论文后，写一份 300 字的模拟审稿意见：
- 一个主要问题（major concern）
- 两个次要问题（minor concerns）
- 一个建设性建议（constructive suggestion）

这个练习的目的不是挑刺，是训练**从审稿人角度看论文**的能力——你未来投稿时，审稿人就是这么看你的。

|---|---|---|

| **实验设计能力** | 从 Paper 01 的 CVaR 实验扩展，学会设计数值实验验证理论预测 | Phase 2 代码验证时 |
| **论文写作能力** | 从 RESEARCH_DIRECTIONS 中选一个方向，写一份 2 页的 extended abstract | 02/03 审计完成后 |
| **Presentation 能力** | 把审计报告浓缩成 10 分钟的口头报告结构 | 联系孙教授前 |
| **形式化方法基础** | 读 Baier & Katoen 前 6 章，跑通一个 model checking 的 toy example | 今年下半年 |

### 怎么从框架中锻炼科研思维

不是"用了框架就有科研思维"。框架是脚手架，思维是在脚手架上反复练习后长出来的肌肉。

具体做法：
1. **每篇论文做完阶段 1 后，合上论文，凭记忆重写五层结构**。写不出来的地方就是你没真正理解的地方。
2. **阶段 3 的假设审查，先自己做，再对照 analyse_XX.md**。差异就是你的盲区。
3. **Motivation 反推是最重要的训练**——如果你能想到"之前的方法...那可不可以..."这个问句，说明你已经在用科研思维了。想不到就多练。
4. **模拟审稿意见写 10 篇以上**，你就会开始在读论文时自动切换到审稿人视角。这个视角是科研能力的核心。
