# 逐篇施工与专项验收

版本：v1.0；状态：PLANNED。本页给执行规格，不表示列出的源码、测试或实验已经产生。原件与旧拆解的准确路径见 [资料输入清单](资料输入清单.tsv)；下文 `B/papers/...` 等为本规划目录内的**待建输出**。

## 共同交付格式：每篇必须回答的具体问题

每篇建一个包，复用旧深拆并交增量，不把旧长文重新改写一遍。README 第一屏必须能让下一位执行者知道：它解决什么、能直接取用什么、哪个命令或手算入口可用、哪里仍不能用。

| 文件/字段 | 必填内容 | 过关方式 |
|---|---|---|
| `README.md` | 论文身份、当前P0/P1/P2/P3层级、用途、取用步骤、限制、下一个动作 | 复核者不看聊天记录即可找到入口和限制；未来路径明确标PLANNED，不冒充存在 |
| `sources.tsv` | `source_id,type,title,authors,version,date,url,local_path,sha256,locator,retrieved_at` | 原件实际存在；公式/图表定位到物理页＋对象编号；网页另存可获得正文或原件，获取不到记访问限制 |
| `analysis.md` / 旧文增量 | 问题→旧方法为何不足→表示/假设→机制→关键推导/证明→实验→结论上限；逐章READ/FOCUSED/NOT_READ | P2须覆盖所有论证相关章节；作者简介等无关部分可排除并写理由；P1明确本次只核哪个机制 |
| `claims.tsv` | `id,author_claim,source_locator,evidence_type,evidence_locator,our_judgment,counterevidence,open_issue` | 摘要、贡献列表、结论的主要主张取并集，去重后逐项有状态；P2不能靠“挑三条检查”结案 |
| `reuse.md` | 输入/输出、前后条件、不变量、异常、成本、原文机制与重建差异、目标consumer | 每项都有可操作定义；不允许“之后可用于Agent安全”代替接口 |
| `fixture/`、`expected/`、`src/`、`tests/` | 只为本篇确有计算用途的机制建立；手算/有限枚举/作者代码分级 | 预期由原文、独立枚举或事前手算提供；测试不得导入被测方法来生成自己的正确答案 |
| `DELTA.md` | 旧材料已完成什么、本次新增/订正什么、为什么值得做、仍未解决什么 | 若只有排版/搬文件，只记归档增量，不计机制交付 |
| `ACCEPTANCE.md` | 适用检查ID、逐项结果、原始日志run_id、复核者、阻断项 | 没执行的填NOT_RUN；未通过的不写PASS；不能以作者自己的“18 passed”字符串作证 |

题面、公开讲解、供教师使用的参考实现分别放置。未来参考包不直接并入本人的作答区。正式未见题由后续授权的验收环节准备；本轮不读已有 sealed/holdout，也不把已公开的这些例子当未见题。

## EI-01 · EdgeIM：采样机制与结构/频次分离

- 输入：SRC_EDGEIM；原课程只读复用。先核 Algorithm 1，保存原文排序/遍历、S/E/R更新、停止条件与返回值的坐标。
- 输出：`B/papers/edgeim/` 的P2分析包、`sample_features(log)`、独立 `full_features(log)`、`edge_counts(log)`；这些是新包接口名，不声称是作者仓函数名。
- `sample_features` 输入为已排序的非空trace序列；返回选中索引、对应trace和S/E/R。原事件表的CaseID/Timestamp排序由loader单列，不偷偷把普通活动列表当原始事件表。函数不得接受fixed K作为原算法参数。
- 固定公开例：`[('a','b')]*9+[('a','c')]`。输出选中索引必须为 `[0,9]`，条数10→2；S/E/R与全日志相同；边次数9:1→1:1。这是机制检查，不证明下游模型相等或不同。
- 检查 `EI-T1`：单活动trace不报空边错误；同一trace内重复边按发生次数计数；原输入不变；两次函数调用无共享状态。
- 检查 `EI-T2`：空日志返回空集合/空选择；含空trace拒绝；非法事件类型由loader拒绝。这里是新包接口选择，README须说明它不是论文补充承诺。
- 检查 `EI-T3`：活动字母表 `{a,b}`，枚举长度1–3的全部14种非空trace；枚举由1或2条这些trace组成的全部210个有序日志。被测输出逐个与“逐事件循环、独立计算新特征”的参考相符；不可调用被测 `full_features` 当oracle。
- 检查 `EI-T4`：每个枚举日志都满足全日志/选择日志S/E/R相等；选择数≤输入数；同日志重跑结果相同。换序可以改变选中集合和数量，不将“数量应不变”写成断言。
- P2额外检查：三阶段输入/输出及Stage1集合R、Stage2权重、Stage3具体consumer分开；九日志评测主张逐项回源，未知参数保留OPEN。不得把这个单元命名为“整篇EdgeIM复现”。

## PNU-01 · PNULock：合法终止、伴随网与可重演性

- 输入：SRC_PNU。旧拆解第22–49行可作导航；原文定义1/3/4/5、Table III、算法1–3、展开与cut-off段是回源对象，物理页由执行者核实后写入sources。
- 全文产物必须画清：同步轨迹→轨迹网→死锁伴随网→展开/配置→每锁调度序列→程序重演。每个箭头附输入、输出和成立假设。
- 必做组件：`add_recover(net, legal_terminal_places, lock_places, initial_place)` 与其使能/发射核验。核原文定义5：recover的前集为合法终止库所并全部锁库所，后集为初始库所并全部锁库所。必须从原文说明为什么正常结束不再被报告为非法死标记。
- `PNU-T1`：合法终止标记中所有合法终止位及锁位为1，其余按已冻结网定义为0；加入recover后该标记不再是死标记，发射后恢复指定初态。锁位始终不超过1。
- `PNU-T2`：两线程各持一锁、等待另一锁的冻结小网标记，原网无可使能变迁；recover不使能，非法死标记仍然存在。另设单侧正常结束和全部正常结束，避免“无后继=死锁”。
- `PNU-T3`：用独立显式可达状态枚举检查上述网的终态；如另实现展开，只在这些有限网比较两种检查的死标记集合。**只有枚举时明确叫枚举校验器，不冒称实现McMillan/ERV展开。**
- `PNU-T4`：同一语句的两次执行分配不同事件/变迁ID；输出轨迹事件↔变迁映射，不能按源代码行号去重。
- `PNU-T5`：重演结果必须分CONFIRMED_DEADLOCK / NORMAL_TERMINATION / UNKNOWN；未清空调度、额外park/unpark等条件不得强报“确认死锁”。未接真实程序探针时只交协议和模拟输入检查，保留真实重演未运行。
- 源码/图形输入缺失时，交论文机制的手工逐状态推演和上述构造规格；P2中的计算核验不能用泛化等待图演示替换。本文P2不要求两天内重建完整CalFuzzer系统。

## SBP-01 · SBPN：真实公式的数值核验与理论范围

- 输入：SRC_SBPN。回源重点：定义1、式(6)与定理1、式(7)与定理2、式(8)/(9)、实验图表。旧拆解第254–279行指向PDF物理页14–15，但仍须读原PDF确认。
- 必做组件：`adjust_rule_probability(r, catalysts, inhibitors)` 实现**原式(9)的逐项修正后求平均**，并另交式(8)的变迁层组合函数。保留逐符号映射和因果独立假设；不得用普通OR/AND计算器冒充。
- `SBP-T1`：冻结公开输入 `r=.5`；一个催化项 `Pr=1,lambda=.6` 应得 `.8`；一个抑制项 `Pr=1,lambda=-.7` 应得 `.15`；两者共存应得精确 `.475`，两位小数展示可为 `.48`。不能把顺序叠加或 `.15+.8` 当原公式。
- `SBP-T2`：同一批协同项改变输入顺序结果不变；返回值在[0,1]；概率越界、lambda越界、同一对象对同一变迁被同时登记催化/抑制时拒绝。
- `SBP-T3`：没有协同项时返回原r作为明确的接口边界，不直接计算分母0。若原文无此边界，标ENGINEERING-BOUNDARY并解释；不能伪作原文定义。
- `SBP-T4`：冻结独立教学参数 `leak=.1, active_rule_probabilities=[.5,.6]`，式(8)应得 `.82`；空active集合应为leak。此参数组为公式检验，不是论文油罐案例复现。
- `SBP-T5`：定理1/2分别写出前提、结论和逻辑方向。以原文为准核“充要/单向”；不能从分数过阈值反推未证明的充分条件。算法阈值 `>` 与 `>=` 如有原文冲突，记录两种输出边界，不自行静默选一个“修好”。
- `SBP-T6`：每个重算值区分精确数、展示舍入和论文图读数；不可倒推缺失的多个CPT单值并称作者参数。其余实验主张按claims逐条标复核/转录/未知。

## ML-01 · 后续小型训练设计（本轮不挤占EX-05）

性质：基础训练材料，不是研究novelty，也不是LLM训练。当前近期优先修订后，本轮只保留输入、前置和施工规格到`A/FUTURE_ML_QUEUE.md`；只有EX-05材料全部就绪且有余量才开始建脚手架。以下完整规格不因延期而删除，未施工不得写READY或PASS。

1. **任务与数据**：二维二分类，x1/x2独立均匀取[-1,1]，标签 `y=int(x1+0.5*x2+0.25>0)`；无标签噪声版本先学训练闭环。这个标签规则是教学设定，不能当真实Agent安全标签。
2. **实例划分**：每个数据seed `[11,23,37,51,89]` 生成300个带ID样本，生成后立即冻结CSV；ID 0–179训练、180–239验证、240–299测试。检查ID不相交、没有逐行重复泄漏；若后续引入模板/扰动派生样本，必须按原始实例组划分，不能沿用逐行切分。
3. **预处理**：均值和标准差只在训练集拟合；零方差特征scale=1；参数和划分写入RUN_CONFIG。更换标准化方法属于协议变更。
4. **模型/基线**：多数类基线只看训练标签；逻辑回归 `sigmoid(w·x+b)`，全批梯度下降，初始化w=b=0；学习率候选[.01,.1]、L2候选[0,.01]、epochs=200。验证BCE选超参，平局先选较小L2再较小学习率；完成选择后每seed只评一次测试。已知生成规则若画成上界，要标有额外机制知识，不作可学习模型的公平成绩。
5. **具体手算**：在已处理的输入 `x=(1,2), y=1, w=(.2,-.1), b=0, L2=0` 上，z=0、p=.5、BCE=ln2；梯度w=(-.5,-1)、b=-.5；学习率.1更新后w=(.25,0)、b=.05。完整推导随教师参考交，学员起始件不含这些目标值。
6. **意义明确的检查**：`ML-T1` 固定前向/更新值与独立手算一致（误差≤1e-9）；`ML-T2` 有限差分梯度相对/绝对误差≤1e-5；`ML-T3` 改动测试样本不改变训练scaler/选参；`ML-T4` 各split ID不相交；`ML-T5` 混淆矩阵总数等于测试样本数，独立重算BCE/accuracy一致。
7. **运行产物**：每seed的学习曲线CSV、scaler、权重、超参选择表、测试预测、accuracy/BCE/混淆矩阵、至少一类错误/边界样本解释和原始日志。没有错误样本时如实报告，不为凑数编造。
8. **通过边界**：不规定必须达到某个accuracy来算学会；先验收实现/切分/选择/计量正确和用户能解释错误。AI参考训练通过只提升材料状态。

## IDEA-01 / RT-01 · 自己的问题与研究toy

这部分消费已经产生的机制资产；论文包不以“想出idea”为通过条件。每个候选卡必须包含：观察、原方法依赖的条件、剩余问题、可测预测、最强简单解释、最近邻、潜在价值、证伪条件、下一条区分性证据。

至少实际比较两个问题族，候选种子只是待查：

- 选择/表示：结构覆盖、重要性、频次或下游模型目标何时错配；先查EdgeIM直系采样前作和强选择基线。
- 并发/见证：轻量图候选到可实现调度之间丢了什么；先查PNULock/SegLock/JOS/MHP已有边界，不能把补一条已知语义说成创新。
- 概率/根因：判定定理的条件与真实分布不符时，阈值/校准是否更有用；先查SBPN/SBTPN自身补充材料和相邻统计方法。

最近邻搜四种证据：论文（方法与保证）、开源（实际实现/维护/issue）、企业机制（已解决哪些操作问题）、失败/负结果（失效条件）。每类写实际检索式、时间、来源、纳入/排除理由；无命中保留检索范围，不能写“全球无人做”。前两项候选要对齐相同输入、可见信息、任务性质、保证、预算和输出；一项不一致就不给无条件优劣排名。

**可直接执行的toy协议验收条件**：

1. `RUN_CONFIG` 填出对象/状态、标签规则、样本ID、split、全部种子、每个比较方法、参数范围、预算K和成本单位、评价函数、允许差异、停止条件；空字段或“以后选一个”均不通过。
2. 真值函数由系统完整状态或独立规范定义；被测方法接口不得读标签/隐藏状态。用修改隐藏标签但保持可见输入的检查，确认选择结果不会偷变。
3. 基线至少包含同信息的简单规则/风险方法和可运行的最近邻；随机只作参照。若普通字段校验已充分解决固定问题，这个候选可直接淘汰，交证明/案例，不必强跑一个新方法。
4. 每次只改一个因素（噪声/缺失/乱序/预算/分布等），保留正常、异常和消融。比较使用成对相同输入与种子；至少5个冻结种子，报告逐seed原始值，不能只报最优一次。
5. 开发/测试按过程或模板家族隔离；参数不能看测试结果选择。消融/误差分析不得回写测试集。
6. 指标定义到分子分母：违规召回=预算内查出的真违规数/该测试集真违规总数；同时报无害占用、误拦、任务效用和实际成本。没有真违规的集合单独标NA，不能默认满分。
7. 预先冻结退出判据：同信息强基线持续持平/更好、收益来自额外信息、成本抵消收益、效果依赖单一机制/种子均触发修改/淘汰；有差异也只能报告当前机制证据。数值容忍区间须根据指标分辨率和使用成本设定，不临场挑显著性阈值。
8. 有合格候选则交完整协议和可运行入口；无合格候选则交“候选—最近邻/简单方案覆盖证据—被否定主张—仍残留问题”档案。协议通过≠实验运行，实验运行≠新颖性成立。

## 运行、验收与返工的统一动作

生产时先构建 `tools/capture.py` 与 `tools/run_checks.py`（本轮尚未创建），或复用已经能满足同一合同的现成工具。不得为了做“平台”拖延论文机制交付。

- capture直接捕获子进程命令数组、cwd、开始/结束时间、真实exit code、stdout/stderr、Python/依赖版本、代码与输入hash；运行失败也保留；已有run_id不可覆盖。
- run_checks检查本包要求的命名用例是否真实发现并执行；零测试、缺必验用例、skip必验用例均失败；数值/逻辑预期参照本页，不能只检查字段非空。
- 每个可运行包在隔离临时副本冷启动一次；临时目录用系统生成的具体路径，保留失败现场，不操作共享原目录。只在已有Python环境或包内独立环境运行，依赖变更和额外资源单独记录。
- 复核者用原文和独立手算/枚举核结果。控制器核实际文件与日志；同一模型换上下文不得宣称异构审查，模型审查也不代替数值oracle。
- 任一身份错误、关键公式错、把模拟当真实运行、泄露正式答案属于阻断问题；先隔离该产物并回溯相同来源的其他包，不把全仓已有成果归零。
