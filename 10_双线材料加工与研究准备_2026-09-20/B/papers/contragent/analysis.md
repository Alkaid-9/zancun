## 1. Question, contribution, and complete-section route

The authors address the gap between per-action tool guardrails and post-hoc stochastic trajectory graders: define checkable interaction predicates, write trajectory-level assume–guarantee contracts in arithmetic finite-trace temporal logic, and reuse per-contract checkers for both online gating and offline recorded-trajectory scoring (abstract and three contribution bullets, pp.1–2; CA-02–04). This is a **conditional method**: the observation map, policy construction, and environment instrumentation are inputs, not guarantees proved by compiling an automaton (pp.4–5,8; CA-12,15,26).

## 2. The actual object chain (pp.2–5,11)

1. **Agent interface:** Def.1 p.2 has an event alphabet Σ containing a call `(tool,args)` and a return `(tool,result)` per tool invocation. A session state `s=(τ,κ,ρ)` stores the existing finite event trace, context-key map, and numeric counters. Its transition appends an event and updates context/counters. Do **not** insert an extra formal `effect` or `END` event from our old teaching sketch as though it were in Def.1 (CA-05).
2. **Observation/grounding:** Def.3 p.3 computes Boolean `P(s,a,c)` from the current event, state, and parameter. Structural AP include `Call`, `ArgHas`, `OutHas`, `Match`, `Flow`, `Perm`; numeric AP compare `Cnt`, `Num`, `Tok` etc. against a threshold. Table 1 is **only a subset**; Appendix A Table 4 p.11 lists 22 entries, and explicitly excludes `Since(e)` from the formal Def.1 state, treating it as an implementation-time extension (CA-09–10).
3. **Contract:** Def.4 p.4 partitions vocabulary `V=V_ag∪V_env`; assumption `φA` uses environment-controlled AP only, guarantee `φG` may use all AP. `OutHas`/user input/permissions are examples of the environment side; `Call`/arguments/call counts are agent-side examples. Other agents' actions are categorized as environment, **not** automatically given a multi-agent causality model (CA-11).
4. **Valuation:** Rendered Eq.(1) p.3 gives `IDLE=1` if `¬A`, `ACTIVE=e` if `A∧G`, `FAIL=0` if `A∧¬G`, with `0≤e≤1`. The plain-text PDF extraction *omits the overbars* on `A`/`G`; copy the rendered equation, not the extraction. Across contracts, Eq.(2) uses `venv=max(join)` and Eq.(3) `vag=min(meet)`. The online σ blocks the first prefix whose pair differs from `(e,e)`; the offline µ records the pair for the given trace. This distinguishes environment assumption failure from an agent guarantee failure (CA-07–08).
5. **Construction:** §5.1 p.4 describes lifting natural-language requirements with an LLM, deterministically grounding placeholder predicates, and human review of a back-translation; the author also allows manually written formulas. Each contract's assumption and guarantee gets its own automaton, together stored as a checker. Numeric counters stay outside the finite automata and are consulted by grounding. The loaded library is checked for consistency, compatibility, and joint satisfiability (CA-12–14). Therefore “a single DFA solves agent safety” is **not** an acceptable paraphrase.
6. **Runtime:** §5.2 p.5 first grounds AP, advances each checker, then gates the next call. Author implementation progresses residual formulas incrementally and reports per-event `O(|C|)` for loaded contracts `C`; this is the authors' bound under their cost model, **not** an empirically verified end-to-end constant independent of predicate parsing, event instrumentation, or contract size. Refused call or suppressed return/input is not appended to the *monitored* prefix (CA-15–16).
7. **Offline:** §5.2 pp.5–6 replays a fixed recorded trace with the same checkers but **no intervention**. With the same library and grounding, online and offline checker states/verdicts agree on any *shared prefix*. After an online block/suppression, the subsequent real-world history may differ, so this fact does not assert outcome equivalence of a blocked live session and a fixed unblocked historical trace (CA-17).

### Side-effect boundary (critical)

The PDF says a *proposed call* is checked before execution, but a **return** arrives after its tool has already executed. Suppressing its return from the agent's observation and monitored trace cannot by itself roll back an external effect that occurred in the tool. The authors' §6.4 p.8 also explicitly trust the framework's faithful reporting of events and counters. Therefore claims of “no hidden side effect”, “atomic approval”, “all effects reversible”, or “audit logging does not alter business state” require a **separate host/transaction protocol and evidence**; they are *not* ContrAgent theorems. This is our inference from Def.1 p.2 and §5.2 p.5, not a direct author quote.

## 4. Deliberate falsification and strongest simple alternative

**Observation-sufficiency challenge (our reconstruction, not author experimental result).** Fix a deliberately *coarse* monitored AP vocabulary `V={Call(approve), OutHas(approve,success), Call(commit), Cnt(approve)≤1}` and a project-world property `φ=commit(A) has a successful current-version approval for exactly A`. Two histories that differ only in the approved object's hidden `order_id` induce identical `V`-valuations but opposite independent `φ` labels. Determinism then implies **any checker over only this V has the same verdict on both**. Details and a second return/effect challenge are in `fixtures/predicate_blindspot_pairs.json`. This challenges an under-instrumented *instantiation*, **not** the paper's entire 22-predicate language: `Match`, `Ctx`, or additional fields may resolve the pair if correctly grounded. No actual ContrAgent implementation or checker was run.

**Strong simple baseline.** Use an object-aware finite-state map `approved[order_id]=(version,request_id)` and check the current version on `commit(order_id)`. Under a trusted, versioned `approve_return`, this simple baseline distinguishes the pair; if it suffices for the target property, the claim that ALTLf is *necessary* for this case must be dropped. Compare (i) coarse AP checker, (ii) object-aware FSM, (iii) an ALTLf contract **on the same visible fields**, and (iv) an oracle with full hidden world state. Equality of visible inputs and access permissions is mandatory. A proposed fixture is **not** a measured baseline result (NOT_RUN).

**Intervention challenge.** If a tool performs an irreversible side effect and then returns an assumption-violating payload, the monitor can suppress its return, but the tool's effect is not shown to roll back. A faithful event/effect/ack protocol or reversible transaction must be supplied to claim preventive enforcement beyond gating calls. This is an inference and an explicit future test, not a paper-produced counterexample.

**Falsifiers/limits for any application claim:** unobserved call or missing return; inaccurate context/counter; inconsistent policy library; natural-language-to-formula error despite back-translation; semantic harm outside observed predicates; tool effect before a suppressed return; a simpler FSM that solves the same fully observed task. The paper acknowledges human contract inspection and untrusted free-form harms in §6.4 p.8 (CA-26). JINZU bridge remains `HYPOTHESIS`, not a new method/novelty or proof of an agent safety system.
