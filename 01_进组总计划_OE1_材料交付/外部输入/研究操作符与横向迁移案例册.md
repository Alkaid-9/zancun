# 研究操作符与横向迁移案例册

v1.0｜2026-09-05｜配套《科研学习与训练体系》

这份文档保存我们已经谈到的具体实例，以及从实例中抽出的研究动作。它回答四个问题：原工作做了什么？我们想借什么？哪里不能照搬？怎样把联想变成可检查的问题？

案例之间的连线主要是我们的机制比较，除明确标注的论文引用关系外，不表示作者之间的历史影响。本轮核对了下面列出的论文或官方材料；核对深度不同，逐项标明。本次没有复现这些工作的实验，也不把论文报告的结果算成我们自己的验证。

阅读方式：先看第1节的总索引；学习 EdgeIM 时按需要打开第2、3节；跨域探索时查第4、5节。第6节是一张已经填好的迁移卡，第7节说明如何继续检索和更新。案例册是可调用的材料库，不是新增的必读清单。

## 1. 总索引：我们在追的研究动作

最有贯穿力的母结构是：**运行痕迹 → 恢复结构 → 显式表示 → 检查 → 改变系统 → 新的运行反馈**。

但不是每篇都走完整条链。有些从自然语言规范出发，有些从源码抽图，有些只诊断而不干预；不能因为最后都画了图，就说它们解决同一问题。

| 研究动作 | 已找到的实例 | 当前最值得追问的接口 |
| --- | --- | --- |
| 改表示、减少有效自由度 | Mapping Networks；EdgeIM | 压掉的信息，对哪个目标无关？ |
| 利用冗余，再追新瓶颈 | IndexShare；LayerSplit；HiSparse | 优化以后，端到端主要成本移到哪里？ |
| 区分真实依赖与偶然顺序 | DSpark；TraceCompiler；Causal Past Logic | 哪种依赖必须保留，日志能否识别它？ |
| 按价值和资源安排验证 | DSpark 的调度机制 | 哪个检查最可能改变决定？ |
| 检查反馈环境本身 | GLM-5.3；Ground Truth Approach | verifier、标签与测量到底在判什么？ |
| 把失败变成判断更新 | Chain-of-Experience；Manus | 错误来自哪条假设，反馈是否可信？ |

## 2. 当前主干旁边的四篇论文

### 2.1 四个角色与比较范围

| 论文 | 训练角色 | 和 EdgeIM 对照什么 | 本轮证据范围 |
| --- | --- | --- | --- |
| EdgeIM | 主干：拆到能重建、解释、实现与审计 | 日志 → 过滤 → 局部特征 → 全局图 → 模型 | 书目核对；机制承接原讨论与既有训练材料，本轮未重新逐行核完全文 |
| sigRank | 横向方法对照 | 新结构覆盖与 trace significance；预算、选择准则、最终质量 | 官方研究成果页与摘要；具体评分公式、实验协议待相应阅读窗口核对 |
| A Ground Truth Approach for Assessing Process Mining Techniques | 实验方法论 | 如何区分行为偏差、记录错误与方法失真 | 论文/全文来源核对，保留其数据生成与ground truth链条 |
| CrossEdgeIM | 纵向后继 | 计算位置、增量更新、特征聚合与模型合并 | 已读六页PDF，尤其引言、方法与有效性威胁部分 |

来源：[EdgeIM](https://doi.org/10.1109/ICWS67624.2025.00057)；[sigRank研究成果页](https://novaresearch.unl.pt/en/publications/toward-efficient-support-for-business-process-event-log-sampling/)及[DOI](https://doi.org/10.1109/TSC.2026.3665370)；[Ground Truth论文](https://arxiv.org/abs/2501.14345)及[出版全文](https://pmc.ncbi.nlm.nih.gov/articles/PMC11934509/)；[CrossEdgeIM](https://doi.org/10.1109/MIOT.2025.3625047)。

sigRank是方法名，检索论文时应同时使用正式标题 Toward Efficient Support for Business Process Event Log Sampling。原讨论中的输入采样比例、具体模型评价流程和“同一15%样本差异很大”，进入正式比较表前要回到相应版本的算法与实验段落。本稿不以摘要替代这些细节的核验，也不重复未逐项核对的性能数字。

### 2.2 EdgeIM：支撑集合、频次与消费方的接口

按原讨论的 Algorithm 1 机制，每条trace携带起点、终点与直接跟随特征。实现抽象时应使用带类型的特征，例如 start(A)、end(A)、edge(A,B)，不能把不同角色的同名活动混成一个元素。

已覆盖集合记为U；新trace的特征集合为F。若F中还有未被U覆盖的元素，就保留trace，并更新U。这个规则利用集合并的幂等性：同一个特征出现多次，不改变“是否存在”。因此，在固定特征定义、完整扫描与正确更新的条件下，所有已观察到的特征仍有保留的见证。

计数采用加法，重复出现会改变结果。因而“支持集合相同”不能推出“频次相同”，更不能直接推出“下游发现模型相同”。判断后者必须核对具体miner版本、输入形式、过滤参数、起终点计数及其实际读取的信息。

**可借的操作符：先找消费方需要的保持条件，再设计压缩；随后审计保持条件是否覆盖消费方的全部需要。**

“见证trace + 原始边计数”是我们的候选扩展，不是这里替论文补写的方法。若消费方只读取完整、同定义的带权DFG摘要，保留这份摘要就可能足够；若还读取trace级顺序、属性、时长或变体分布，就不够。若只为这个消费方服务，也要反问见证trace是否仍有必要，不能默认所有组件都需要。

### 2.3 Ground Truth：构造能区分解释的世界

这项工作把初始过程模型、已知行为偏差、变化后的模型、记录错误与最终日志保留在一条可追溯的生成链上。它的价值在于：观察到某种偏差时，评估者有依据区分“过程确实变了”和“记录出了问题”。[论文全文](https://pmc.ncbi.nlm.nih.gov/articles/PMC11934509/)

**迁到我们的训练：**先明确要审哪个claim，再决定需要怎样的ground truth。例如“过滤扭曲统计量”和“过滤让某个miner漏掉行为”是不同问题，需要不同的检查。

**类比停止处：**合成世界给出已知答案，不代表覆盖真实环境。通过合成实验支持的是给定生成机制下的结论；真实日志仍承担外部有效性检查。验证器也不能与待测方法共享同一个未审计错误，然后相互“证明正确”。

### 2.4 CrossEdgeIM：有文献依据的后继，与我们重建的瓶颈迁移

| 维度 | EdgeIM | CrossEdgeIM |
| --- | --- | --- |
| 原讨论中的核心压缩/更新手段 | case级特征保持过滤 | activity节点在线维护并传递增量特征 |
| 中间层 | edge侧构造局部特征 | organization侧聚合Org-DFG并发现局部Petri网 |
| 顶层输入 | 局部特征/DFG信息 | 各organization已发现的模型 |
| 顶层主要工作 | 聚合全局图后发现模型 | 合并局部模型 |
| 需要继续审的接口 | 保持的特征是否足够支持下游 | 顶层组合是否显式表达跨组织交互 |

CrossEdgeIM引言直接讨论EdgeIM，参考文献[8]就是EdgeIM；它的中心合并以共同split/join连接组织模型，正文也承认协作关系与组织间交互仍未显式捕获。这支持我们把它记为“后继扩展”，也支持追问新的交互语义问题。[CrossEdgeIM，§I、§III-D、§IV-C](https://doi.org/10.1109/MIOT.2025.3625047)

“旧架构留下压力 → 计算下沉 → 顶层改为模型组合 → 交互表示成为新的关键问题”是我们依据方法重建的研究动作，不是作者完整自述的思考历史。EdgeIM含鲁法明署名，CrossEdgeIM不含；合作谱系不能直接等同实验室组织关系。

## 3. 从飞机论文等材料抽出的操作符卡

下面每张卡中，“原机制”尽量限于来源支持的范围；“迁移”和“最小练法”是我们提出的训练用途。最小练法是任选入口，不自动成为正式作业或新的PASS条件。

### OP-01｜Mapping Networks：先问为什么在这个空间求解

**原机制。**工作用紧凑的可训练表示，通过mapping产生网络参数，使优化不必直接在全部原始权重自由度上进行。本轮核对摘要与论文入口，未独立复核其所有理论或实验。[Mapping Networks](https://arxiv.org/abs/2602.19134)，[CVPR论文](https://openaccess.thecvf.com/content/CVPR2026/papers/Sen_Mapping_Networks_CVPR_2026_paper.pdf)

**抽出的动作。**质疑默认搜索空间；区分表面自由度与任务所需自由度。

**迁到EdgeIM。**完整日志是否是下游必需的输入？某个摘要能否替代它？这里借的是“换表示后再解决”的动作，不是把日志过滤称为同一种参数化方法。

**停止条件。**低维表示存在、容易学习、保留任务性能，是不同命题。结构覆盖也不能借“低维”这个词自动升级为充分性。

**最小练法。**对一个压缩表示列两种查询：一种能够精确回答，一种不能；明确被压掉的自由度影响哪一种答案。

### OP-02｜IndexShare / LayerSplit / HiSparse：消除冗余以后重新测量

**原机制。**GLM-5.2材料介绍IndexShare以减少稀疏注意力索引相关开销；后续服务优化材料讨论LayerSplit、HiSparse等系统措施及实际部署成本。本轮核对官方介绍与SGLang优化文章；它们构成机制相邻的案例组，不把并列出现直接当作严格的发明先后链。[GLM-5.2官方介绍](https://z.ai/blog/glm-5.2)，[SGLang服务优化记录](https://www.lmsys.org/blog/2026-07-13-glm52-optimization)

**抽出的动作。**profile → 找主要浪费 → 利用冗余 → 计算新增成本 → 再profile。端到端瓶颈会随优化改变。

**迁到EdgeIM。**减少trace处理之后，再测通信、特征维护、中心发现或质量损失是否成为决定性问题。频次失真是待检查的质量接口，不能未经实验就称为“新的最大瓶颈”。

**证据待补。**原笔记中“局部相似性proxy不如直接看LM loss”的具体实验，本轮没有定位到对应段落。保留为回查项，不借官方文章入口把这条旧记忆认证为已核实事实。

**最小练法。**给一个已有流程列耗时与质量成本；提出优化前后的预测，实际测一次后更新排序。不要一直优化已不再主导总成本的部分。

### OP-03｜DSpark：拆开昂贵计算与必须保持的依赖

**原机制。**DSpark结合并行生成骨干与较轻的顺序模块，并使用置信信息安排推测解码；顺序部分承担块内依赖相关工作。本轮核对方法段落。[DSpark论文](https://arxiv.org/abs/2607.05147)，[方法全文](https://arxiv.org/html/2607.05147v1)

**抽出的动作。**先识别依赖落在哪个部分，再决定并行边界；串行与并行不必是整个系统层面的二选一。

**迁到科研工作。**独立来源检索、实现定位和候选构造可以分开进行；最终claim的界定与证据解释有逻辑依赖，需要整合后的判断。这个组织建议不是DSpark对人类研究流程做过实验所得的结论。

**停止条件。**日志中先后发生不等于必须先后发生；“可以并行”仍需检查共享状态、资源冲突和结果消费关系。

**最小练法。**取一个熟悉流程，画出谁读取谁的产出；给每条串行边写出保持理由。没有理由的边先标“待查”，不直接删除。

### OP-04｜DSpark：验证价值与资源状态共同决定调度

**原机制。**其置信调度结合候选接受相关信息与运行时负载，考虑验证开销和资源机会成本。这里的置信信号和成本对应具体解码系统。[DSpark，调度方法](https://arxiv.org/html/2607.05147v1)

**抽出的动作。**同一个验证动作在不同资源状态和决策情境下，价值可能不同。

**迁到科研。**先查“会不会改变我们对方法的判断”的未知，再查对结论没有影响的细节。可比较错误可能性、决策影响与成本，但没有校准数据时不用虚构精确分数。

**停止条件。**调度优先级不能改变证据标准；支持当前主张所必需的检查不能因成本高而被默默省掉。“高风险依赖边优先放检查点”是我们的候选预测，不是原论文已验证的Agent结论。

**最小练法。**对三个未知各写一句“答案改变后，我会怎样改变下一步”。答不出的未知暂缓。

### OP-05｜Chain-of-Experience与Manus：失败要经过反馈和归因

**原机制。**Chain-of-Experience研究结合尝试与反馈的持续改进；Manus的工程文章强调保留失败行动等上下文，帮助后续行动调整。前者是研究工作，后者是构建系统的经验记录，证据类型不同。[Chain-of-Experience](https://arxiv.org/abs/2608.18027)，[Manus上下文工程文章](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)

**抽出的动作。**attempt → feedback → diagnosis → revised attempt。失败记录的价值取决于反馈质量以及能否定位需要修改的判断。

**迁到Mistake Log。**保留“原belief、被哪项证据击穿、正确模型、下次识别信号、独立复测”，而不只写“答案是什么”。例如把原算法误读为fixed-K，真正该更新的是“比较时新增的预算规则可能已经换了研究对象”。

**停止条件。**失败可能来自工具、数据、测量或环境，不一定来自策略；不能每次都归因于同一条belief。模型实验也不直接证明某种人类教学安排有效。

**最小练法。**找一次真实错误，写出两种原因及能区分它们的检查，再决定改什么。

### OP-06｜GLM-5.3环境：先验收产生反馈的地方

**原机制。**官方材料描述验证器构建与环境检查，包括利用求解轨迹寻找奖励捷径，以及oracle、no-op、未解状态等检查。它说明反馈系统本身也是需要设计和测试的对象；这是官方方法说明，不是我们独立验证的效果结论。[GLM-5.3官方文档](https://docs.z.ai/guides/llm/glm-5.3)

**抽出的动作。**不要只问系统能否提高分数，还问分数究竟奖励了什么。

**迁到科研训练。**参考答案从哪里来？手算与代码是否真的独立？做题者是否能靠格式或泄漏信息过关？评测测的是记忆、操作还是迁移？

**停止条件。**两个实现一致不保证正确，可能复制了同一错误；更多反馈也不自动带来更好归因。训练者不能伪造结果来考验更新能力。

**最小练法。**给一个检查器输入已知正确、已知错误和无实质工作的答案，看它是否按目标区分；只做当前任务需要的检查。

### OP-07｜DataMagic / DVSpec：把关键语义落到显式表示

**原机制。**DataMagic面向数据洞察视频，用DVSpec连接数据语义、可视内容和动画等设计，使生成结果具有可编辑、可追溯的表达。本轮核对系统与表示部分。[DataMagic](https://arxiv.org/abs/2606.20388)，[论文全文](https://arxiv.org/html/2606.20388v1)，[代码仓库](https://github.com/HKUSTDial/DataMagic)

**抽出的动作。**把后续检查与修改所需的语义显式化；避免只有叙述，没有可定位的状态。

**迁到学习记录。**同一节点分别记录问题、表示、claim、来源、能力证据与未决事项；七张图由同一份记录链接出来。Research Learning IR是我们的设计比喻，不是DataMagic提出的科研教学系统。

**停止条件。**有schema不等于内容真实；有provenance不等于源头正确。字段维护成本也需要控制。

**最小练法。**把一句“DFG没变”改成可核对的状态：哪个节点/边集合、哪个权重、哪份输入、哪次运行，分别是否相同。

### OP-08｜DataMagic：广泛生成，再作整体选择

**原机制。**其生成与编排过程把候选内容的产生和全局一致性组织联系起来。[DataMagic系统方法](https://arxiv.org/html/2606.20388v1)

**抽出的动作。**发散与整合采用不同约束；候选可以多，最终执行必须考虑整体目标与预算。

**迁到探索。**一个问题可以产生表示、计数、形式化抽象、下游反例等多条候选；回到主线时按关联性、可检验性与成本选少量推进，其余PARK并记录重启条件。

**停止条件。**候选数量不是研究进展；先整合不代表必须由单一权威裁决。决定仍需明确依据。

**最小练法。**为一个对象写三个不同候选，并给出只追其中一个的理由；不因此同时开三个项目。

## 4. EdgeIM的横向类比：相同骨架与明确边界

本节是概念比较，不主张EdgeIM作者实际受这些领域启发。这里没有把每个领域扩成综述，也没有宣称已核完该领域经典论文。

| 类比对象 | 共享的结构 | 不能照搬的部分 | 能产生的新问题 |
| --- | --- | --- | --- |
| 测试集约简 | 每个实例覆盖一组要求；保留较小见证集 | branch覆盖不等于故障检测能力；覆盖标准本身要审计 | 保住结构覆盖后，哪些下游错误仍可能漏掉？ |
| Set cover | trace对应子集，目标涉及覆盖一个特征全集 | EdgeIM按既定顺序单遍保留新特征，不是标准最小set cover求解；也未因此得到其近似保证 | 改变输入顺序会怎样改变样本规模与构成？ |
| Maximum coverage | 在候选实例与覆盖量之间作选择 | 固定预算下最大化覆盖与“不限预算保完整覆盖”是不同问题 | 加K后，哪条原有保证首先失效？ |
| Streaming summary | 用状态摘要替代全部历史实例 | 单遍不等于有界内存；特征集合可继续增长；乱序、窗口和删除改变更新问题 | 精确counter、近似sketch、见证集合分别需要什么资源？ |
| Coreset | 压缩数据，以服务明确的目标或查询族 | 通常需要相对某个目标的误差保证；仅保边存在性不足以自动叫coreset | 下游查询族是什么，允许什么误差？ |
| 统计充分性 | 相对明确推断任务讨论保留信息 | 充分统计量是相对统计模型与参数定义的；不能与“算法够用的摘要”混称 | “足够”究竟是算法输入可替代，还是统计推断意义？ |
| 形式化抽象 | 丢弃具体细节，保留关心性质所需的信息 | soundness、完备性及模型—实现联系需要具体证明；不是任何压缩都保性质 | 对哪个property有保持关系，反例能否回到具体系统？ |
| 图稀疏化 | 缩小对象，同时保某类图查询/性质 | 删trace且保边支持并非删图边的sparsifier；cut、谱、距离等保证不同 | 论文的“无损”精确指向哪一种图性质？ |
| Parser与递归分解 | 识别外层结构，再处理子对象，最后组合 | 解析已有语法与从行为数据推断结构不同；IM还涉及cut判据与回退策略 | 当前分解由什么证据支持，分解失败怎么办？ |

### 一个可独立核对的小例子：幂等集合与非幂等计数

构造两份日志：D₁只有一条〈A,B,C〉；D₂有十条相同的〈A,B,C〉。只检查新起点、新终点、新直接跟随关系的过滤器，在完整扫描且没有额外规则时，都只需保留第一次出现的trace。

两份保留结果相同，原始边计数却分别是1与10。这已经足以反驳“从保留trace能恢复原始次数”的泛化说法。它没有证明任何指定miner一定改变输出；后一命题必须继续检查消费方。

这个例子是本稿构造的机制演示，不替代既有练习、个人作答或PASS证据。

### DES、系统辨识、验证与控制：共享模型，任务方向不同

| 任务 | 已有输入 | 要得到什么 | 迁移前必须补的连接 |
| --- | --- | --- | --- |
| Process discovery | 观测日志 | 描述行为的过程模型 | 观测覆盖、case定义、事件与关系语义 |
| System identification | 输入/输出或状态观测等 | 满足给定建模目标的系统模型 | 可识别性、激励/观测条件、模型误差 |
| Formal verification | 模型与性质 | 性质是否成立及相应证据 | 抽象假设与模型对实现的代表性 |
| Runtime verification | 执行观测与规范 | 当前轨迹是否满足可监控性质 | 丢失/延迟事件、可见信息与UNKNOWN语义 |
| Supervisory control / synthesis | 系统模型与规范 | 满足条件的行为限制或控制策略 | 可控/可观测事件、可实现性等条件 |

控制论式闭环可以启发提问，但EdgeIM的模型发现本身没有因此变成控制器合成。Petri网能表达并发与同步，也不表示从任意有限日志挖出的网都充分代表真实系统。

## 5. 已找到的Agent实例：按输入、表示与用途整理

### 5.1 运行痕迹 → 依赖/程序 → 编译

**A01｜TraceCompiler：从痕迹恢复生产者—消费者关系。**

工作从Agent轨迹构建依赖并编译工作流。其hard dependency规则要求消费者参数中的值能够唯一追溯到生产者输出；不确定关系保留为suspected，而不是强制设为顺序依赖。论文比较了直接相邻、频率阈值DFR等基线。[TraceCompiler](https://arxiv.org/abs/2608.02680)，[方法与实验全文](https://arxiv.org/html/2608.02680v1)

可借：先界定哪种证据才足以建立依赖，再让依赖约束编译。边界：这些结果来自给定数据与依赖判定协议；值追溯不是一般因果识别的证明，不能推出“所有DFG都无用”。论文的部分评估还存在与提取规则相近的参考构造，不能把自洽检查当完全独立ground truth。端到端经济性还要计算离线挖掘、编译、验证与失败回退成本。本轮已看方法及相关实验段落，未复现。

**A02｜AWO：把重复工具调用编成meta-tools。**

微软的 Optimizing Agentic Workflows using Meta-tools 从工作流执行中识别可复用模式，用meta-tools减少重复的中间决策与调用。[微软研究页面](https://www.microsoft.com/en-us/research/publication/optimizing-agentic-workflows-using-meta-tools/)

可借：Repeated reasoning → callable capability。边界：高频不等于可安全固化；仍要处理输入条件、失败、环境变化及回退。我们关心的不是少几次调用本身，而是包含成功率与构建成本的整体收益。本轮核对官方摘要，不复述旧讨论中未重新核验的百分比。

### 5.2 自然语言或代码 → 显式IR → 分析

**A03｜Artic：把隐藏的数据依赖写成artifact约束。**

Artic围绕artifact驱动的表示编译自然语言workflow，使读写关系、约束与控制转移更明确，并检查生成结果与源流程的一致性。[Artifact-Driven Compilation for Reliable Agent Execution](https://arxiv.org/html/2608.21341v1)

可借：隐含语义 → 显式IR → 可检查的局部要求。它与DVSpec共享“重要语义应该可定位”的动作，但输入是流程描述，不是从运行痕迹挖掘。编译后可优化，不自动等于忠实保留源意图；局部检查与scenario dry-run也不自动构成全面等价证明。本轮核对方法描述。

**A04｜Agentproof：显式工作流图带来静态分析。**

Agentproof从多种Agent框架提取统一抽象图，检查结构问题，并把时序安全策略转成DFA，通过工作流图与DFA的乘积进行分析，也涉及运行轨迹检查。[Static Verification of Agent Workflow Graphs](https://arxiv.org/html/2603.20356v1)

可借：Make structure explicit → new analysis becomes possible。边界：图抽取是否覆盖动态分支、工具内部行为与框架语义，会限定验证结论。应分别审“抽图正确”“策略表达正确”“检查算法正确”，不能只看到model checking就宣称整个系统安全。本轮核对论文方法概述。

**A05｜Lean4Agent / LeanEvolve：形式化工作流与轨迹反馈推动修改。**

它以Lean表达workflow及其执行轨迹，检查相关语义一致性，并利用失败信息辅助定位、改进工作流。[Lean4Agent](https://arxiv.org/abs/2606.06523)，[论文全文](https://arxiv.org/html/2606.06523v1)，[代码](https://github.com/RickySkywalker/Lean4Agent)

可借：formal object → evidence → diagnosis → repair。边界：性质、假设与被编码语义决定保证范围；自动改出一个通过检查的workflow，不等于修好了所有现实失败。本轮核对摘要与方法入口，未运行Lean或仓库。

### 5.3 协议与分布式执行 → 组合检查 / 可见性 / 回放

**A06｜AgentRFC：规范到形式检查，再接真实SDK。**

该工作将协议要求组织为可检查的表示与TLA+性质，并用一致性测试把分析接回实现。[Security Design Principles and Conformance Testing for Agent Protocols](https://arxiv.org/abs/2603.23801)

可借：明确区分规范要求、实现行为与额外加固目标，形成可回到实现的证据。边界：规范没有要求的行为不能自动叫“违反规范”；形式模型也需要检查是否忠于原协议。本轮核对论文摘要和框架描述。

**A07｜AgentThread：组合以后才暴露的问题。**

Formal Security Analysis of Agent Protocol Composition中的AgentThread研究协议组合，使用形式检查与可执行反例/SDK回放连接模型和实际实现。[AgentThread论文](https://arxiv.org/abs/2606.28690)

可借：分别成立的局部性质，不必对任意组合继续成立。它可与CrossEdgeIM的顶层组合并排，但二者验证目标不同；“局部PN合并”与“协议安全漏洞”不是同一结果。本轮核对摘要；未复跑反例或独立确认所有报告问题。

**A08｜Causal Past Logic：全局时间先后不等于当时可知。**

CPL面向分布式Agent工作流，以因果过去、消息关系及vector clocks等处理执行中的可见信息，并用逻辑guard参与运行时控制。[Causal Past Logic for Runtime Verification of Distributed LLM Agent Workflows](https://arxiv.org/abs/2605.20923)，[全文](https://arxiv.org/html/2605.20923v1)

可借：表示必须匹配判断发生时的信息边界。边界：消息因果顺序、应用数据依赖和现实世界的因果关系仍是不同概念；逻辑监控结果只对给定事件与语义成立。本轮核对摘要与方法描述。

**A09｜可验证Agent协商：规则、消息与实际遵守分开。**

Do LLM Agents Negotiate Rationally?研究A2A/MCP交互中的机制约束与可验证行为。[论文入口](https://arxiv.org/abs/2608.14613)

可借：把“希望Agent合理行动”拆成可表达的规则、可观察消息与具体检查。边界：机制设计中的理论性质不意味着LLM实现一定遵守；消息修复也不能直接替代对整个协商行为的评价。本轮核对摘要级来源，详细实验和版本日期留待专读。

**A10｜分层Runtime Assurance：集体行为成为检查对象。**

Mission-Level Runtime Assurance for LLM-Assisted ISR Swarms over a Verification-Aware Fabric采用多层组合监控与来源追踪，并处理证据不足时的不确定状态。[论文摘要](https://arxiv.org/abs/2607.23532)

可借的通用动作：检查群体层面的性质，而不只汇总单体合规；证据缺失时明确UNKNOWN。边界：论文特定场景与模拟评估不能自动外推到任意多Agent系统。本册只取组合验证方法，不展开其应用部署细节。本轮核对摘要。

### 5.4 在线学习模型 → 监控，以及运行反馈 → 重新设计

**A11｜AgentGuard：观察I/O，学习行为模型，再做概率检查。**

Runtime Verification of AI Agents中的AgentGuard把原始I/O转换成形式事件，在线学习MDP行为模型并进行概率性质检查。[AgentGuard论文](https://arxiv.org/abs/2509.23864)，[全文](https://arxiv.org/html/2509.23864v1)

可借：observe → identify → verify。边界：事件抽象是否足够、状态是否满足建模要求、概率估计是否可靠、未见行为如何处理，都会限制结果。学习到模型不等于知道真实完整系统。本轮核对摘要与框架描述。

**A12｜AutoRAS：工作流结构本身可以成为搜索对象。**

AutoRAS以primitive表示Agent系统结构，并把执行反馈用于后续设计。它让sequence、parallel等结构选择进入可操作的设计空间。[AutoRAS: Learning Robust Agentic Systems with Primitive Representations](https://openreview.net/forum?id=7zTV4dvdGB)

可借：design IR → execute → diagnose → redesign。边界：有符号primitive不自动等于形式化正确性保证；仍需看语义与检查机制。OpenReview存在不同标题/投稿版本，本轮只核对公开书目信息与摘要线索，不把旧讨论中的投稿状态当现状或录用结论。

**A13｜从软件工程流程记录生成Agent：反向箭头。**

该工作结合不同过程挖掘表示，从软件工程记录及相关角色知识出发，生成Agent角色/流程规范等设计产物。[Using Process Mining to Generate AI Agents from Software Engineering Process Records](https://arxiv.org/abs/2607.04948)

可借：真实人的工作记录 → 过程结构 → Agent设计。边界：这不是“先运行Agent再挖Agent协议”；已有角色词汇和设计先验也属于输入，不能讲成完全无先验的自主发现。本轮核对摘要与工作说明。

### 5.6 这些工作真正可以怎样并排

| 维度 | 应记录的具体问题 |
| --- | --- |
| 起点 | 原始trace、带provenance的trace、自然语言规范、源码，还是已有形式模型？ |
| 关系 | 直接跟随、控制依赖、值来源、消息因果、权限、资源，还是概率转移？ |
| 目标 | 描述、预测、发现、压缩、编译、诊断、验证、监控，还是修复？ |
| 保证对象 | 抽取图、形式模型、被测实现、特定数据集，还是闭环系统？ |
| 证据 | 定理、已知真值的实验、标注、SDK回放、模拟，还是案例展示？ |
| 成本 | 离线构建、观测/标注、在线检查、重训练、回退与维护成本是否计入？ |

同一矩阵可以帮助界定研究空白，但不能因为没有一篇覆盖全矩阵就推出“完整大闭环值得做”。可能有些组合不必要、不可识别或成本过高。先确定一个具体用途，再比较已有工作的覆盖与不足。

### 6.1 一个共同观测、不同依赖的构造

两个确定性toy workflow都记录同一活动序列：A → B → C。

| 动作 | Workflow X | Workflow Y |
| --- | --- | --- |
| A | 产生本次运行的新artifact x | 产生本次运行的新artifact x |
| B | 做一个与x无关的动作 | 做同一个无关动作 |
| C | 读取x，输出x+1 | 读取预先存在的y，输出y+1 |

只记录活动标签时，两者的DFG相同；但X有A→C的数据依赖，Y没有。这个构造说明的是：**在这个观测接口下，该依赖不可被唯一识别。**它不是说所有日志、所有DFG增强方式或所有任务都必然不够。

如果我们有可靠的读写对象记录，就可以区分两者。在这个已知toy语义里，保持其他输入不变而修改x，X的C输出应随之变化，Y的C输出应不变。这给出一个可执行检查的预测。迁到真实Agent时，仍须排除缓存、隐藏状态、随机性、同时改变的输入和日志遗漏等解释。

还可以交换真正独立的动作，检查目标表示是否保留同样的有效依赖。预期不变的是指定的依赖语义，不是原始DFG的每条边必须不变。

### 6.2 从小构造到研究问题，中间还缺什么

小构造已经说明“某种信息会丢”，却没有说明这在实际任务里常见、影响足够大，或新表示值得成本。要进入研究队列，应继续限定：哪一类Agent任务、哪一个下游用途、哪些已有表示、什么数据和预算，以及什么结果会让我们放弃。

“成功与失败trace的拓扑可能不同”仍是候选观察问题，不是必然预测；若差异来自任务难度或trace长度混杂，也不能解释为依赖结构造成失败。流程合规与现实安全的连接同样需要独立论证。

## 7. 如何继续检索、保存证据与更新想法

### 7.1 搜动作，不只搜领域名

| 动作族 | 可用的检索表达 |
| --- | --- |
| 痕迹到流程/程序 | workflow induction from traces；trajectory compilation；program synthesis from traces |
| 痕迹到依赖 | def-use mining；artifact provenance；dataflow inference；causal dependency discovery |
| 规范到可检查表示 | workflow compilation；protocol IR；automata extraction；formal workflow semantics |
| 结构到保障 | static verification；runtime verification；conformance checking；compositional verification |
| 痕迹到可复用能力 | meta-tool compilation；skill induction；procedure extraction；workflow optimization |
| 失败到修复 | failure localization；trace attribution；counterexample replay；workflow/protocol repair |

检索式只是入口，搜索结果必须回到“输入—关系—用途—保证—证据”矩阵。其他社区可能提供直接prior art，也可能只共享一个动作。查不到同名论文，不能据此宣布新颖性。

### 7.2 状态与出处分开

一条候选可因成本高而PARK，但其机制可能已被证实；也可因价值高而PROMOTE，但证据仍是假说。调度不是真假判断。

每次真正推进，只更新必要信息：来源与版本；核对到摘要、方法、实验还是代码；自己的判断；新证据；旧判断被保留、收缩还是推翻；下一步或重启条件。无需给每篇论文另做全套表格。
