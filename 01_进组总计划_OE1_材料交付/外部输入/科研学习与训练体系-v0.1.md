## 1. 总目标与使用边界

以真实问题为主阵地，从零基础逐步获得研究对象的独立掌握；在实践、比较、反馈和复测中，形成可迁移的研究动作、问题判断与研究身份。

近期沿用原约定：九月底能够“不虚地联系鲁老师”，形成“基础 + 自实现 + 小实验 + 脱稿讲清”的窄而真实闭环。完整 EdgeIM 复现、全部基础补齐或进组结果不构成新增硬门槛。

主干仍按 BRIEF 与 Amendment 的 0 → 1 → 5a → 2 → 3 → 5 → 6 → 7 推进。本次整理不重排站序、不重开旧实验、不判定练习完成状态。你本轮补回的讨论恢复的是体系内容，里面“当前已掌握”“下一站”等旧快照不能直接当今日进度。

本稿包含三种内容：既有训练约定、补回的讨论方案、本次为解决冲突而提出的修订建议。它们不具有同样的执行地位；新增训练只在需要时接入现有任务，不自动变成每日必做清单。

## 2. 整体结构：七张图、操作符库、两个贯穿原则

七张图是同一批任务与证据的不同视图，不是七本需要分别填写的笔记。

| 视图 | 核心问题 | 记录什么 |
| --- | --- | --- |
| Knowledge Map · 知识图谱 | 知道什么，缺什么前置？ | 概念、定义、依赖、当前路径、掌握证据 |
| Method Landscape · 方法地图 | 同一问题还可以怎样解决？ | 目标、表示、假设、保留与丢失、预算、复杂度、失败模式 |
| Idea Genealogy · 思想谱系 | 方法从哪里来，解决了哪一个旧瓶颈？ | 文献支持的继承关系，以及另列的机制重建 |
| Transfer Map · 迁移图 | 什么研究结构能借，什么不能借？ | 源—目标映射、不对应之处、新预测、检查结果 |
| Researcher Competency Map · 能力图谱 | 哪些研究动作已经能独立完成？ | 任务范围、提示量、反例、改条件、陌生情境表现 |
| Research Identity & Fit Map · 身份与适配 | 喜欢哪类认知活动，适合怎样的问题与指导？ | 多次实际选择、投入体验、反馈偏好；保留情境与变化 |
| Research Trajectory Map · 成长轨迹 | 反馈以后，能力怎样改变？ | 初次表现、收到的反馈、修正、延迟复测、迁移、指导撤除 |

**Research Operator Library · 研究操作符库**负责连接这些视图。操作符是可以执行的思考动作，例如“质疑表示”“追踪新瓶颈”“检查验证器”“将怀疑闭合到证据”。一篇论文可以提供多个动作的实例，一个动作也可以有多个论文来源。

两个贯穿原则：

- **Epistemic integrity · 对知识与证据诚实**：原文、代码观察、实验结果、个人推论、类比与 UNKNOWN 分开；负证据可以改变喜欢的结论；明确个人、AI 与合作者贡献。
- **Research economy · 研究资源分配**：优先检查会改变决定的不确定性，考虑时间、算力、注意力、反馈机会与实现成本。它帮助排序，不允许省略支持当前主张所必需的验证。

研究议程形成（agenda setting）贯穿问题选择：从解答给定题目，逐步走向重新界定问题、提出候选问题、判断价值并放弃不合适的问题。

## 3. 四篇论文形成当前训练闭环

这部分恢复本轮提供的明确结构：一篇主干、一篇横向对照、一篇实验方法论、一篇纵向后继。相对深度表示投入方式，不是掌握成绩。

| 论文 | 用途与相对深度 | 打开的时机 | 本次阅读要留下什么 |
| --- | --- | --- | --- |
| EdgeIM | 主干，★★★★★ | 沿原训练包持续推进 | 独立重建 Algorithm 1；说明表示、数据流和状态变化；自实现；核对假设与 claim 边界 |
| sigRank | 横向方法对照，★★★★ | 理解 Stage 1 与 DFG 后，在相应比较窗口打开 | coverage 与 significance 的设计差异；样本量内生与比例预算的区别；公平比较与最终目标 |
| A Ground Truth Approach for Assessing Process Mining Techniques | 实验与证据，★★★★ | 将疑问转成实验设计时 | 已知模型、行为偏差、记录错误、观测日志之间的关系；实验能区分什么解释 |
| CrossEdgeIM | 后继与思想谱系，★★★，先浅后深 | 先登记架构差异；理解 EdgeIM 全链与必要模型知识后再深读 | predecessor → 旧瓶颈 → 架构改动 → 新假设/剩余问题 |

另外三篇在节点合适时实际打开，不无限期搁置，也不要求同时逐页精读。跨论文产出优先复用当前笔记，不能额外改变原练习的 PASS 条件。

横向比较必须分开：方法用什么准则选择样本，以及最终怎样评估发现模型。不能因 sigRank 评估下游质量，就断言它的 ranking 分数等于或最优地优化最终质量。

CrossEdgeIM 正文把 EdgeIM 作为前序相关方法；它的顶层合并局部模型，EdgeIM 则在中央聚合特征后发现模型。CrossEdgeIM 不含鲁法明署名，不能把合作网络的论文都叫“鲁老师自己的成果”。[CrossEdgeIM](https://doi.org/10.1109/MIOT.2025.3625047)，已读 PDF pp.55–60，尤其 §I、§III、§IV-C 与参考文献[8]。

## 4. 单个学习节点：零基础教学与研究动作同步发生

默认教学顺序：

1. 先说要解决什么问题、没有它会怎样。
2. 用一个与正式练习不同的最小例子建立直觉。
3. 再给定义，每个符号说明装的是什么。
4. 亲手数、画、推、切或运行一次。
5. 接回论文：前一阶段给它什么，后一阶段读取什么。
6. 选择当前最自然的一两个研究问题：假设、保证、反例、表示或实验。

每次只打开一个小视窗：当前节点、必要前置、眼前动作、原有验收、下一接口。图谱中的六种生长方向——前置、横向、纵向、跨域、科研能力、研究身份——可以登记，不要求一次全部学习。

旁枝进入当前路径的理由包括：它是必要依赖；它在多个任务中反复出现；它能改变当前研究判断。再结合前置与成本决定是否推进。PARK 必须允许留下重新查看的触发条件。

## 5. 从论文与源码到研究问题：完成证据闭环

工程理解的目标是讲清**数据怎么流、状态怎么变、算法怎样落到代码**。旧讨论将它称为 Navigation-Learning 式 Level 2；这里是理解深度的描述，不是要求复制仓库规模，也不等同于下文的能力分级。

每份主要对象笔记复用两栏：

| 栏目 | 必须回答的问题 |
| --- | --- |
| Evidence audit · 证据核对 | 这句话来自论文哪一处、哪版代码、哪次运行，还是我的推论？我验证的是实现、模型还是抽象？依据最多允许说什么？ |
| Research hooks · 可追问的问题 | 哪个假设脆弱？哪项设计值得比较？有什么失败模式或反例？改条件后哪项保证可能消失？替代方案是什么？ |

发现疑点后，按需要走：原判断 → 规范/原模型 → 代码路径与历史 → 替代解释 → 可区分的预测 → 最小检查 → 结果 → 剩余结论。代码与论文不同，首先记录差异，不能仅凭直觉定性为 bug。

本轮的低仰角权重例子只作为证据闭环模板：先检查公式、单位、manual、源码历史与其他实现，再检查两种模型在相关工况下的权重及最终误差/残差表现。本次没有审阅该仓库或作出其实现有错的判断。

一个合格的收尾可以是“这个疑点已排除”，也可以是“只验证到这一层，下一层仍 UNKNOWN”；不需要把每个疑点变成新项目。

## 7. 迁移判别：把 sense 变成可以判断的候选

保留原讨论的层级，但修正其中过早宣布“已迁移”的表述。

| 层次 | 能说什么 | 尚不能说什么 |
| --- | --- | --- |
| L0 词汇相似 | 名词重合，可以作检索线索 | 有可用机制 |
| L1 现象相似 | 观察到类似现象 | 原因相同 |
| L2 结构对应 | 对象、关系和约束能部分映射 | 问题严格同构 |
| L3 机制重合候选 | 源方法依赖的机制在目标中可能存在 | 已证明可迁移 |
| L4 可操作候选 | 可提出具体表示、诊断、设计或干预 | 该操作必然有效 |
| L5 可检验候选 | 有能区分成立与不成立的检查 | 检查已经支持迁移 |

这里不是必须逐级通过的标准化量表。观察性方法、证明方法也可以有价值，不必强行变成 runtime intervention。已设计实验与已有实验支持要单独记录。

Transfer Card 最小字段：源实例与出处；源机制；目标对象；对应关系；不对应之处；可观测信号；如果成立能改变什么；新预测或证明义务；最小检查；证据状态；下一步。

特别检查：目标结构是否稳定、信号是否能识别它、下游是否真的使用它、检查能否排除替代解释、迁移成本是否已变成另一个大项目。

原讨论的 Transfer Value 乘除式与 verification priority 公式只保留为提问框架，不填伪精确分数。状态 DROP / PARK / PROMOTE 描述资源决定，不能代替对真假与证据的判断。

## 8. 从学习到独立研究：三个相连的循环

**学习循环**：理解 → 亲手操作 → 反馈 → 独立重建 → 延迟复测。原任务的 PASS 检查适用于这里。

**探索循环**：观察 → 类比 → 抽象 → 目标域检查 → 候选问题 → 来源检索 → 反例/最小检查 → 更新或暂存。初期允许模糊，不要求每个灵感立刻有可执行实验。

**研究循环**：界定问题 → 核对已有工作 → 假设与竞争解释 → 设计证据 → 实现/证明/实验 → 解释结果 → 收缩或升级主张 → 下一问题。

研究循环中，负结果、排除解释、识别测量错误、证明不可识别，都可能是进展。不能将“没有正结果”统一记为失败。描述性、形式化与探索性问题也不必机械写成统计 H0/H1。

研究议程的成长：给定问题怎么解 → 这是否是正确的问题 → 它属于哪个更一般的问题族 → 为什么现在值得做 → 什么证据会让我停止。把议程形成接到对象层证据，避免抽象越来越大而实际问题越来越少。

## 9. 能力、潜力、身份与导师适配

导师视角是训练用的观察框架，不是鲁老师本人已公布的 selection function，也不是一次面试可以得出的“科研潜力总分”。

| 观察轴 | 有信息量的表现 |
| --- | --- |
| 学习与理解 | 新概念经过解释后，能重组定义、做新例子，并保留到复测 |
| 分解问题 | 能把“方法有问题吗”分为实现、保证、测量、下游与外推等可检查问题 |
| 抽象与迁移 | 找到机制与保持条件，也能指出类比停止的位置 |
| 严谨与诚信 | 让结论服从证据，明确 UNKNOWN、假设与贡献 |
| 实验与证明 | 提出真正区分解释的检查，清楚证明义务与实验边界 |
| taste 与研究经济 | 说明为什么某个问题值得先查，并根据证据更新排序 |
| 更新能力 | 反馈后重建错误来源，不迎合权威，也不盲目守住旧判断 |
| ownership 与表达 | 独立说明对象、关键决策、证据与局限 |
| 身份、合作与 fit | 在不同任务中发现兴趣与工作方式，提出别人能回答的问题，沟通阻塞与贡献 |

潜力主要看多次任务中的变化轨迹；熟悉题的快慢会受到已有知识、提示量、资源和状态影响，不能直接等同于学习能力。旧讨论的能力“导数”是比喻，不是可计算的人格指标。

身份与适配记录：你是否会自发回到一个问题；更享受证明、造反例、debug、实验、换表示还是追谱系；什么指导频率有帮助；在哪些条件下能持续推进。兴趣会变化，寻求指导或一时焦虑不能直接判为不适合科研。

## 10. 科研学徒制：示范判断，再逐步撤除指导

教学除显性知识，还要示范选择的理由：为什么不做某个实验、为什么一句结果不能写、为什么负证据重要。示范时用不同例子，并保留用户自己完成的环节。

| 阶段 | 指导者提供什么 | 学习者逐步接管什么 |
| --- | --- | --- |
| 1 | 问题、方法与原验收 | 理解、手算、核心实现与重建 |
| 2 | 问题与边界 | 寻找、比较并选择方法 |
| 3 | 问题域 | 提出问题与初步证据方案 |
| 4 | 质疑与反馈 | 定义问题、执行研究、解释结果 |
| 5 | 平等讨论与必要资源 | 用证据反向质疑原问题或指导建议 |

这是按能力与任务调节的支架，不是一次升级后再也不能求助。反馈可以来自导师、同伴、论文、可执行检查与 AI；任何反馈都需要检查依据，不把反对意见自动当真理。

旧讨论的 75 分钟面试保留为可选练习脚本：项目说明10分钟、假设深挖10分钟、陌生问题15分钟、改条件10分钟、问题排序10分钟、最小证据方案10分钟、双向fit10分钟。它不能代替连续的小项目观察。训练者不得伪造实验结果来“故意让你答错”；可以使用明确标注的假设情境或真实反例。

固定练法按当前缺口选取：论文机制重建、反例、claim审计、先预测再执行、失败假说记录、冷启动重建。无需每周每项全做。

## 11. 记录模型：避免把调度、掌握和证据混在一起

这是本次明确修订建议，兼容旧标签但分轴保存：

| 轴 | 示例 | 注意 |
| --- | --- | --- |
| 调度状态 | SEEN / OPEN / PARKED / DONE | 当前是否推进，不说明掌握深度 |
| 能力表现 | 能解释、能手算、能改条件、能找反例、能迁移、能提出并检查问题 | 可保留旧 L0–L6 简写，但这些能力不总是严格线性 |
| 证据状态 | 原讨论线索 / 一手核对 / 个人已验证 / 假说 / 被反驳 / UNKNOWN | 论文结果与个人能力是不同证据 |

旧 OWNED / TRANSFERRED 可以作为能力摘要，但须附范围、提示和证据。PROMISING 不等于 TRANSFERRED；PARKED 的知识也可能已经熟悉。

一份主记录即可链接七图：

> 节点与问题；必要前置；当前调度；对象层笔记；Evidence audit；Research hooks；本次操作符；自己的产出；提示与反馈；证据状态；复测；下一步或重启条件。

只有实际出现新关系时才更新关系；没有新错误就不硬写错误；没有用到的字段可以留空。新方法、论文与案例优先进入索引，不立刻新增任务文件。

## 12. 原有训练约定与最小执行入口

保留事前冻结的 Active Check List；每天至少一次可判错训练，不要求每天 PASS；AI 的后台结果不自动算个人能力。

Hard Evidence Ledger 的掌握证据只收 PASS；BRIEF 允许无PASS且无新错时记录 NO-HARD-OUTPUT，不能误算成能力进展。Mistake Log 只收可迁移认知错误；看懂解析不算关闭。复测不通过标 RE-OPEN，保留历史。

复测按原任务与 Amendment：第0站的 D+2/D+7、第5站的 D+3及已有具体日期，不给所有能力套统一日程。题面、个人作答和参考答案分开；AI 不代写个人 paper note、关键 reasoning、既定独立核心实现或个人裁定。
