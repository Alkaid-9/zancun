## 2. EdgeIM 与鲁侧研究的位置

### 2.1 已核实事实

EdgeIM 是鲁法明署名的边缘过程发现工作，论文记录列出 Xuan Su、Cong Liu、Faming Lu、Long Cheng、Qingtian Zeng、Shouli Zhang。它是一个具体分支，不能代指整个研究版图。[EdgeIM 论文记录](https://run.unl.pt/entities/publication/91b982e7-dc5e-4ead-99d8-8ffa5236e043)

学院公开代表成果同时覆盖业务流程建模／验证／挖掘，以及 Petri 网展开、死锁、数据竞争、UAF 等。因而“过程挖掘不是他的主线”过强；“EdgeIM 的边缘与采样问题不必成为我们的长期研究主轴”更准确。公开成果无法确定当前内部资源分配或用户将收到的实际任务。[学院官方页面](https://cise.sdust.edu.cn/home/page/details/catId/85/id/209.html)

### 2.2 当前路线判断：属于推断与建议

依据近期进组目标、长期形式化与可信 AI 兴趣，以及已有学习资产，建议优先短探：

**程序运行行为 → 并发模型 → 性质分析 → 错误预测与重演。**

对象／交互一致性保留为有真实积累的竞争入口。前者有较连续的鲁侧程序分析成果；后者与已有行为表示讨论连接更直接。哪条更适合个人研究，仍取决于原文理解、可用材料、前置成本、实际问题和导师反馈。

这不是把“更硬”“更热门”“更新”当作选题依据，也不预设必须马上接 Agent。

## 4. 两个入口怎么比较

| 维度 | P：并发程序／死锁与重演 | O：对象／交互一致性 |
| --- | --- | --- |
| 核心未知 | 模型报告的错误是否能在合法执行中发生？ | 次序正确时，对象／依赖是否仍然配错？ |
| 关键对象 | 程序、线程、锁、控制流、调度、状态 | 事件、对象、版本、关系、参考模型／规范 |
| 可迁移能力 | 执行语义、抽象、可达性、近似、反例与重演 | 身份与依赖语义、规范、一致性、定位、约束求解 |
| 初步负担 | 先学最小线程／锁语义；不能一开始就默认搭 LLVM | 先理解实例与模型关系；不能停留于设计字段 |
| 原文下一动作 | 选一个误报实例，追旧表示、新表示与可实现证据 | 选一个身份／同步实例，追 replay 或 alignment 的信息需要 |
| 研究推进依据 | 一个符合假设且有价值的剩余问题 | 一个现有办法尚不能妥善处理的明确任务 |

知识图谱新增节点：挂在“行为模型 → 分析／验证”接口下，区分“已观察执行的检查”“其他可能执行的预测”“模型上的性质证明”“真实系统保证”。连接抽象、规范来源、观察覆盖与重演。模型发现本身不自动提供安全规范；模型上没有错误也不自动证明真实程序无错。

## 5. 入口 P 的第一次尝试

**这是教学构造，不是上述任一论文的原例，不是新研究结果。**

暂定语义：两个线程，三个普通互斥锁 G、L1、L2，开始都空闲；获取已被另一线程持有的锁会阻塞；释放只能释放自己持有的锁。无异常、取消、超时、递归锁；只考虑显式给出的操作。

程序 P0：

```text
线程 T1：lock(L1); lock(L2); unlock(L2); unlock(L1)
线程 T2：lock(L2); lock(L1); unlock(L1); unlock(L2)
```

程序 P1：在每个线程整段外面增加同一个 G：

```text
线程 T1：lock(G); lock(L1); lock(L2); unlock(L2); unlock(L1); unlock(G)
线程 T2：lock(G); lock(L2); lock(L1); unlock(L1); unlock(L2); unlock(G)
```

逐步试，不一次回答所有问题：

1. P0 能不能正常结束？写一个完整调度。
2. P0 有没有另一种调度导致死锁？逐步记录每个锁属于谁、线程正在等什么。
3. P1 中还能不能实现同样的死锁？指出阻断或允许该执行的具体规则。
4. 如果一个教学用粗摘要只记录 L1、L2 之间的嵌套获取方向，它能区分这两种程序吗？这个摘要明确投影掉 G，不能冒称它是论文真实算法，更不能借此证明某个工具有误报。
5. 你现在最想追的是哪一步：调度、模型表示、误报、还是如何自动检查？

留下 `步骤｜线程操作｜锁拥有者｜等待对象` 表。没见过 lock、线程或死锁，就从第一条语句解释，不要求预先学完操作系统。

试后回原文：优先取 2021 锁增广分段图或 2026 死锁论文中的一个失败实例，登记图号／段落与精确假设。手推后才比较作者方法。锁与 fork 的耦合、锁获取／释放信息等已被相关工作处理，不能把复述这些改动算作自己的新意。

## 6. 入口 O 的第一次尝试

**这是教学构造，不是专利或论文原例，不是已验证创新。**

任务 T 有两个不可变版本的方案 V1、V2。规范先独立规定：执行某个版本前，必须已有针对同一任务、同一版本的批准。本例无撤销、批准过期或隐藏批准事件。

执行 O0：

```text
create(T,V1) → approve(T,V1) → execute(T,V1)
```

执行 O1：

```text
create(T,V1) → approve(T,V1) → create(T,V2) → execute(T,V2)
```

逐步试：

1. O0、O1 各自满足规范吗？依据是哪一条事件与哪一条规则？
2. “执行前出现过批准”这条只检查先后的规则够不够？它具体忽略了什么？
3. 写一个最朴素的判断办法：它需要记住哪些信息？先不用 Petri 网或 SMT。
4. 任务 ID 与版本 ID 分别有什么作用？不要直接回答“字段越多越好”。
5. 回到真实论文：对象身份／依赖已经能处理这个例子吗？如果能，记录“已被解决”，再追真正剩余的问题。

记录 `事件｜关联对象｜规范所需关系｜判定依据`。O0/O1 的完整动作序列并不相同，不能声称它们具有相同 DFG；这里首先比较的是弱顺序规则与精确绑定规则。

试后回原文：选择鲁侧专利的一个多对象执行例子，再定向查看 Object-Centric Conformance Alignments with Synchronization 中身份或同步如何进入 formalism。不能因为从日志发现一个模型，就把该模型当作应当遵守的规范。

## 7. 从尝试回到自己的研究

以上两例只帮助进入问题。第二条线的完成目标仍然是自己的技术成果。

推进顺序可往返：

1. 原文失败实例：谁需要解决这个问题，旧方法错在哪里？
2. 方法比较：现有表示、假设与算法已经解决到哪里？
3. 形成自己的问题：在哪个具体条件下，仍存在有价值的缺口？
4. 最小证据：手工构造、证明或实现，区分至少两种解释。
5. 自己的产物：有限方法、检查器、摘要方案或实验构造；说明新增设计与 baseline。
6. 验证与定位：适用边界、代价、反例与最接近前人；结果不支持时调整问题。

不以发表年新、图更复杂、加一个字段、换成 Agent 场景或做过比较表作为贡献证据。也不要求先完成全部教材才能开始问题形成。已有工作解决了当前构造，并不等于自主研究任务完成，而是帮助缩小或改变问题。
