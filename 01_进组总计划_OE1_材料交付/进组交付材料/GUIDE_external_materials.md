## 一、这套材料是什么(30 秒)

9 月进组的对外自我介绍套件:**一页纸 Research Statement(主件)+ 一页简历(配套)+ 管线示意图(面谈用)+ OE1 邮件发信包(鲁法明线)**。
历史上有 v1、A/B/C 中英与鲁版；本轮只修鲁侧急用的邮件、鲁版一页纸和简历。通用版、声音版及旧图/渲染输出暂不可外发。
每个最终副本都须重新核对事实、数字、本人贡献和时间；版本间文字一致不等于事实可信。

## 二、当前定稿顺序（不承诺十分钟完成事实核验）

1. 先确定用途：面谈提纲、简历或邮件，不默认有发送任务。
2. 使用 [鲁版一页纸](onepager_lu_variant.md)、[简历](resume_onepage.md) 或 [OE1](OE1_lu_email_v4.md)，逐项填真实身份与本人贡献；可选项目没有证据就删去。
3. 每条数字须能指向版本、测量方法和结果；“愿意公开”与“已验证”是不同的门。个人经历还须本人确认，不凭旧稿继承。
4. 分清论文事实、本人学习、Agent/团队工作和未来计划。课程 QA-PASS、代码存在或截图不自动成为本人实现。
5. 填好后人工逐句核对所有方括号。旧 `fill_placeholders.sh` 未适配本轮新增字段；替换/渲染成功不能授予内容 PASS，本轮未运行它们。
6. 如带 demo，先按 [附件说明](OE1_attachments/README.md) 核清离线/合成性质，在独立目录复跑并保留真实输出，再检查隐私及许可。否则可只带学习笔记。
7. 最后才从确认稿提取正文并排版，去掉内部审计与模板说明；用户确认最终副本。邮件另过 [发送检查单](OE1_send_kit.md)，不自动发送。

## 三、分场景用法

| 场景 | 用什么 | 注意 |
|---|---|---|
| 鲁侧面谈 | 本人填证据后的鲁版提纲与必要简历 | 未完成的训练可以诚实列为待学，不冒称掌握 |
| OE1 邮件 | 当前正文与发送检查单 | 日期重定；BR-1 不是普通请教的前置；附件可不带 |
| demo 展示 | 本人复跑且能解释的限定样例 | 图和 notebook 旧输出不能证明本次运行 |
| 其他受众 | 本轮未修通用版本 | 重新核事实与用途，不能“微调即发” |

## 四、红线速查(外发前 60 秒自查)

1. 不用化名或推算填写学校、教育年份、奖项和本人经历。
2. 论文标题、作者关系和方法从原文核对；同姓导师不混绑，未核文献不进入定稿。
3. 不宣称研究空白、新颖性、导师当前基金或组内偏好，除非有对应证据。
4. 不把代码规模、测试条数、课程完成量包装成本人掌握。
5. 不把离线规则流水线或合成轨迹称为真实 LLM Agent 实验；历史结果不称本轮复跑。
6. 改平台称谓不等于已脱敏；日志公开须另核许可与隐私。
7. 未填字段、旧 PASS 表、审计说明和内部路径不进入最终外发正文。
