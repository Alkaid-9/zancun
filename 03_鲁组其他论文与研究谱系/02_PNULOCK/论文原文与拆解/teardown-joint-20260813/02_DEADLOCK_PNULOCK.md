## 1. 问题

动态死锁检测(相对静态分析假阳性少、效率高,是主流)靠从运行轨迹提取锁授权模式。但现有模型(锁图、锁树、循环锁依赖链、扩展锁图、分段图)有两个信息丢失:

1. **循环体内同一锁获取语句的不同次执行无法区分**——有的执行会死锁、有的不会,模型合并它们就产生假阳性。论文 Program 1:ThreadA 循环两轮嵌套获取 o1、o2,ThreadB 反序获取 o2、o1;第一轮 ThreadA 始终持有 G(门锁)故不可能死锁,第二轮才可能。分段图/扩展锁图把两轮都报成死锁;
2. **跨线程因果依赖不只来自 start/join**——同一锁对象的释放-获取也会造成因果依赖(ThreadA 首轮释放 G 与 ThreadB 获取 G),现有分段图无法建模。

根因:现有模型不能精确建模"获取/释放操作及其依赖关系"。此外,已有重演方法(DeadlockFuzzer 等)本质随机、需多次运行,且调度方案不直观、无法回溯根因。

## 2. 方法(两阶段)

### 2.1 阶段一:轨迹挖掘 → 程序轨迹网 → 伴随网 → 展开检测

**程序运行轨迹(定义 1)**:同步操作序列,
$$op \in SynOperation ::= c{:}fork(u,v) \mid c{:}join(u,v) \mid c{:}stop(u) \mid c{:}acq(u,l) \mid c{:}rel(u,l)$$

**程序轨迹网(定义 3,PN 建模选择的核心)**:扩展 PN
$$\Sigma(\alpha) = (P, T; F, \beta, \gamma, M_0)$$
- $P = P_S \cup P_L$:**状态库所**(每线程控制流状态)+ **锁库所**(每个锁对象一个,初始 1 token);
- $T = T_F \cup T_J \cup T_L \cup T_T$:fork/join/锁操作/stop 四类变迁,**$\gamma$ 是变迁到轨迹操作的一一映射——同一语句的每次执行都是独立变迁**(直接解决问题 1);
- $F = F_S \cup F_L \cup F_F \cup F_J$:线程内控制流弧 + 锁获取/释放弧 + fork 到子线程初始状态弧 + 终止状态到 join 弧(锁弧天然编码了问题 2 的释放-获取因果);
- Table III 给出五种操作的标准网片段;算法 1 逐操作扫描轨迹建网,时间复杂度 $O(\zeta^2 + \zeta \cdot |Locks(\alpha)|)$($\zeta$ = 轨迹操作数)。

**性质**:轨迹网 1-safe(状态位与锁位都是 0/1);**定理 1**:轨迹网的每个可发射变迁序列 $\sigma$ 对应潜在程序运行轨迹 $\gamma(\sigma)$(挖掘算法只添加确实存在的因果,冲突与并发结构使网蕴含比原轨迹更多的潜在交错——这是"从一条不死锁的轨迹检出死锁"的原理);但轨迹只捕获部分同步原语,$\gamma(\sigma)$ **不必然可执行**(假阳性来源,交给阶段二)。

**合法/非法死标记(定义 4)**:死标记 M 合法 ⟺ 非 join 线程的终止库所与全部锁库所各 1 token、其余为空(正常终止);否则非法(潜在死锁)。**定理 2**:$\sigma$ 到达非法死标记 ⟹ 程序按 $\gamma(\sigma)$ 运行可能死锁。

**死锁伴随轨迹网(定义 5)**:加一个 $recover$ 变迁,${}^{\bullet}recover = P_{T\_legal} \cup P_L$,$recover^{\bullet} = \{p_0\} \cup P_L$——合法死标记被"复位"回初始态、不再是死标记,非法死标记保持死。**定理 3**:伴随网的死标记(且 $\sigma$ 不含 recover)= 潜在程序死锁。**这一步把"区分两类死标记"的语义问题转化成了纯粹的 PN 死标记检测问题**,是全文最干净的构造。

**展开检测(§IV-B)**:采用 McMillan/ERV 完全有限前缀(complete finite prefix)。引用两条已证结论:有界 PN 有可达死标记 ⟺ 其展开有;展开有死标记 ⟺ **存在与所有 cut-off 事件都冲突的配置**(定义 6:deadlock-adjoint configuration,对每个 cut-off 事件 e 都存在 $e' \in C$ 使 $e'\#e$)。示例:$C_1 = \{e_1,\ldots,e_8, e_{26}\text{–}e_{29}, e_{38}\}$ 导出死标记 $\{p_1, p_{12}, p_{19}\}$ = Program 1 的真死锁(A 持 o1 等 o2、B 持 o2 等 o1、主线程等 join)。

### 2.2 阶段二:配置张成子网 → 锁调度器 → 确定性重演

**配置关联锁调度器(算法 2)**:取配置 C 的张成子网(C 中事件 + 其输入输出条件;配置无冲突故子网无冲突),从每个锁库所的初始条件出发沿子网顺序遍历,依次记录获取该锁的线程,得到**每个锁的授权线程序列** $\delta(o)$。复杂度 $O(|P_L| + |P_L|^2 \cdot |C|)$。示例:$\delta(G) = A \to B \to A$、$\delta(o1) = A \to A$、$\delta(o2) = A \to B$。**张成子网本身就是死锁形成过程的偏序图示,可直接用于根因回溯**——这是"可解释重演"卖点的实体。

**调度重演(算法 3,基于 CalFuzzer 的 lockBefore/lockAfter/unlockAfter 探针)**:每次 acq(threadX, o) 前查 $\delta(o)$ 首元素:
- 非 threadX → `LockSupport.park` 挂起并入 o 的等待集;
- 是 threadX → 放行,删首元素,unpark 该锁等待集全部线程;
- $\delta(o)$ 空 → 不干预;每次获取后检查配置张成锁图是否成环(CycleDetected)。

终态三分判定:全部 $\delta$ 清空 + 成环 → **真死锁**;全部清空 + 正常终止 → **假死锁**;其余 → **未知**(如 Program 1 取消注释 park/unpark 后,ThreadA 二轮获取 G 时被调度器挂起、三线程全等待,重演失败,正确地拒绝确认这个假阳性)。复杂度 $O(|C|^2 + |P_L| \cdot |C|)$。

**跨运行对象映射(附录 A)**:线程/锁地址跨运行会变。假设两次运行输入相同且都正常终止,则主线程有固定标识 → 每线程 fork 出的子线程顺序一致 → 递归建立线程映射;每线程申请锁的顺序一致 → 锁映射。

## 3. 实验

原型系统:CalFuzzer 采轨迹 → 算法 1 建网 → 展开检测 → 算法 2 导调度器 → 算法 3 重演。对比 iGoodlock(CalFuzzer 内置,循环锁依赖链 + DeadlockFuzzer 随机重演)。基准:CalFuzzer 开源例程 Demo2、Test1a/1b/2a/3/4/6/7/8 + Program 1。机器:Xeon Platinum 8163,2GB 内存,Ubuntu。

结果(Table VII [PDF p.24],08-24 R1-f 补锚并经原 PDF vision 直证):
- **假阳性**:Demo2 与 Program 1 上 iGoodlock 各报 2 个潜在死锁(含 1 假),PNULock 各报 1 个、零假阳性;其余程序两者持平;
- **重演效率**:PNULock 确定性调度一次成功(0.123–0.522 s);iGoodlock/DeadlockFuzzer 随机重演,Test1a/1b 需 3+ 次(0.469–2.441 s);
- **检测开销**:PNULock 更慢(0.256–0.927 s vs 0.123–0.161 s)〔[PDF p.24 Table VII]〕——轨迹网信息更多 + 展开本身受状态爆炸影响,作者明说这是"用时间换精度"。

## 4. 局限(论文自认 + 我的补充)

论文自认(结论章,相当坦诚):
- 分支结构多时展开**状态爆炸**;
- 只用**单条轨迹**,多轨迹合并需为 if/else/loop 建不可观测变迁(指向 interpreted PN 辨识的后续工作);
- 只处理**资源死锁**;通信死锁(wait/notify/park/unpark)理论上可建模,但状态空间剧增(引用 RRNA 死锁检测 PSPACE-complete 的结论),明确选择分开研究;
- 无时间信息(指向 time PN 辨识)。

我的补充:
- 基准全部是**教学级小程序**(CalFuzzer 例程),没有真实规模应用(对比:Magiclock 系工作在大型多线程程序上评测),状态爆炸问题在这个基准上根本没被触发;
- 跨运行映射的"输入相同 + fork/锁申请顺序一致"假设,在数据依赖调度的程序上不成立,论文没讨论失败模式;
- 重演"未知"类别的占比没有统计——三分法诚实,但缺少"未知率"数据就无法评估实用性;
- 与同期 SOTA 动态预测式检测(如 sound deadlock prediction 线,PLDI'23)没有对比。

- 扩展 B:统计"未知"重演率,补上实用性评估缺口。

**与 T 课题的关系(T1 直接借力,T3 间接)**
- T1(PN 展开×MAS 自传播割集)的映射:锁库所 → MAS 中的共享资源/通信信道;acq/rel → agent 对资源的占用/释放或消息收发;**非法死标记 → "感染扩散完成"或"系统被劫持"状态;deadlock-adjoint configuration → 攻击传播路径;配置张成子网 → 攻击的偏序因果图**。鲁侧图说 T1 要做"传播割集"——在展开上找切断所有到坏标记配置的最小事件集,正是这套机器的自然延伸;
- "确定性重演"是 T1/T3 的**审稿人可验证硬卖点**(鲁侧图 §3 战术注:主流预测式检测重演靠随机调度,PN 展开天然携带偏序因果):把 $\delta(o)$ 换成"消息投递顺序调度器",就能确定性复现一次多 agent 攻击;
- recover 变迁的构造思想可复用:在 MAS 里"合法终态复位、非法终态保持死"= 把"什么算安全终局"编码进网结构,而不是事后过滤。
