# 科研台搭建审查与融合取舍

日期：2026-09-08。TASK-20260908-002。范围：当前搭建的技术与语义审查，随后形成设计；本轮不开发、部署或迁移资料。

用户要求：“要不你先审一下现在的科研台的搭建，看看怎么融合比较好，然后先设计方案？”

**审查结论：已有地图、检索代码、论文处理工具、学习模板和外部学习应用可以分项复用；尚缺一个统一保存研究与学习记录的独立科研台。推荐在当前仓库新增独立模块，保留资料原位，以普通记录文件为权威、数据库为派生索引，通过适配接入旧工具。**

具体方案：[科研台融合设计 v0.2](../../../../decisions/2026-09-08__research__research-desk-fusion-design.md)。它承接并修订 07 的技术建议，当前为 PROPOSED。

## 2. 已实现的数据流

```text
地图 Markdown ──map_to_yaml.py──> YAML／静态 HTML
                         └────> papers.yaml ──papers_yaml_to_bib.py──> BibTeX

deep.md／部分 marker_output ──tools/kb──> Chroma 论文检索与上下文块
                                             （本轮未运行，当前 solver 缺 chromadb）

训练包 Markdown ──> 七图文字、示例、模板和局部调度
research_growth ──> 方法库、迁移卡、反思

工作台全图 HTML ──/wbmap──> 工作台展示入口
手机包 ──用户手动携带──> 另一账号的学习输入
```

这些流之间尚无统一的 Question／Session／Evidence／Relation 写入和检索链。新科研台的核心增量应落在这一缺口。

## 3. 关键发现

### A1. 07 的五层映射漏了一层，应直接订正

原 [FOUR_PAPER §9](../../../../../learning/training/lu-edgeim-algo1/FOUR_PAPER_TRAINING_LOOP.md#9-五层架构中的位置) 五层是：`WORLD / FIELD → RESEARCH MAPS → ACTIVE TRACKS → EVIDENCE / PRACTICE → ARTIFACTS`。

07 先前将 WORLD 和 FIELD 分成两行，同时没有保留 RESEARCH MAPS 独立层，造成名为“五层融合”却改变原导航的错误。本轮订正 07，并在新设计保留原五层。WORLD/FIELD 中仍可缩放全域与细分领域；七图在 RESEARCH MAPS 中看同一批对象，跨层引用证据。

### A2. W5 可复用，但地图实体还不是研究记录

本轮在内存调用 `build()` 和 `sorted_items()`，未调用写盘函数。得到 40 流派、33 团队、170 论文记录、5 课题、19 增量行；41 张规范表解析 25、跳过 16。现存 schools／teams／papers／topics 四份 YAML 的 `items` 与当前内存重建结果分别完全相同。

170 个论文 ID 唯一，269 个 `sources` 的文件与行位置全部有效。这只证明 ID 与定位的结构性状况，不证明每项代表独立论文、来源里的主张成立或行号对应全部语义。

当前四类实体全量重建仍与旧生成物一致，也说明旧内容口径不会仅靠再运行生成器就自动修正；应先修订有问题的源文或明确裁定，再生成对应视图。

`data/` 是派生输出，不能保存人工追加的学习结论。源码里的 `derived_by: token-match`、结构包含关系和 `needs_verification` 需要在新界面保留来源性质；未标“待验证”不等于已经人工核实。

旧 v1 待办仍可在盘上复核：`reconciliation/`、`data/cells.yaml`、`radar/WATCHLIST.md` 均未存在。数据中仍并存 `arxiv:2408.00989` 与 `or:Bp2axGAs18`，以及 AgentHarm 的 arXiv／OpenReview 记录；`paper-agentspec-pro2guard` 仍是复合标签。这里确认记录分立／复合现象，未重新核实它们应怎样合并。新系统应保存跨 ID 候选和人工裁定，不按标题直接去重。

### A3. 旧 KB 有实现，但不能直接充当统一检索

[`tools/kb/core.py`](../../../../../tools/kb/core.py) 扫描 `deep.md` 和部分 `marker_output/**/*.md`；默认论文 ID 来自相对目录，向量 chunk 元数据没有精确页／段定位。移动目录会影响身份；普通学习记录、七图和方法库不会因文件存在就自动成为合适的检索对象。

核心 `sync`／`search` 需要初始化 Chroma；本轮用安装元数据确认当前 solver 中没有 `chromadb`。因此旧 PLAN 的“已跑通”属于历史回执，不是本次运行状态。没有为审查安装 Chroma、读取其数据或执行检索。

建议保留旧知识库，后续作为可选语义召回提供者；先解决统一文件身份、定位与关键词搜索。语义相似度不能生成事实关系或能力证明。

### A4. 中文检索需要显式设计

当前 SQLite 为 3.52.0。仅在内存表插入“递归调用返回与科研菌丝网络”，实际结果：

| 查询方式 | “递归” | “菌丝网” |
|---|---:|---:|
| FTS5 `unicode61` 的 MATCH | 0 | 0 |
| FTS5 `trigram` 的 MATCH | 0 | 1 |
| 字面子串查询（实测“递归”） | 1 | 本项未测 |

因此“使用 SQLite FTS”本身不足以承诺中文好搜。新设计规定短中文使用字面子串查询，较长查询可用 trigram 候选检索；保留匹配片段与来源。以上只是分词能力样本，不是检索质量、性能或大语料验收。

### A5. 学习模板的局部规则不能覆盖长期 F／E

[`KNOWLEDGE_MAP.md`](../../../../../learning/training/lu-edgeim-algo1/KNOWLEDGE_MAP.md) 明确要求新节点绑定当前主干、旁枝先登记不追、按门升级；其场景是 EdgeIM 训练。用户后来确认长期 F 连续积累、E 独立观察、R 可做局部试探，这些不能被训练目录的位置消除。

新设计须把“记录存在”“当前是否投入”“正式课程／实验是否满足条件”“本人具体表现”分别存放。旧课程门对其课程有效，导入七图文本不会把每个新问题都 LOCKED。长篇研究模板按实际研究动作调用，日常一次带学继续使用简版记录。

### A6. LearnGraph 值得参考，整套采用会引入额外语义

当前克隆具有 React／FastAPI、来源与文档工作面、图谱提案、证据接口和 SVG／PNG 导出代码，MIT 文件存在。适合参考文档与笔记并看、节点邻域、提案修改、图形导出等动作。

但 [`MasteryService.apply_evidence`](../../../../../../LearnGraph/backend/app/services/mastery.py) 使用质量阈值增加 `mastery_stars`，并配有固定复习间隔；图提案输入也有它自己的节点／关系种类。新写入已由旧 `/evidence` 转向 `/learning/evidence`，并非一个简单统一的可直接调用旧接口。

用户当前需要按作答、提示和复用记录能力，没有采纳星级或自动复习日历。整套 fork 会同时带入账号、模型 provider、沙箱、记忆、调度和数据库迁移。因此建议先做开放文件桥接，相关 UI 作为参考；需要复用代码时按具体模块保留归属并复核依赖，不把整个 LearnGraph 作为科研台权威库。

运行归档的 README 明确只是 08-30 试用保存，原虚拟环境可能保留旧绝对路径。本轮没有解包或恢复运行。

### A7. 现有“桥接”和“PDF 工具”各有窄边界

- [`cards_to_obsidian.sh`](../../../../../tools/scripts/cards_to_obsidian.sh) 当前做 vault／卡片目录探测与使用说明；不是科研记录双向同步器。它记录过 WSL 符号链接与 Windows 使用不兼容的经验，新设计采用真实文件路径和普通导出。
- [`papers_yaml_to_bib.py`](../../../../../tools/scripts/papers_yaml_to_bib.py) 输出 `@misc` 及已有 label／标识信息；它不是完整作者、venue 和出版版本核真的文献管理器。
- [`academic_pdf_reader.py`](../../../../../tools/scripts/academic_pdf_reader.py) 有 Marker 与视觉 API 路径，默认视觉开关不能当纯离线读取；本轮未执行。科研台初版先打开原 PDF、记录页码及已有文本，转换／OCR 按明确动作单独调用。
- Reviva 的[停止交接](../../../../../../docs/superpowers/handoffs/2026-09-04__reviva-trial-stop-handoff.md)未完成实际桌面体验验收；这轮不恢复试用。与 Obsidian／Reviva 的连接优先是开放文件。
- TaskQuay 的[部署记录](../../../../task_logs/2026/09/2026-09-08__setup__taskquay-local-deploy.md)只授权独立练手目录，状态为停止；不把这项旁窗工作视为科研台远程接入或本用户允许上传的证据。

### A8. 单一数据库不是当前最重要的统一点

现有 W5、KB、训练包、方法库和工作台拥有不同的 ID、来源粒度与状态语义。直接汇入一张图或一套数据库会隐藏这些差异。需要先统一的是：对象身份、原件位置、一次观察的范围、关系含义和谁负责修改。

一个来源可被多次学习和多个研究问题引用；一次学习也可同时服务 T/F。世界里的论文／概念与“我在某次会话里做到什么”应连接但分别记录。七图由这组共同记录呈现，不按七图复制七份正文。

## 4. 复用与替换取舍

| 部分 | 建议 | 进入新系统的方式 |
|---|---|---|
| W1–W7、论文、方法库、历史会话 | 保留原位，按需注册 | Source／locator／原件关系；不批量宣称已核实 |
| W5 v0 解析和浏览器 | 复用现有能力 | 旧派生数据读取适配；页面作为旧地图入口 |
| W5 v1 对账设计 | 取用有价值的身份与关系裁定思想 | 先在科研台保存覆盖记录；待 BR-11 实现时明确唯一裁定位置，避免双写 |
| 七图主文件和模板 | 保留，补范围映射 | 来源＋视图定义参考；新个人会话独立保存并回链 |
| 旧 Chroma KB | 暂不设为首版依赖 | 后续语义召回接口；补 source／locator 后才接入 |
| LearnGraph | 参考交互、保留未来桥接 | 不复制能力计分和自动调度为默认制度 |
| 工作台 | 继续负责执行 | 科研问题和执行产物相互链接 |
| 手机包 | 继续使用 | 选择性导出／用户手动返回；原记录与整理分开 |

## 5. 本轮结论与未决项

可以据本轮审查给出具体技术建议：当前 solver 已安装 PyYAML 6.0.3、FastAPI 0.136.1、uvicorn 0.46.0、Jinja2 3.1.6；可用 Python＋普通网页＋SQLite 构建第一版，无需先引入外部学习应用和新向量数据库。包版本存在不等于新应用已运行。

正式数据参数路径、首批来源、端口与页面实现仍在设计稿中作为明确建议。用户本轮要求审查和设计，因此本轮到此完成可审方案，不启动应用、修改原训练门或恢复冻结研究。

本轮没有为所有资产新增 hash 清单、代码护栏或测试。验收采用源码核对、只读／内存重建、定位检查与文档回链。设计生效和开发完成分别判断。
