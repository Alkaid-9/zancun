## 5. 数据合同：最低必需字段

| 对象 | 字段及规则 |
|---|---|
| Asset | id、title、kind、collection_id、locator(root_id+relative_path)、discovered_at、availability；已分配ID不随路径改名变化 |
| SourceRevision | source_id、revision_id、hash(可空且注明未计算)、observed_at、locator、declared_version；日期未知保留unknown |
| Review | asset_id、revision_id、checked_at、checked_scope、evidence_ref；文件时间不能替代核验日期 |
| Coverage | discovered/read/extracted/adapted/used 分列，各自带范围和证据；不要求线性逐级升级 |
| Design | design_id、scope、proposal/adopted/superseded、decision_ref、supersedes；后写稿不自动成为已采纳稿 |
| Continue | id、问题、source_refs、上次停点、next_action、active/parked、resume_condition；无法确认当前课堂状态时并列显示冲突 |
| Guidance | id、source_refs、stage_tags、使用场景、适配状态、原条目引用；来源与场景视图复用同一ID |
| Proposal | id、target_ids、建议操作、依据、pending/accepted/rejected、决定记录；首版支持查阅与普通文件确认，无需画布写回 |

目录首页不堆全部字段。常见卡片显示标题、用途、所在库、整理覆盖、核验范围和来源入口；技术字段在详情展开。仅做确定性的路径/标题索引，AI生成摘要与正式标题、身份、关系区别保存。

同一来源新版本的哈希变化，显示“变更后尚未复核”；旧版本核验仍保留。只有mtime变化时显示“文件时间有变化，内容待比较”；未计算哈希不能声称内容变化。不要全库定时重审。重复扫描应保持ID与记录数量稳定。

## 6. 页面与实现默认值

首页：继续哪里 → 板块入口 → 需要处理的少量事项。科研台建设进度放到“建设与维护”，不混入用户学习进度。

板块：Map、菌丝网络、文献资料、科研指导库、学习与能力、研究议程、协作画布。当前只实现目录、搜索、筛选、详情和来源跳转；未实现交互的工作面保留说明与资产入口。工作台日程、CLI执行、TaskQuay真实委派不在本包实现。

实现建议：Python标准库完成文件盘点与XLSX ZIP/XML读取；本地轻量服务加普通HTML/CSS/JS。可用现有FastAPI/Jinja2，但不为本包引入大型前端、向量数据库或账号体系。中文短词采用明确的子串匹配，首版搜索登记字段及活跃部分文字摘录，UI标明范围；不宣称PDF全库全文搜索。

本地服务使用显式配置的回环地址和空闲端口，不能占用现有8899。来源链接通过asset ID解析允许根路径，以本地只读页面显示文字/原件；提供Windows路径复制。禁止将任意URL路径拼成文件读取地址。展示Markdown、Excel文本、文件名时按不可信内容转义；外部链接不自动加载或访问。

机器配置在app外或忽略文件中记录allowed_roots、content_root、runtime_root、log_root、host、port、scan_excludes；代码仓只含脱敏示例。运行日志不记录资料全文。提供同一配置下 build-current、scan、serve、check-links 等明确命令及完整启动用法，不依赖用户猜工作目录。

## 7. Sol 分工及工作包

Sol是接手实现主窗口的称呼，运行回执填写实际模型和入口；本方案不声称能通过任意CLI调用特定模型。当前AGENTS规定子代理用于只读探索/核验：不写文件、不执行状态变更、不派生；fork_turns=none，不覆盖模型和推理参数。执行和正式写入由Sol主窗口完成。

| 包 | 责任、输入与输出 | 依赖与验收 |
|---|---|---|
| N0 当前入口与契约 | Sol主控将五项决定、根路径和字段落入内容登记与app样例；建立CURRENT骨架 | 完成后导航Markdown可直接读；不得因待审附录卡住既有五项决定 |
| N1 来源盘点 | 只读子任务A核Map/论文/学习，B核成长库/指导库，C核Excel/5份讲义；返回路径与范围证据，主控写registry和导出 | N0后；三个范围独立，可并行。全量位置数可复核，失败/排除列明 |
| N2 活跃整理 | Sol主控落实Excel表/媒体覆盖、pengsida跨层目录、真实继续记录；所有未核主张带状态 | N1后；每表有定位和覆盖；如课堂游标冲突，展示待对账而非造一个游标 |
| N3 本地导航 | Sol主控实现搜索/筛选/来源详情/双入口/版本展示，从同一内容生成CURRENT | N0后可搭框架，最终以N2数据验收；首页到pengsida详情最多两次点击 |
| N4 独立核验 | 只读审查者抽查来源、状态与界面代码；A11浏览器实际走查（截图+通过/失败判定）由非N3实现者的独立执行者完成，主控不得自证浏览器验收通过 | N2/N3后；若另开可执行测试窗，需具有对应写域授权，不套用只读子代理权限；若单会话无法拆分执行者，须在回执中明示"A11由同一执行者自评"这一降级事实，不得隐去 |
| N5 接手交付 | Sol主控保存运行方法、检查回执、缺口、回退及新入口，更新原任务路由 | N4后；能关闭重开，不依赖原聊天；软件与资料整合分别报告 |

并行方式：默认一批三个只读子任务，最多不超过环境7个总实例；这是资源预算建议而非必须满额。派发后按用户规则等待该批终态，主控不重复同范围检索。小文件与奠基性合同主控直接读。任务依赖、编辑、审批和共享更新保持串行；仅主控维护台账。

每个子任务自包含：目的、绝对读取根、明确问题、排除范围、只读动作、返回格式、停止条件。回执首行为complete/partial/blocked；一次终态输出，给file:line、符号、关键原文、未覆盖项。主控沿出处抽查后整合；Agent自述不自动作为事实。

若无子代理能力，Sol主控按A/B/C顺序完成同样的只读盘点，交付标准不变。不得为满足角色名称安装新工具或恢复失败的旧Sol协议。

**（2026-09-10 追加）大批量生成的分段落盘**：工作簿逐表导出、媒体锚点核对、pengsida跨层目录等大批量生成按分段落盘执行：每完成一个可核实单元（一张表／一个来源分区／一批锚点）立即写入registry对应条目，不等全量跑完再一次性落盘。遇上游超时、连接中断或单次调用失败，从最近一次已确认写入点续做，不视为整批失败、不整批重做；中断处在coverage.json标注为待续，不得因中断导致该记录静默消失。

## 9. 停止、修复与回退

源不可读、图片无法定位、旧版本不明：记为局部缺口，继续其他来源。共享写域冲突：停该文件合并，保留候选补丁，继续独立工作。遇到外部账号、付费接口、服务器、全量迁移或真实执行授权：停对应动作，它们不是导航首版的前置。runtime身份不明（effort=UNKNOWN或换路径未重新确认）：停止发起后续批量/无人值守执行，待用户在场确认后继续，不得凭配置文件或旧会话记录推断续跑。

普通实现错误在已授权写域内直接修复。相同诊断无新证据时停止重复预检，报告命令、错误、已尝试方法、缺少输入和可继续的部分；不能把额度花在持续证明“可以开始”。

原件保持只读。可撤回本轮新建应用/内容及原仓中的定向入口；删除派生索引不丢记录，用户新写内容单独备份后才能回滚。不要清理整个工作区或顺手移走旧资料。

首版使用后收集“找不到/过时/归类不合适”的具体对象反馈；按照对当前学习研究的影响排序修复。对知识库分类与提示进行小范围改进，不把全部历史材料重新读一遍作为默认维护。
