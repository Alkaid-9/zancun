## 2. 多层结构的共同底线

### 2.1 四个轴不混用

| 轴 | 表达什么 | 不能替代什么 |
|---|---|---|
| 关系层 | 对象在这一层怎样关联、可以做哪些判断与操作 | 不是界面颜色或单纯筛选标签 |
| 展开深度 | 从方向／问题进入方法、机制、假设、公式、实现及反例 | 不是掌握等级，也不是固定单根树 |
| 观察范围 | 当前聚焦哪类问题、领域、团队或成果 | 不自动新增学科或改变研究方向 |
| 状态与评价 | 来源依据、关系裁定、个人表现、任务执行等分别记录 | 不合并成一个 maturity 或综合分数 |

### 2.2 七组候选关系层

这是已有场景稿的逻辑组织，层数和边界待真实案例验证；不要求七个数据库或服务，也不要求每个对象进入所有层。

| 关系层 | 层内主要内容 | 跨层时需解释的连接 |
|---|---|---|
| L-K 知识与机制 | 定义、条件、前置、组成、推导、机制 | 某知识支持哪一步理解或实现；支持到什么范围 |
| L-E 问题与证据 | 问题、主张、证明、测量、反例、限制 | 哪项依据支持或限制哪句话，而非笼统支持整个节点 |
| L-M 方法与迁移 | 替代、比较、改进、方法对应和迁移边界 | 比较接口、假设与目标是否匹配；类比尚缺什么验证 |
| L-O 人物与组织 | 作者、团队、合作、角色与时期 | 谁在何种角色下参与；不能把所属机构推为成果归属 |
| L-A 成果与应用演化 | 论文、实现、版本、采用、替换、后继 | 具体采用了哪个变体、多少内容、依据来自哪里 |
| L-G 指导与实践 | 研究操作、指导、配方、选用、调整、反馈 | 推荐、选择、实际使用和效果分别是什么事实 |
| L-P 个人学习与研究发展 | 作答、帮助条件、理解变化、能力证据、轨迹 | 本人表现怎样联系知识与实践，但不替代研究证据 |

数学、编程、过程挖掘或形式化知识可在相关层中继续展开自身结构；它们不只是某篇论文的一串前置。具体补哪些内容由已声明范围和实际缺口决定，不自动扩成一份全学科课程表。

### 2.3 跨层结构示意

```text
知识与机制 L-K  <---条件、前置、推导--->  方法与迁移 L-M
      | 指定对象与性质                         | 比较与迁移问题
      +----------------> 问题与证据 L-E <------+
                              ^
                              | 依据、版本与具体采用情况
人物与组织 L-O <---参与角色---> 成果与应用演化 L-A

指导与实践 L-G --实际选用与过程--> 学习／toy 活动
                                       |               |
                                       v               v
                           个人表现与变化 L-P     研究判断 L-E
```

这只是跨层语义示意，不是冻结的数据模型。各层内部仍各自成网；真实活动不必经过每一层。共享实体身份、来源和产物，不意味着不同断言共享真假、不同评价自动互认。

## 3. 三级要求总览

最低与正常不是“证据宽松／证据严格”的区别；来源、归属和能力边界在三档中都不能降低。区别主要是覆盖范围、场景完整性、维护能力与使用规模。

| 建设面 | 最低可用要求：局部闭环 | 正常完整要求：日常可用 | 长期补全方向：跨课题持续成长 |
|---|---|---|---|
| 多层结构 | 在真实局部案例中区分层内关系与跨层连接，不退化成标签图 | 活跃专题所需各层均能参与往返；按需展开不同深度 | 可重叠专题与子网络跨阶段复用，保留多尺度结构 |
| 知识内容 | 核心概念有必要定义、条件、例子和卡点返回路径 | 反复使用的基础形成连贯单元，教学支撑能匹配练习要求 | 在选定研究范围形成可持续深化的基础与理论结构 |
| 对象身份 | 分清概念、方法版本、代码实现、来源断言和本人理解 | 处理同名异义、别名、版本、部分对应与待消歧 | 跨资料／项目的身份对应可追溯，修订不污染历史 |
| 承重关系 | 说清为什么连、适用条件、来源与未知 | 表达条件性推导、比较、采用、使用及不适用边界 | 支持更复杂论证与争议的追溯和复核，不自动串推结论 |
| 来源与证据 | 能回到具体原文位置或本人产物；未知诚实保留 | 来源版本变化、矛盾断言、后续更正与影响范围可追溯 | 多来源、多时点与复杂证据链的长期维护 |
| 本人学习 | 提示与独立表现分开；原作答可引用；不自动 PASS | 教学、反馈、重做、迁移与到期冷测能够连续承接 | 纵向观察能力增长、复发缺口与跨课题迁移 |
| 权重与范围 | 明确近期重点及本次探索边界；不猜百分比 | 重要性、投入、可信程度、掌握程度分别影响相应动作 | 随导师指导、阶段目标和实际证据重调，不重写世界事实 |
| toy 与 idea | 能把一个具体疑问写成最小区分检查及结果分支 | 多个候选可比较；论文机制、知识缺口、基线与取舍连接 | 持续积累问题谱系、失败经验、可复用实验与研究判断 |
| 更正维护 | 一次更正能找到需要复核的直接判断；原记录保留 | 处理合并、撤回、版本替换及跨层影响，不重复录入 | 更大网络中的冲突整理、变更提示和局部重建 |
| 查找与使用 | 关闭再打开仍能找到来源、当前问题和继续点；文件形式可用 | 搜索、比较、局部展开、返回原位置、App／CLI 衔接顺畅 | 按需求评估多模态、协作、服务器和更大规模检索 |
| 自动化 | 人工记录可用；AI 内容保持提案身份 | 对反复发生的操作定向辅助，可拒绝、修改和追溯 | 评价推荐质量与维护收益后再扩大，不默认自动爬取 |

“长期整块”在这里是补全地图，不是近期承诺清单；没有预设上线日期、预算比例或数据库选型。

## 4. 最低可用要求：什么做到后才有资格说能用

### M1. 一个实际局部网络，而非只有层名

选择当前真实学习问题，展示它涉及哪些层、层内关系是什么、跨层如何连接。优先候选是 EX-05 的代码对象／字段转换／机制理解卡点；这是方案候选，不是替用户开始新练习。

能从原问题定位必要概念和代码位置，完成学习动作后回到原问题。未使用的层不造空事实填满；当前范围以外的层保留可扩展边界。

### M2. 重要连接有可解释内容

至少用一个承重连接走通：定义对象和条件、说明为什么连接、引用依据、给出不成立或待核的情况。例如“表示足够”必须针对某个消费者／查询／性质，不能无条件贴在 DFG 节点上。

没有查过、查过但没找到、已有反证分别记录；局部网络没有某条边不等于相关工作不存在。

### M3. 一次学习记录能跨层复用但不升级身份

同一份作答可以被知识解释、反馈记录和研究问题引用，不要求用户复制多份。必须仍能分清提示下成功、独立完成与尚未运行；AI 写的代码不能登记为本人独立实现。

### M4. 一个研究出口能说明区分价值

不要求最低档已经发现新颖成果，但系统应能保存：疑问来源、已有工作边界、待区分的解释、最小检查、不同结果分别改变什么决定。

检查可以是手算、证明、反例、代码追踪或实验；是否实施另按当前授权。理解型 toy 不等待四篇全文 OWNED 才允许开始，研究型 toy 不因一次跑通直接晋升为贡献。

### M5. 能恢复并能改判

关闭再打开后能找回问题、来源与继续点。用一例“反例其实来自代码错误”检查：研究归因需修订，原失败与排错过程保留；相关关系只在实际依据受影响时复核，不自动整片删除。

以上是建议的验收行为，不是本次已经执行或通过的测试。

## 5. 正常完整要求：从单个样板到稳定日常使用

正常档应在最低档有效后补齐以下常用路径，而不是按节点数量升级：

1. **基础成长**：从任务所需片段进入连贯基础；区分现在必需、先理解到接口、以后集中深化。核心定义、例子和推导不只存索引。
2. **四论文联动**：围绕具体问题比较机制、选择目标、评测世界与架构演化；同一 toy 不强制使用全部四篇。
3. **研究论证**：区分假设到定理、机制到结果、指标到目标、观察到解释；匹配各自需要的证据，不把所有关系都画为 supports。
4. **科研操作复用**：指导被推荐、被选择、实际使用及反馈有对应记录；做研究的方法与被研究的方法按用途区分。
5. **多候选取舍**：比较问题价值、已有工作、能力／材料缺口、最小检查成本和指导条件；记录继续、改写、停放或放弃的理由。
6. **来源与修订维护**：概念别名、方法变体、来源矛盾与版本有效期可区分；先后出现不能自动推出历史影响。
7. **使用闭环**：学习台、科研台与工作台分别保留权威；网络引用执行请求与回执，不复制一套任务调度状态。App／CLI 交接明确手机已做什么、电脑仍待验证什么。

正常档建议由三个真实样例验收：当前卡点恢复、跨论文比较、toy 结果引起改判。不同样例承担不同问题，不用一次演示宣布整包教学效果或软件功能全部通过。

## 6. 长期整块还要补什么

| 补全面 | 长期价值 | 何时值得展开 | 现在不承诺什么 |
|---|---|---|---|
| 基础与理论纵深 | 避免只对局部题目熟悉；形成跨论文可用的概念、推导和方法基础 | 同类前置反复出现，或确实限制独立研究 | 不默认增加全学科课程或小模型训练 |
| 问题／方法谱系 | 看清问题怎样演化、瓶颈怎样迁移、哪些候选已被解决 | 需要选题、比较路线或解释研究位置 | 不把时间顺序、共同术语当继承关系 |
| 团队／成果／应用网络 | 理解方法由谁发展、怎样实现、在何种条件下采用 | 实际指导、课题或中长期路线需要 | 不从 OAI 目标推出近期工业项目清单 |
| 论证与证据积累 | 留下可复核的证明片段、反例、实验合同、测量限制和争议 | 同类判断开始跨多个项目复用 | 不让自动连接承担未经验证的推理 |
| 研究操作与实践经验 | 把失败、诊断、对照设计、问题重述积累成可复用经验 | 同类方法已有多个真实使用案例 | 不用格言或成功次数代替方法有效性 |
| 个人纵向成长 | 观察保留、迁移、反复失误与研究判断变化 | 有持续作答、复测和实际贡献记录 | 不把收藏、推荐、提示成功转换为能力等级 |
| 探索与推荐 | 发现有解释的新连接，同时保留自主深挖和自由捕获 | 人工使用暴露出稳定的检索或发现需求 | 不先造爬虫、推荐平台或自动研究代理 |
| 规模与维护 | 更大资料量下仍能查找、修订、恢复和协作 | 真实内容与使用频率超过现有方式承载能力 | 不现在指定图数据库、3D、服务拆分或部署 |

这些工作面可以相互交叉，不是新增八层。重点仍是选定研究范围中的多层知识与实践结构，不能借“长期完整”把所有外部主题纳入默认任务。

## 7. 六项改进如何进入三级要求

| 本轮已讨论的改进 | 最低档落点 | 正常／长期深化 |
|---|---|---|
| 分清层、深度、范围与状态 | 用实际案例标明四个轴 | 在复杂场景检验能否保持不同语义 |
| 知识内部解释 | 核心概念有足够定义、条件和例子 | 连贯基础单元与更深理论结构 |
| 跨层成立条件 | 承重关系有对象、条件、依据、未知 | 复杂论证、冲突和迁移边界 |
| 权重影响下一步 | 当前重点与投入边界明确 | 依据指导、反复卡点和区分价值重调 |
| 从连接到研究问题 | 一个候选有最小检查和结果分支 | 多候选比较、问题谱系和放弃理由 |
| 修订影响与低负担 | 原记录保留，一次产出多处引用 | 局部影响复核、合并撤回与规模维护 |
