## 2. 科研 map 究竟装什么

以下是研究内容面，不是新增八个服务或数据库。其内部关系分布在知识、问题／证据、方法、人物组织、成果演化、指导实践、个人发展等逻辑网络中。同一个对象可通过身份桥复用，具体断言及证据仍独立。

### 2.1 最低、正常与长期要求提案

“最低”是当前一个专题足以支持真实判断；“正常”是一个活跃研究范围内形成连贯版图；“长期”是随着研究积累逐渐覆盖相邻问题、演化和实践。三档均不降低证据标准，不按节点数量升级。

| 研究内容面 | 最低要求：一个专题可以做判断 | 正常要求：活跃范围成体系 | 长期补全方向 |
|---|---|---|---|
| 问题与对象 | 写清要判断的对象、输入输出、约束；允许未成形疑问 | 能区分相邻问题、不同任务定义和关键假设；说明价值与已有回答 | 问题如何演化、重述与被替代；哪些长期难点尚存 |
| 方法与机制 | 重建当前方法关键机制，并有一个真正可比的替代或明确未查 | 按共同任务、接口、假设、预算比较多个方法，保留不适用处 | 方法族、组合方式、瓶颈迁移与跨问题对应 |
| 主张与证据 | 每个重要判断回到具体依据，写条件和未验证面 | 证明、复算、实验、反例和竞争解释相互校对；更正可追溯 | 累积可复用论证、争议与反例，分析结论变化影响 |
| 思想与成果谱系 | 当前成果的前驱、改动及残余问题有来源或待核标签 | 多条路线的继承、分叉、替代及同期对照可说明 | 长期问题谱系、失败路线、负结果与复兴条件 |
| 人物与团队 | 当前相关作者／团队及具体工作；未知角色不猜 | 谁在做何种问题、合作与时期，区分作者贡献和机构归属 | 跨学术／工业的人员与方法流动，保留历史时期 |
| 实现与应用实践 | 原论文、实际代码／版本、公开部署说明区分；没有应用证据就标未查 | 比较真实约束、实现差异、成本、采用范围与公开失败 | 工程经验、产品路线、技术替换及可迁移的实践约束 |
| 科研操作与指导 | 当前困难能找到一种可执行检查方法及其原来源 | 阅读、反例、实验、写作、协作等方法有真实使用、调整与反馈 | 积累研究 SOP、taste 与学徒制经验；方法可因失败被修订 |
| 自己的问题与研究轨迹 | 保存候选问题、来自哪里、下一次检查及继续点 | 比较多个候选，记录继续／改写／停放／放弃及本人贡献 | 形成个人问题线、选题判断和可继承成果；不是履历包装 |

这些要求是本次新提案。原四篇已有权重而非平均铺开；先围绕鲁侧一个实际问题形成局部研究版图。孙侧与 OAI 是后续取舍参照，不要求每条当前关系同时通向三方，也不强迫外部探索立即产生 toy。

### 2.2 与原有地图的映射，不删掉原范围

| 原科研 Map 内容 | 本次落点 |
|---|---|
| 分区图 | 问题范围与任务定义；L0／L1／L2 仍是观察尺度 |
| 脉络图 | 思想／方法／成果的演化，不能只按日期连线 |
| 团队图 | 人物、组织、角色与时期 |
| 成果横向对比 | 同任务、接口、预算和条件下的方法／证据比较 |
| 困难清单 | 未解决的问题、能力／材料缺口与两者的区别 |
| 动向雷达 | 学术／工业独立观察，保留来源与已查／未查范围 |
| SOP 与 taste | 科研操作、指导选择、实际使用及效果 |
| 领域工程实践 | 代码、系统约束、测量、交付和失败经验 |

原七图保留导航用途：Knowledge → 知识结构；Method／Genealogy／Transfer → 方法、谱系、迁移；Competency／Identity／Trajectory → 个人证据与发展。它们不是七个互不相干的课程，也不证明底层只有一个扁平图。W1–W7 是资料来源／搜集波次，不是个人学习阶段。

### 2.3 连线必须承担具体含义

选中某个方法后，知识层回答“定义、条件和机制是什么”；方法层回答“在相同任务下还有哪些选择”；证据层回答“哪句话由哪段依据支持”；成果层回答“哪个版本实现或采用了哪部分”；个人层回答“本人在何帮助下做到了什么”。

关系详情至少能展开理由、适用条件、原来源／版本、未知和后续更正。只像、明确引用、实际采用、个人使用、独立验证是不同关系，不都写成“相关”。层间通过身份、依据、实践与行动连接；行动桥只在用户决定安排后进入工作台，探索本身不必有任务。

## 3. 学习台：目标要求与个人表现分栏

### 3.1 一个知识可以服务多个目标

内容引用 K 不复制。目标 G1 是考研数据结构，G2 是鲁侧论文训练；它们各有“G—K 的要求记录”，而不是把最低／正常／长期直接写到 K 上。概念定义变化与目标要求变化也分别修订。

| 同一内容 | 考研目标下看什么 | 鲁侧目标下看什么 |
|---|---|---|
| 图与递归 | 图表示、遍历、调用返回、正确性与复杂度、限时变式 | DFG 输入信息、切分条件、递归机制、实现与行为语义 |
| 概率／抽样 | 对应考纲下的对象、条件、计算与推断 | 选择单位、预算、接口、偏差及评价目标；过滤不自动满足随机抽样条件 |
| 英文阅读 | 英一词汇、句法、篇章和各题型要求 | 论文术语、论证结构、假设与主张范围；不是同一成绩 |

完整内容骨架和两组深度示例引用[暂定内容版图 §4–§7](../2026-09-14__research__multilayer-content-map-provisional-baseline.md:98)，不复制一份新考纲。第一版可录入用户明确的目标和暂定要求；官方范围未核就显示未核，不能生成“覆盖 100%”。

### 3.2 建议页面

```text
学习台
左：继续上次／基础与目标／纠错与回顾
中：当前知识或材料
    本目标的最低要求｜正常要求｜长期后续
    原文与我的草稿／尝试／反馈
右：前置与已有连接｜帮助条件｜相关研究问题
底：当前继续点｜暂放｜返回原问题

研究专题
左：问题范围、方法、谱系、团队、应用、指导与个人问题线
中：当前问题 → 所用机制／替代 → 依据与未查面
    打开局部关系、比较记录或共同工作区
右：跨层关系详情｜补学入口｜候选最小检查
底：这次改变了什么判断｜继续／改写／停放的理由
```

这是一份文字低保真设计，不是运行界面。科研各内容面尚未实施的部分明确标记并能回原资料；不能全都指向同一列表后宣布八层齐全。窄屏通过列表与关系详情完成同样动作，不依赖拖拽或 3D。

### 3.3 纠错本与两类评价

从当前材料旁“记录疑问／留进纠错本”，引用原尝试，不重抄。展开“当时—后来—再检查”：输入、帮助、反馈、质疑、修订、后续尝试和继续点。原因可未知；反馈可以被推翻；强提示成功与独立失败并存。

考研、科研／工程可以有各自入口和评价，但共用原产物。本人证据必须包含成功与失败，不要求先制造错误才能进入回顾。推荐的指导、实际选用、部分使用与有效性分开；首批不建自动推荐／分类器，完整指导使用留 C05。

## 4. 三条代表路径：纸面走查，不冒充用户试用

以下只使用合成过程与已公开知识，不读取私人题目、用户答案或 sealed。T0/T1/R0 等为说明标签，不是已保存的真实活动 ID。

### S-L：从考研基础独立进入

1. 从“基础与目标”选择数据结构，目标时间为 2027-12；当前范围显示用户指定、章目待核。
2. 进入递归 K，查看该目标下最低／正常／长期说明；切到鲁侧目标时是另一份要求，不改变 K 或既有成绩。
3. 保存一份尝试 T0，帮助条件未知时保留未知；先不要求填写错因。
4. 引用反馈 F0；后来发现反馈漏了条件，添加更正而不覆盖 F0。
5. 新尝试 T1 与原题／变式条件分开；若未做独立复测，显示未检查。
6. 暂放后再次进入，能找到原材料、当前解释与继续点。全程无需创建科研任务。

纸面检查：修改要求不会改成绩；更正反馈不会自动把错误归用户；未核专业课范围不会显示全覆盖。这些是未来验收预期，当前没有真实题目／作答证明教学效果。

### S-R：论文拆解进入研究问题，再补学回来

1. 从鲁侧专题的已登记来源，保存问题 Q：“当前局部摘要能否回答一个指定查询？”；查询尚未定时明确留空，不称已选课题。
2. 引用 EdgeIM 的相关机制，按实际需要引入 sigRank 的比较目标、Ground Truth 的世界定义或 CrossEdgeIM 的架构条件；不强制四篇全用。
3. 研究问题记录写出当前假设、可比替代、已有依据和未查面。这里只形成最小检查计划，不启动 toy。
4. 因图／递归前置不熟，开学习分支，保留原问题、原工作区、来源版本与位置、中心和选中。
5. 在分支保存 T0 与反馈；返回后写研究判断 R0，引用实际依据。本人学会某概念只解释理解变化，不替代论文或实验依据。
6. 回到原专题，问题、比较与仍未知内容可见；没有自动写创新、通过或日程。

纸面检查：分支不是复制一张“学习版方法”；返回不能只到首页；候选检查不能显示“实验已完成”；多层整体未完成时只称局部研究—学习往返。

### S-X：失败后来被定位为实现问题

1. 一份合成运行观察与预期不符，最初解释为“方法可能失效”，明确是待核判断。
2. 保存诊断、指导引用与后续发现；若定位到实现错误，新判断说明理由，保留旧观察。
3. 修复由助手完成时记录参与者，不把工程检查通过写成本人独立实现。
4. 研究判断撤回“算法已被反驳”的过强解释；原方法的一般正确性仍未由这次修复证明。
5. 个人回顾与研究专题各读取同一过程，评价分别修订；后续能继续原问题。

纸面检查：不是错误都归学习者；不是代码修好就使研究主张成立；不是改判就删除旧来源和历史。完整失败谱系与跨专题成果继承仍属 C07，不由本局部过程冒充完成。

## 5. 首批所需的候选语义合同

这是待批准的局部设计，不是已修改的 `CONTRACTS.md`。优先复用现有 Object／Revision／Workspace／View，是否新增 kind 在正式 CONTRACT_DELTA 写明；不因为 attrs 可装 JSON 就跳过 UI、引用、查询、导出和兼容检查。

| 记录 | 必须表达的语义 | 首批建议与边界 |
|---|---|---|
| 学习目标 | 目标范围、出处、范围是否核验、可选时间 | 独立 goal 记录；四科目标按用户输入，未知章目不填；不新建时间比例或强制截止 |
| 目标—知识要求 | 目标引用、知识引用、最低／正常／长期说明、暂定／已确认与版本依据 | 建议独立 requirement 记录，正式关联须明确目标和知识；只写想法时先存普通草稿；长期说明可空 |
| 个人尝试与反馈 | 题目／输入、帮助和参与者、产物、反馈及后续尝试引用 | 复用 Attempt／Feedback；不以 author=human 自动推导独立；未记录帮助显示未知 |
| 研究问题与判断 | 问题、主张／条件、证据与版本、当前解释及修订原因 | question 继续复用；研究判断与个人评价分开记录。不用 result_of 表示 supports，不自动生成新的正式边 |
| 返回上下文 | 原问题、原工作区／视图、来源版本／anchor、中心／选中／筛选 | 在现有 return_context 上提出明确差异；首批只保证一次分支往返，多层嵌套另评估 |
| 显式引用与导出 | 引用了哪个对象的哪个版本，未导出的引用有哪些 | 新记录纳入导出引用说明；选择导出不递归拉出整个图或私人过程 |

创建简单草稿依旧只需正文或已有来源。关联目标、补帮助条件、建立评价可以后补，不强迫一次填完；研究判断没有证据时可保存，但显示未验证。

### 5.1 实施前必须解决的窄差异

1. `goal / requirement / research_judgment` 是否以独立 kind 复用 Object：本稿建议如此，不建新表；正式字段、引用校验和版本读取在 CONTRACT_DELTA 冻结。
2. 返回上下文新增原工作区／原视图和完整来源引用：现服务只允许 origin/filter/center_ref/selected_ref/source_id/view_id/topic_ref，不能直接发送新字段。本稿建议增加明确的原工作区、原视图引用与已支持 SourceRef，保留旧记录读取；当前分支的 view_id 不冒充原视图，不顺带实现网页来源。来源只有 registered_asset 时只能承诺回到整份资料，不能虚报原段已定位。
3. 引用解释：引用当前对象与引用历史 revision 分开；本文要求记录依据时固定所用版本，浏览当前内容可以显式切换，不静默替换历史。
4. 首批的研究问题正文可先分段记录假设／替代／检查计划；正式多层关系类型与复杂采用／使用记录不在本批冻结。

续作已在 [B 接口提案](B_CONTRACT_PROPOSAL.md) 给出推荐字段与读写行为，包括三条写路径的一致语义、原问题同身份进入分支、原视图显式恢复及按版本选择导出。该提案仍待批准；不把当前代码“能存 attrs”算作这些能力已经实现。
