## 2. 四个相互独立的划分标准

### 2.1 先看什么：时机按影响排序，不按热度排序

| 时机类别 | 入类条件 | 应在何时处理 | 不能推出 |
|---|---|---|---|
| 结构前置 | 可能改变对象身份、关系含义、来源／版本、分支返回或权威分工；晚改可能需要迁移 | 下一批相关合同定稿前；先做机制比较，不等真实数据齐全 | 优先阅读不等于优先安装 |
| 场景伴随 | 能改善当前学习、批注、反馈、计划评审或任务切换，但可局部采用 | 与A/B真实小样或教学样板同时比较 | 样例顺畅不等于长期有效 |
| 需求触发 | 与现有能力重叠较多，收益取决于尚未出现／确认的使用需求 | 出现具体用途，或一轮探索带来有价值的新能力假设时 | 当前不紧迫不等于没有长期价值 |
| 身份待补 | 不能唯一定位来源或版本 | 先补地址；只暂停该候选的事实核验与试点 | 来源未找到不等于工具差 |
| 内部依赖 | 不是候选软件，而是已有需求、授权、验收或写域的约束 | 与相关方案同步对账，按原任务处理 | 内部交接归档不等于问题已解决 |

具体判断依次问：影响我们的哪个过程？是已有缺口还是探索性新可能？下一批会不会作难以撤回的决定？来源够不够核对？能否先用较小改动验证？维护／学习成本由谁承担？

不使用star、介绍篇幅、图是否漂亮或“AI功能多”作为优先级依据。不给不同职责的工具排统一总榜；同一工具的不同机制可分属不同类别。自由探索仍可保留，不要求每条参考立即接回EdgeIM或产出toy。

### 2.2 看到多深：按将要作出的决定选择证据

| 阅读／验证深度 | 必须弄清 | 最低产出与结论上限 |
|---|---|---|
| 定位 | 作者／项目、版本、用途、许可、维护及来源缺口 | 一条清单记录；只能称“候选／来源说明” |
| 机制 | 输入、输出、关键对象、操作过程、成功与失败语义 | 一条可解释的场景路径和来源坐标；仍是文档／演示层判断 |
| 实现 | 对决定关键的源码路径、数据持久化、导出、网络传输、恢复和已有测试定义 | 窄范围源码证据；区分“定义了测试”和“测试实际通过” |
| 实测 | 固定版本在隔离场景中的实际表现、失败恢复、导出与退出 | 可复现记录；技术结论、用户体验与长期效果分别记录 |

原则借鉴一般到“机制”即可形成候选；涉及权威写回、数据格式、模型上下文或隐私的设计要查相应“实现”；安装接入前需完成相关“实测”。评论、视频等无法查源码时不伪造实现证据；工具不开放源码时说明可观察范围和剩余风险。无需每个参考都读到最高档。

这些档位是参考评估深度，不是课程D0/D1/D2，也不是学习台的最低／正常／长期掌握要求。

### 2.3 怎样融入：五种处置都可以是合理结果

| 处置 | 适用条件 | 交付与授权 |
|---|---|---|
| 借鉴原则 | 方法有用，但不需要引入软件或改数据模型 | 把原则转成一条具体设计／教学检查建议；冻结课程的修改仍走原授权 |
| 转化设计 | 具体交互／机制有价值，需按两台语义重新设计 | 提出最小合同／界面差异及反例；先审阅，获批后才施工 |
| 隔离试用 | 文档／源码不能回答实际体验、兼容或收益问题 | 明确一个场景、版本、目录、数据、成本、退出办法；用户批准后运行 |
| 正式接入 | 相关实测与真实使用均支持采用，且归属、数据流、退出与维护已明确 | 用户明确批准写域／部署或接入范围，新增独立实施任务及回执 |
| 暂存／不采用 | 信息不足、收益未成立、成本不合适或语义冲突 | 保留依据、影响范围和重新评估条件；不删原始参考，不无限重试 |

这不是必须逐级晋升的流水线：可以一直只借鉴，可以试用后不采用；也可以先设计而不安装。不得把“文档可读→实测通过→适合采用”自动串联。

### 2.4 怎样算通过：分开对象和证据，不合成一个总分

每项结论分别记录：**参考主张／已见证据、对我们是否适配、已授权到哪一步、实测与用户试用是否完成**。当前原件自报、源码观察、主线程实测、独立复核、用户反馈不得互相代替。

判定用“满足／部分满足／不满足／未检查／不适用”，每项附依据；“不适用”需说明原因，未知不能按满足计分。不建立新应用状态机，不改已有PASS或研究判定枚举。

## 4. 融入两台时保留的语义边界

| 对象或连接 | 由谁解释 | 借鉴时必须保留的区别 |
|---|---|---|
| 知识定义、前置、机制与条件 | 相应知识层及来源 | 不以聊天的父子顺序推导知识前置；不因有连线就视为成立 |
| 目标—知识的三档要求 | 学习目标要求记录 | 同一知识对不同目标各有要求；不把参考阅读深度写成个人成绩 |
| 问题、方法、证据、谱系与研究判断 | 对应科研网络层 | 层内关系及依据各自成立，跨层通过明确身份／来源／实践连接；不是单层图加筛选 |
| 对话树、模型上下文选择 | 对话交互层（候选） | “送入模型”“显示在画布”“导出成笔记”“支持某主张”是不同动作 |
| 手写、原尝试、反馈、重做 | 原产物＋学习活动引用 | 清稿不覆盖原尝试；AI辅助与本人独立动作分开，普通草稿不强制逐页登记 |
| 计划依赖、执行、评审 | 既有任务正本与获准执行工具 | 工具终止／completed不等于验收通过；不得反向改课程或研究结论 |
| 文件／脚本／工作区入口 | 资源入口工具（候选） | 能打开不等于已完成，也不授予脚本对其他仓库的写权限 |

优先引用同一产物及明确版本，不复制整份正文建立第二正本；新能力若现有合同表达不了，先记录窄差异与消费者，再讨论修改。不默认增加图数据库、统一Event平台、后台调度或自动语义边。

## 6. 检查、评审与分级处置标准

### 6.1 所有拟融入项共同检查

| 检查面 | 满足标准 | 不满足／未知时如何处理 |
|---|---|---|
| 用途与增量 | 指向明确缺口或值得验证的新能力，列出现有替代方式 | 只“看起来强大”则保留探索，不列近期施工收益 |
| 来源与范围 | 精确来源／版本、作者声明和本次核对分开；阅读范围可追踪 | 无唯一身份只定位；不拿旧视频替代新版本行为 |
| 语义与权威 | 不混淆知识、上下文、任务、研究判断、本人能力；各正本有明确写入者 | 对相关采用范围为阻断项；不能用易用性抵消 |
| 数据流与许可 | 对试点实际用到的保存、模型推理、联网／MCP、同步、权限及许可有说明 | 不明则不投入敏感资料；允许明确缩小的只读／非敏感试点，不自动升级全量扫描 |
| 来源回链与退出 | 关键产物可读、来源／版本或缺失限制可见；能停止使用并取回已声明范围的材料 | 核心证据不可恢复则不正式接入；可降为不持有正本的辅助工具 |
| 收益与负担 | 至少有一项用户可指出的实质改善，如少抄一次、能返回原处或暴露理解错误；记录代价 | 不凭一次计时显著性或主观评分保证效果；新增负担抵消收益时改方案／暂缓 |
| 实测与维护 | 相关用例有结果，实际版本、已知限制、维护和更新／退出责任明确 | 没实测保持候选；无人愿维护不引入长期依赖 |

### 6.2 问题严重度

- **阻断当前拟采用范围**：越权写入／外传、丢失关键原产物、错误通过或错误归属、核心来源不可辨、无法退出。修复或收窄范围后再评估。
- **需要修改后复核**：核心场景走不通、恢复或版本含混、教学帮助不足、相关回归失败。保留失败，不靠增加说明宣布通过。
- **可带限制试用**：不影响核心证据与语义的小范围体验问题，且用户知悉并接受；列清影响范围。
- **观察／未知**：未测、设备／来源未给、长期效果未知。不是产品缺陷，不评分为通过；不适用必须给理由。

### 6.3 谁检查、谁批准

主线程负责来源抽查、方案整合、写域与最终判断。独立复核优先看结构前置项、权威／隐私／恢复，以及“证据是否真支持结论”；用户负责选择真实样本、评价使用负担与批准实际采用。不要求用户重复机器回归，不让评审意见自动变更授权。

总并发最多2（主线程＋一个只读核验位）。子代理仅在有具体、独立任务时派发，`fork_turns=none`，不改文件、不派生；派发后按当前AGENTS等待，主线程不在同一范围重复检索。可让唯一核验位检查一个机制组，主线程在返回后整合。

若连接失败／429，无有效回执就标独立复核未完成，不自动反复派发；主线程可以完成文档自查和方案交付，但不能补签独立通过。下一次具备条件时复核关键差异，不要求重读所有无关材料。
