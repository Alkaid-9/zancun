## 3. A1 来源检索

### 行为

- 检索范围为当前已加载、类型与可用性符合原入口规则的完整资产集合。不得先取前 300 再检索。
- 提供可见查询框、结果标题与所属集合、匹配数及空结果提示；可分页／逐批显示，但任何匹配项都应可到达，页大小作为明确局部参数，不成为数据截断。
- 用户选中来源后，原工作簿范围入口及普通登记来源读取保持各自语义。改查询不能让旧的“用此来源记录”按钮把用户带到不对应的资料。
- 不修改 catalog／registry，不重新扫描全库，不声称支持未实现的任意 PDF 片段或网页定位。

## 4. A2 首次保存

限定 `renderP1Capture` 的首次保存，包括新工作区和加入已有工作区；保留已有的对象已保存／工作区已创建／页面打开失败阶段记录。不要重写所有保存操作。

- 在请求发出前同步设在途状态，使同一 capture 的两个保存入口不能并发启动；显示正在保存。
- 保存中的编辑与导航如何处理要明确：建议临时禁用会改变提交内容的控件，显示说明；不静默丢弃后来输入。失败后恢复编辑并保留草稿。
- 成功后在到达页面显示“已保存”及可辨别的记录标题；不能只依靠页面跳转暗示成功。
- 对已知的部分成功，重试只补尚未完成阶段；不得重复创建已记录的对象／工作区。保留当前的冲突与输入保留语义。
- 网络失败可能发生在服务器已提交而响应未到达之后，不能一律声称“没有保存”。此时显示结果未确认，保留输入；已知工作区可走现有继续入口，未知中间对象若无现有界面可定位则明确待人工核对，不能假装提供不存在的查找或自动清理。不得后台自动重试。本包不承诺跨会话或多客户端全局 exactly-once。

| 编号 | 场景 | 应观察到的结果 |
|---|---|---|
| A-05 | 首次保存快速重复点击／另一保存入口 | 在途期间只有一条保存流程；控件和状态明确 |
| A-06 | 新建与加入已有工作区成功 | 内容正确，成功状态可见，目标工作区正确 |
| A-07 | 保存前验证失败、明确服务错误 | 未吞输入，解除在途状态，可修正后重试 |
| A-08 | 对象成功、工作区失败；工作区成功、页面加载失败 | 保留阶段身份，重试不重复已知成功阶段 |
| A-09 | 响应丢失导致结果不确定 | 不虚报确定失败／成功，不自动重提；草稿仍在，已知工作区能返回，无法定位的中间态明确待核 |

以上只覆盖用户已登记的保存问题及相应失败分支，不新增通用遥测、重试框架或服务端幂等平台。

## 5. B 的功能边界与建议合同

### B1 目标与知识要求

首批提供考试目标的四科范围入口与一个鲁侧训练目标；章目尚未核验时只显示明确的范围说明。样例只展开图／递归、概率／抽样两组已讨论知识，不批量导入课程、用户答卷或七张地图。

建议复用 Object／Revision 表，增加有明确语义和界面的记录 kind，而非增加数据库：

| 记录 | 建议字段语义 | 创建／更新约束 |
|---|---|---|
| goal | 目标类别、范围说明、范围来源／核验状态、可选目标年月 | 考试 2027-12 源于用户；不伪造官方考试日或已核章目；空白目标状态不算零进度 |
| requirement | goal_ref、knowledge_ref、最低／正常／长期说明、暂定／确认、所依据版本 | 正式要求须绑定明确目标和知识，同知识不同目标分别维护；仅有想法先存普通草稿，之后再建立要求关联；旧要求保留 revision |
| attempt／feedback | 继续复用；补帮助条件、参与者、输入／产物和后续引用的局部语义 | 未填写帮助默认未知；feedback 仍指合法 attempt，不新增第二份反馈权威 |
| research_judgment | question_ref、主张与条件、依据对象／来源版本、当前解释、修改原因 | 与个人评价分开；证据可缺但标未验证，不自动造 supports／refutes 正式边 |

字段名、校验和查询行为在正式 CONTRACT_DELTA 中固定；本设计给出推荐语义，不是对现有服务能力的证明。若这些记录不能在 UI 编辑、按目标找回、读历史并正确导出，就不能因为 attrs 已存入而算完成。

续作的 [B 接口提案](B_CONTRACT_PROPOSAL.md) 已列推荐字段、窄查询入口和三条写路径要求。正式实施时只将获批部分转入实际 CONTRACT_DELTA，不把设计稿直接标为冻结。

### B2 返回与分开的评价

- 研究问题页先提供明确分段：问题与约束、相关机制／替代、已有依据与未查面、候选最小检查。可以只写一句问题再补其余，不强制提交实验计划。
- 从问题或当前原段开学习分支，复用知识对象；原问题保持原身份，不复制成另一个“学习问题”。
- 分支保存个人尝试／反馈；返回原问题的工作区后再保存研究判断。允许只留一边，也允许只暂放；引用同一产物的实际版本，不复制正文，不从本人的练习结果自动生成结论。
- 返回必须恢复原工作区／专题、原视图、中心、选中、筛选、来源及已知版本／anchor和继续点。首批保证一次分支往返；复杂嵌套链另项。仅整份登记来源时显示“原段未定位”，不承诺不存在的页码或位置。
- 当前 `return_context` 有字段白名单。续作建议在新 `branch_origin` 对象中保存原工作区／原视图引用和完整、已支持的 SourceRef；旧 context 字段保留原读法，原视图由显式入口选择。原内容后来变更时提供当时版与当前版的区别，不回滚覆盖新工作，不给未知旧字段伪造默认事实。
- 引用历史版本、查看最新版本分别操作；没有原文快照不能声称可重现旧内容。导出列明带出的内容与未带出的外部引用，不递归整图。
