## 1. 首批终点与非目标

用户可从已登记、可读取的普通文本选择一段，把**原摘录和自己的问题分开保存**；补学回来时能看见当时摘录、当时行区间及当前同位置的文本，并知道位置是否仍能对上。无需迁入Obsidian、连接模型或安装新软件。

首批只做`.md`／`.txt`的UTF-8原始文本**整行区间**，行号从1开始、两端包含。Markdown按源码行而非浏览器渲染坐标；可输入起止行，也可通过列表选择整行，不把任意字符框选／公式渲染映射列为首批必须。PDF页、图片区域、网页、享做深链接、模糊重定位、多层嵌套与完整备份另案。

来源原文件只读；正文是用户记录，摘录是带来源的局部快照；两者都不能自动成为已证实的主张或本人独立能力。B当前技术通过和真实用户试用开放状态不变。

## 3. 推荐表示：复用text_excerpt，不新建表

来源身份仍在`source_refs`，记录及其版本仍为Object／Revision。用户问题留在`body_md`，不把原摘录复制一遍混入正文；新摘录快照仅保存在对应anchor，示意如下，字段仍待实际施工合同确认：

```json
{
  "source_id": "src:DEMO",
  "asset_id": "asset:DEMO",
  "anchor": {
    "kind": "text_excerpt",
    "line_start": "12",
    "line_end": "15",
    "text_basis": "utf8-source-lines-v1",
    "quote": "本次实际读得的四行，换行统一为LF",
    "captured_at": "本次读取时刻，实际写入ISO时间"
  }
}
```

这是字段示意，不是可提交的DEMO数据。`line_start/end`沿既有字符串表示，首批新捕获只允许正十进制整数字符串且start≤end；不把旧字符串静默转为新格式。`quote`、`text_basis`和`captured_at`成组存在才作为新捕获读取；旧text_excerpt缺快照时显示“旧引用没有摘录快照”，不补造。

**版本分两层**：Object的revision固定“当时记录了哪份quote”；SourceRef.revision_id才是所引用的原来源版本。登记中的上次扫描版本不等于本次实时文件内容。本批不新造全文件hash／历史文件库；没有证据绑定本次读取与已登记版本时，来源revision_id保持未记录，并显式显示“来源版本未核，只保存当时片段”。不可拿captured_at或Object revision冒充原来源版本。

这一点必须写入未来实际CONTRACT_DELTA：满足原SourceRef合同中的可辨位置与内容版本，是通过**行区间＋已保存摘录的Object revision**，而非宣称保存了整份来源历史；若验收要求整份原件版本重现，当前范围不满足，另列扩展，不能把它自动判通过。

新捕获由读取结果形成，再由用户明确保存；接口字段校验只证明结构合法，不证明内容未被手工编辑或经独立审查。更正引用／摘录生成新Object revision，原因明确；原快照和原帮助条件保留。

## 5. 返回如何判断，不做模糊猜测

读取当前相同行区间后进行文字对照：相同只说明“当前该位置文字与保存片段相同”，不证明整份文件还是原版本；不同／行已移动则显示“未在原位置核对成功”，允许查看当前文本，保留当时quote。原文件缺失／不可读与文字变化分别提示。

首批不全文件搜索第一个相同句子，不用“距旧位置最近”当来源身份，也不自动迁移锚点。TreeTalk的可见文本anchor和启发式重定位可以后续单独评估，不能照搬为本地Markdown源码行或PDF坐标。

多来源问题明确选择本次带入分支的引用；未选来源时可继续开纯知识补学分支，但不能假定第一条就是原段。原Q/View及其版本、continue点继续按B合同返回，不回滚后来正文，不自动建立研究支持边。
