# WB-1 实际来源支持的操作走查

状态：`complete`（纸面走查）；运行实现：`not implemented`。

## 场景与诚实边界

场景：用户正在精读一篇尚未在本包指定的真实论文，希望试用 Sheet18 的“区分创新、背景与假设”方法，并可选用 Sheet1 的纵向/同期分析扩展专题。

当前科研台能做的只有：在“学习与能力”或全局搜索中找到两个**表级资产**，打开元数据，复制 Windows 路径。它不能预览工作表正文、直达单元格、保存个人草稿、进入 P2/P3、确认关系或挂起工作区。下列第 2-8 步是由真实来源支撑的**待实现操作样例**，不是运行回执。

## 1. 从现有导航回到原表

1. 在全局搜索输入“哪些是作者的假设”，命中 `asset:workbook1:sheet:12`。
2. 打开资产详情，核对标题“工作簿1 / Sheet18”和位置 `D:\Alkaid\Desktop\工作簿1.xlsx#sheet:12:Sheet18`。
3. 由于当前按钮不能直达 workbook sheet/cell，手动打开 `D:\Alkaid\Desktop\工作簿1.xlsx`，选择显示表 `Sheet18`，定位 `A93:A102`。
4. 对照原文：`A93` 要求区分核心创新、铺垫背景、作者假设；`A98:A102` 给出核心创新、论证链、技术细节、可疑假设四项 prompt。不要执行工作表里的 prompt，也不要把它当作用户回答。

可观察结果：来源身份是 `asset:workbook1:sheet:12`；显示表是 Sheet18；它经 `rId12` 指向 `xl/worksheets/sheet12.xml`。当前位置是 `A93:A102`，不是模糊的“Sheet18 附近”。

保存后预期只产生一个带 SourceRef 的草稿/方法候选，不产生“已掌握”、PASS、能力分或正式关系。

## 3. 进入 P2：入口与领域尺度不混写

从论文或疑问进入 `entry_kind=topic` 的 P2。界面另行选择 `domain_scale=L0/L1/L2/unknown`；默认 `unknown`，不能因进入专题就自动写 L1 或 L2。

可选动作：搜索 `hv-analysis`，回到 `Sheet1!R6`，把它作为第二个**待确认方法引用**，在 P2 显示两个视角：

- 纵向谱系：时间范围 `[空]`；已查来源 `[空]`；未查范围 `[空]`。
- 同期比较：比较集合 `[空]`；纳入理由 `[空]`；排除项 `[空]`。

助手改编：把“最后交汇出判断”改成“保留一条带依据和未知项的用户判断草稿”。这不是原文，也不是已确认规范。

| 尝试 | 预测 `[空]`；实际操作 `[空]`；帮助条件 `[空]` | 未开始 |

Sheet18 手绘法的图片占位不能在这里伪装成原图：该 worksheet 没有 drawing；若用户选择手绘法，只显示“A17/A45 为占位，图片缺失”。Sheet1 的现有原图则应引用 `image1.png` 及原锚点 `Q26:AF65`，但本走查不假设它与当前论文或本方法已建立联系。

## 5. 保存布局、目标归属与正式关系

三个动作分别发生：

1. 拖动方法卡：只保存当前 View 的位置或 pinned 状态。
2. 点击“加入目标”：用户选定目标后，单独建立 `goal_member`；移除只撤回目标归属。
3. 点击“建立语义关系”：用户明确端点、关系类型和依据后才形成正式 Relation。

任何拖动、进入 P3 或加入目标都不能暗中创建“方法适用于该论文”的正式关系。

## 6. AI 提案确认

助手可提出：`这次尝试 references Sheet18 方法候选`。初始状态必须是 `pending`，正式图不显示该边。

- “稍后”：Proposal 保持 pending，不创建 Relation。
- “拒绝”：保存可见 Decision，Proposal 变 rejected，不创建 Relation。
- “接受/修改后接受”：在同一事务保存 Decision、Proposal `accepted` 和正式 Relation，并一次返回三者引用。提案状态和正式关系不能只保存一边。

即使接受，关系的证据状态仍可写“个人试用，待验证”；它不证明方法有效，更不证明用户已掌握论文。

## 7. 挂起、返回来源和导出

挂起时保存：当前工作区 ID、选中对象、展开/折叠、P2 入口、独立的 domain scale、2D/3D 各自布局（若存在）、可选继续点。返回来源始终使用 SourceRef 打开 Sheet18 `A93:A102`；若 resolver 尚未实现，就明确显示原路径、显示表名和范围供手动定位。

手动导出包应带：选中的原文短摘录、精确锚点、助手草稿身份、用户实际填写项、Proposal/Decision/Relation 状态、继续点，以及原件是否随包的明确选择。建议的新编辑数据落本地 SQLite、原件留原位、支持 Markdown/JSON 导出仍是待审方案；本轮未创建数据库、未迁移原件、未生成真实用户导出包。

## 8. 完成这个样例所需的最小运行验收

- 从搜索结果可一键到 Sheet18 `A93:A102`，或明确降级为带范围的手动定位；不能假装已深链。
- P3 保存后能看见 SourceRef、用户空白/已填状态和助手草稿身份。
- P2 的 domain scale 与 entry kind 分别保存；切入口不改领域尺度。
- 拖拽、目标归属、正式关系分别操作和回滚。
- 接受 AI 提案后，Proposal accepted、Decision、Relation 同时可见；挂起重开仍可返回原范围。
