## 4. 维护、回退与分工约束

开始一包先记录自己文件范围与当前版本；不碰他窗改动、不整树git操作。原资产和受保护学习答案保持只读。新增数据用独立演示根，不能把试用写进真实记录。

选择SQLite后，备份需要一致快照（例如SQLite backup API），不能复制正在写入的单一DB文件冒充完整备份。具体保存位置和恢复步骤随数据根一起确认；本轮不创建备份脚本。

代码回退只撤自己的小范围改动；新个人记录须先导出/保留，不能为回退代码删除内容。回退后旧导航仍能打开原资产；新对象在未兼容版本中标明需新版本读取。服务启停、升级和服务器维护手册在技术路线确定后据实际命令写，不能现在编造已可用命令。

网络阻塞、写域变化、缺必要决策、源不明确时交付局部结果及精确缺口。不要为了“完成”安装依赖、扩大可写目录、修改模型配置或反复搜索同一失败入口。
