# 学习台设想：主要深入工作入口与能力发展

状态：PROPOSED；关联[总体方案](README.md)。学习台覆盖独立基础、课程/考试、论文、项目和兴趣。科研中的精加工也可调用同一工具；材料按共同来源引用，不因切台搬文件。

## 1. 主要使用过程

用户从一个问题或资料开始：看原文、让AI解释、自己推演/写代码、记录反馈和疑问，必要时补一个前置单元，再回到原问题。长期总览记录能力证据与覆盖，不用课程勾选替代个人掌握。

核心过程提案：问题/学习目标→初次尝试或示范→必要补充→亲手操作→反馈→换条件再做→按需要复测。初学可以先示范，不强制每次冷测；是否掌握必须依据具体表现，不能把示范后的顺畅体验当独立能力。

考研覆盖有独立目标，不只追论文暴露的缺口；科研学习保留整篇论证结构及问题→方法→证据→局限，不能全部切成孤立记忆卡。自由兴趣可以始终没有“产出论文”的目标。

## 2. 页面与共用工具

```text
学习台 [继续上次] [从资料开始] [随手记问题] [基础/课程] [回顾]
┌─────────────────┬────────────────────────┬──────────────────┐
│ 本次路径         │ 原文 | 我的草稿 | 尝试  │ 关联与帮助        │
│ 当前问题         │ 原文和草稿可并排        │ 前置 / 方法 / 来源│
│ 前置分支         │ 可见讨论、手推、代码引用│ 解释 / 示例 / 指导│
│ 已静置分支       │ [保存] [新尝试] [记反馈]│ AI提案待确认      │
├─────────────────┴────────────────────────┴──────────────────┤
│ 继续点 / 帮助条件 / 未解决处                [挂起] [手动导出]│
└────────────────────────────────────────────────────────────┘
回顾：上次怎样做的｜证据支持会到哪里｜哪些条件还没检查｜下一次建议
```

共用能力：原文与图片定位、编辑/草稿、讨论分支、Attempt/Feedback、代码/实验引用、关系提案、历史、继续点、选择式导出。学习台添加课程/能力/复测的解释层；科研台可以打开相同工作区，侧栏改为方法比较或研究证据。

观察角度可以切换，活动不必二选一归属。普通阅读、草稿、手推、尝试与反馈直接保存；只有安排时间、委派或协调资源时才调用工作台。P1采用现有本地网页实现共同工作区，不要求先安装桌面壳。

“加入专题/目标”“建立语义关系”“调整位置”分别操作；随手保存无需先选目的、课程或项目。完整拖拽和3D按原专项方案，首批普通工作区不能冒称画布完成。

## 3. 概念、课程、技能与人的状态

| 层 | 保存什么 | 不应直接推断什么 |
|---|---|---|
| 共同知识对象 | 概念、定义、方法、来源、例子与关联 | 存在一张概念卡不说明用户掌握 |
| 课程/考试覆盖 | 目标范围、课程/参考书/习题、已接触章节 | 看完课程不等于掌握，课程次序不必是唯一前置 |
| 学习活动 | 任务/输入条件、尝试、帮助、产物、反馈 | 一次失败不自动成为长期短板 |
| 能力证据 | 能解释/推导/实现/判错/迁移的具体样本 | 考试正确率不自动代表科研能力 |
| 学习建议 | 建议做什么、理由、依据、可忽略/修改 | 推荐不是强制任务或自动日程 |

“递归”可共同引用；考研手算、复杂度解释、实现递归、理解EdgeIM中的分解，各有具体能力目标与证据。可共享前置，不无条件互认成绩。知识关系、课程先后、个人本次路径分别有类型；横向类比不自动成为硬前置。

考研、科研训练、日常学习是同一学习台下的不同课程或目标范围，共用实际适用的记录能力。学习与科研各自维护建议逻辑；不强行把复测、反证、新颖性等字段统一成一张万能评价表。是否抽取共同结构由真实重复需求决定。

## 4. 最小记录与逐步细化

第一次保存只需正文或来源。形成一次有意义的尝试时，按需要附：目的/题目、输入范围、本人或AI做了什么、帮助条件、可见产物、反馈、未解决点与下一步。其余字段可以逐步补齐。

| 字段候选 | 何时有用 |
|---|---|
| first/repeat、资料与题目条件 | 避免把重做或换简单材料的表现直接比较 |
| confidence、error_type | 有具体作答时记录自我判断与错误；不强迫每题填写 |
| delayed_retest、transfer | 确认保留和迁移；没有做就是未检查 |
| time/context | 帮助复盘安排，时长不是学习目标；主观状态自愿记录 |
| assistance/roles | 区分示范、提示下、独立操作及系统产物 |

首批不生成mastery=0.6这类无依据分值。完成练习、得到正确答案、独立掌握、研究结论成立是不同结果。未来若引入模型，需明确校准、适用范围和可纠正机制。

## 5. 学习与科研之间怎样回流

例如学习中发现两个输入得到同一个摘要：可先作为理解材料；用户想追它时保存研究候选，注明这是个人疑问。科研台再比较既有工作与适用范围；没有证据不能宣布创新。科研探索发现能力缺口时，可以在学习台开独立基础分支，回去时保留原位置。

例如同一次反例构造：保存一次活动及产物，学习视角记录本人在什么帮助下做到了哪一步，科研视角记录反例针对的主张、条件与证据。两份评价引用同一产物，允许只填写一边、稍后补另一边，彼此不自动通过。科研视角同时保留发现问题、团队/工业路线、取舍与研究议程，不能缩为“核验主张”。

七图共用来源：Knowledge接概念与依赖，Method/Genealogy/Transfer接方法和历史/类比，Competency/Identity/Trajectory接长期个人样本。研究指导库、pengsida、CCF、W6、操作符可在侧栏被选来使用：记录“本次用于什么/哪里不适用/反馈怎样”，随后回到完整来源。

外部作者真实草稿/公开失败与我们的教学重建分别标记；个人当时的错误解释与后来更正分开保存。不会要求保存模型隐藏思维；记录可见讨论、推演、动作和产物。

## 7. 外部参考和学习统计

virtualxiaoman/kaoyan可作为待核的个人执行记录/复盘案例：关注如何记资料/章节/轮次、生成统计、据结果调整计划。前轮GitHub访问超时，没有源码/许可事实，本稿不沿用讨论转述的分数、时长、脚本能力作设计依据。具体比例/路线是个体经验，不能直接变为用户预算。

FSRS、SRL、课程图、增量阅读等是后续定向核验对象，本稿不声称已完成学习科学综述。引入某机制前只回答：解决哪个已出现的问题，需要什么数据，怎样知道有帮助，怎样停用。统计先从真实活动需要出发，不要求先建完整telemetry平台。

## 8. 维护与验收

手机仍采用手动文件包：选中内容、来源、草稿、继续点；自动上传/双向同步不在首批。原笔记与新解释引用相连；导出后编辑与回导的冲突合同另定。建议可忽略/关闭，静置分支不持续催促，身体/精力信息不作为默认强制字段。

| 验收场景 | 通过条件 |
|---|---|
| 从基础或兴趣直接开始 | 无论文/项目/日程也可保存与恢复 |
| 从工作簿具体段落开始 | 原表/单元格/图片锚点正确，来源和改编可区分 |
| 提示后成功、随后独立失败 | 两次证据并存，不把前次成功写成全面掌握 |
| 修改最初解释 | 原草稿仍可查，后来解释有对应反馈 |
| 从前置分支返回论文 | 位置和原问题清楚，不靠长聊天恢复 |
| 发出执行请求并接回结果 | 运行结果回当前活动，个人表现仍独立记录 |
| 关闭再打开 | 新记录出现在可发现的继续列表，不要求手记ID |

以上是产品验收提案，不是已实现或用户已经通过。
