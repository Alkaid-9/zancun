## 1. 教学：一张表就是一个事件日志（15 分钟）

过程挖掘的原材料是一张表，每行一个**事件**，至少三列：这个事件属于哪个**案例**（CaseID）、做了什么**活动**（Activity）、什么时候（Timestamp）。

一个案例的所有事件按时间排好，就是一条 **trace**（轨迹），写成活动序列 ⟨…⟩。

微例子（跟练习不同）——一家奶茶店的两个订单：

| CaseID | Activity | Timestamp |
|---|---|---|
| o1 | 点单 | 10:00 |
| o2 | 点单 | 10:01 |
| o1 | 制作 | 10:02 |
| o1 | 取餐 | 10:05 |
| o2 | 取餐 | 10:06 |
| o2 | 制作 | 10:03 |

注意 o2 的最后两行在表里是乱的。按时间排完：o1 = ⟨点单, 制作, 取餐⟩，o2 = ⟨点单, 制作, 取餐⟩。**两个案例、两条 trace、六个事件、三种活动**——这四个数别混。

## 2. 教学：一条 trace 的三样特征（20 分钟）

对一条 trace σ，取三样东西：

- **起点** s：第一个活动
- **终点** e：最后一个活动
- **相邻对** Rtmp：所有"紧挨着的两个活动"组成的有序对，**是一个集合**——同一对出现两次只算一个元素；(x,y) 和 (y,x) 是两个不同元素

微例子：σ = ⟨点单, 制作, 点单, 制作, 取餐⟩（客人加单）。s = 点单，e = 取餐，Rtmp = {(点单,制作), (制作,点单), (制作,取餐)}——四个相邻位置，三个元素，因为 (点单,制作) 出现了两次。

对一整份日志，把每条 trace 的三样各自并起来，就得到三个**全局集合** S、E、R。它们记录的是"日志里出现过哪些起点 / 终点 / 相邻对"，**不记录出现了几次**。

## 3. Algorithm 1（读，20 分钟）

下面是论文 p.407（PDF 第 4 页）左栏 Algorithm 1 的逐行转录，符号照抄原文。第 1 站你会拿 PDF 对照它；这一站只需要能照着跑。

```
Algorithm 1: Feature-Preserving Sampling
Input : cases set = {σ1, σ2, …, σn}
Output: Filtered D′, Global Features (S, E, R)
 1  Sort L by ⟨CaseID, Timestamp⟩ to obtain ordered cases Case_ord
 2  Initialize S ← ∅, E ← ∅, R ← ∅
 3  for each trace σ in Case_ord do
 4      Extract s ← σ[0], e ← σ[−1], Rtmp ← {(σ[k], σ[k+1]) | 1 ≤ k < |σ|}
 5      if (s ∉ S) ∨ (e ∉ E) ∨ (Rtmp ⊄ R) then
 6          D′ ← D′ ∪ {σ}          // Add log to D′
 7          S ← S ∪ {s}
 8          E ← E ∪ {e}
 9          R ← R ∪ Rtmp
10      end
11  end
12  return D′, S, E, R
```

读的时候在每一行旁边写两个字：这一行**读**了哪些变量、**改**了哪些变量。三个小问题，答案写进作答文件：

- 3.1 第 2 行初始化了三样东西。第 6 行往 D′ 里放东西——D′ 是在哪一行初始化的？如果让你补这一行，你写什么？
- 3.2 第 4 行 Rtmp 的下标范围原文写的是 `1 ≤ k < |σ|`，而起点是 `σ[0]`。按这个范围**逐字**去取 ⟨a,b,c,e⟩ 的相邻对，会得到哪几对、漏掉哪一对？（按 §2 的定义应该是哪几对——以定义为准，这一站后面都按定义算。）
- 3.3 第 5 行三个条件之间是 ∨（或）。用一句话说：什么情况下一条 trace 会**被滤掉**？
