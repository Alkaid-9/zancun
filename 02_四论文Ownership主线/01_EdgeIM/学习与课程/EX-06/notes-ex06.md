

* **GT = Ground Truth，真值 / 真流程 / 参照答案。**
  它回答的是：**“什么才算真的对？”**
  比如我们自己先规定一个流程规则：`A → B → C` 才合法，然后按这个规则生成日志。这个预先规定的规则，就是 GT。
  关键是：GT 必须来自**独立来源**，不能让被测试的算法自己给自己当答案。比如“EdgeIM 跑出来的模型就是正确流程”就不能叫 GT。

————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————

* **IMf = Inductive Miner – infrequent。**
  这是 **Inductive Miner 的一个带噪声过滤的版本**。

  普通 IM 大致想的是：

  > 根据 DFG 的结构找 sequence / choice / parallel / loop，然后递归构造过程模型。

  IMf 多做了一件事：

  > **先把一些低频行为 / 低频边当作噪声处理，再做 IM。**

  所以它有一个很重要的参数：**noise threshold（噪声阈值）**。

    EX-02 里你跑了多个 threshold，并且发现 **t = 0.3 时第一次出现结构分岔**。

  所以：

  > **IM = 看结构。**
  > **IMf = 看结构，但允许先过滤低频行为。**

  这也是为什么我们一直关心 **边频次有没有被 Algorithm 1 扭曲**：
  因为普通 IM 可能主要在意“边存在不存在”，但 **IMf 会真的读频次/阈值**。

————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————

* **surrogate = 代理指标。**
<!-- **surrogate 代理指标 真正想测的东西不好测，于是拿另一个比较容易测的东西代替它。** -->

    EdgeIM 的通信成本有没有降低？
    ↓ ->没测网络传输字节数，只测了：
    程序运行时间变短了。

    → 那“运行时间”最多只能是通信成本的 **surrogate**。 运行时间下降≠通信量一定下降  运行时间还可能受到 CPU、磁盘、Python实现、缓存等影响。

    比如：
  > “留下的 trace 数变少了”也可能暗示通信更少，但 **trace 数 ≠ 实际传输字节数**。

！！！**不要把“代理变量变好了”偷偷写成“真正目标变好了”。**！！！

  README 直接规定：不能拿时间去代替通信、隐私或质量的直接测量。

——————————————————————————————————————————————————————————————
* **claim ceiling = 主张上限。**

 **你现在手里的证据，最多允许你把结论说多大。**
  证据强度
      ↓
  决定
      ↓
  你最多能说多大的话


README 里的定义也是：**当前证据允许的范围、条件和强度上限。**

——————————————————————————————————————————————————————————————

GT
“什么是真的？”
        ↓
IMf
“我用什么算法/消费者来处理数据？”
        ↓
surrogate
“我测不到目标时，是否用了代理指标？”
        ↓
claim ceiling
“这些证据最后允许我说多大的结论？”


拿我们 EdgeIM 这条线举一个完整例子：

> 我们先用 **GT** 规定一个 synthetic process；
> 生成日志 D，再让 Algorithm 1 得到 D′；
> 分别把 D 和 D′ 喂给 **IMf**；
> 看不同 threshold 下过程树是否改变；
> 如果只测了运行时间，就不能拿它当通信量，只能叫 **surrogate**；
> 最后如果只测试了 10 个 synthetic worlds，**claim ceiling** 就只能限制在这批实验和这种构造条件内。

这样应该会比单独背词清楚很多。

而且这里最重要的其实不是四个英文词本身，而是四个科研习惯：

> **标准答案从哪来？**
> **下游到底消费什么？**
> **我测的是目标本身还是代理？**
> **我的证据到底允许我说到哪一步？**

——————————————————————————————————————————————————————————————————————————————————————————————————————
**研究方法论语言**。
——————————————————————————————————————————————————————————————————————————————————————————————————————

* **T0 / 研究对象裁定**：决定“我接下来到底研究哪一个具体问题”。不是选一个宏大方向，而是把实验对象钉死。比如不是“研究 EdgeIM”，而可能是“研究 Algorithm 1 保住边集合以后，会不会扭曲边的频次，并进一步影响 IMf 的输出”。README 要求这个裁定必须建立在你前面 EX-01/02/03/05 自己拿到的证据上。

* **flag**：就是“前面发现但还没有解决的疑点/警报”。例如某个地方你写过 `UNKNOWN`，或者我们不知道 Stage 3 到底用不用边频次。进入研究设计时不能假装这些东西不存在，要逐条决定：已经解决、带进实验当边界，还是和这次问题无关先搁置。

* **T2′ / Measurement Contract**：中文可以直接理解成**“测量合同”**。它回答的不是“我要跑什么代码”，而是：**我要测什么东西？单位是什么？跟谁比？用什么指标？什么情况下这个指标就失效？** 比如你说要研究“质量有没有下降”，那就必须先规定“质量”到底用什么量表示，而不能跑完以后看哪个数字顺眼就拿哪个。

* **GT / Ground Truth**：真值、参照答案。重点是它必须独立于你正在测试的方法。比如你自己规定一个合法流程，再由它生成 traces，这个规则可以当 GT；但“EdgeIM 跑出来这个模型，所以这个模型就是真流程”不行，那叫自己证明自己。

* **surrogate / 代理指标**：你真正关心的东西测不到，于是拿另一个容易测的量代替。例如真正关心“通信开销”，却只测了“运行时间”。运行时间可能跟通信相关，但它**不是通信量本身**。所以不能写“时间下降 → 通信下降”，除非另外证明这种关系。

* **claim ceiling / 主张上限**：这个特别重要，就是：**凭目前这些证据，我最多有资格说到哪一步？** 例如你只在 10 个 synthetic logs 上看到某现象，那最多能说“在这 10 个构造实例中观察到……”，不能突然升级成“EdgeIM 一般情况下都有这个问题”。EX-06 专门防这种证据只有 3 分、结论写成 10 分的情况。

* **direct measure / 直接测量**：你想知道什么，就真的测那个东西。例如“运行时间”→计时；“通信字节数”→统计传输字节数。
  **indirect support** 就是间接证据，例如过滤后的 trace 数变少了，可能提示通信会少，但它不是通信量的直接测量。README 后面专门要求把两种证据分开。

* **T3′ / CORE vs ADJACENT**：决定**哪些知识是这次研究非懂不可的，哪些只是邻接知识**。比如当前设计里 Algorithm 1、DFG、IM cut、IMf 阈值属于 CORE；Petri net、alignment、sigRank、CrossEdgeIM 等先放 ADJACENT。目的就是防止研究问题一开，知识图谱无限膨胀。

* **T4′ / 时间倒排 + 降级线**：研究设计定完之后，再从截止时间往回排。所谓**降级线**就是时间不够时，哪些东西可以砍，哪些绝对不能砍。比如当前方案里 `D vs D′` 是核心对照，不能降级；随机等量抽样只是辅助控制，可以砍。

* **credit / provenance**：简单说就是**“这条东西是谁得到的、从哪来的”**。论文里的结论归作者；代码跑出来的事实归代码证据；AI 给的解释只能算导航/摘要；你自己手推、预测、实验、裁定出来的，才算你的能力证据。

我们刚才走到的是：**Algorithm 1 可能扭曲频次，而 IMf 会显式读频次，所以这个变化可能传导到下游。**

现在把四个层次彻底分开：

* **现象（phenomenon）**：你实际观察到了什么。
  例：`D` 和 `D′` 的边集合一样，但边频次变了。

* **风险（risk / concern）**：这个现象为什么值得担心。
  例：IMf 会用频次和阈值做过滤，所以频次变化可能影响后续处理。

* **研究问题（research question）**：把担心改写成一个能被系统检查的问题。
  例：
  **在什么条件下，feature-preserving sampling 引入的频次失真会改变 IMf 的过滤结果或最终模型？**

* **假设（hypothesis）**：你在实验前对这个研究问题给出的可证伪预测。
  例：
  **当采样使某条边相对其源节点最强 outgoing edge 的频次比例跨过 IMf 阈值时，D 与 D′ 的过滤结果会发生分岔。**

这里最关键的是：

```text
现象 ≠ 研究问题
风险 ≠ 研究问题
研究问题 ≠ 假设
```

很多刚开始做研究时最容易犯的错就是：

> “我发现频次变了，所以这是个问题。”

这还不够。

因为你还没说明：

> **谁会读取这个变化？**
> **什么条件下它真的产生 downstream consequence？**

而你现在已经开始补上这两层了。

---

再往前一步，我们把它形式化一点。

假设从活动 `a` 出发有两条边：

```text
a -> b
a -> c
```

原始日志 D 中：

```text
w_D(a,b) = 100
w_D(a,c) = 20
```

采样后 D′ 中：

```text
w_D'(a,b) = 10
w_D'(a,c) = 10
```

定义相对频次：

```text
r_D(a,c)
=
w_D(a,c) / max_y w_D(a,y)
```

那么原始 D 里：

```text
r_D(a,c) = 20/100 = 0.2
```

采样后：

```text
r_D'(a,c) = 10/10 = 1
```

如果 IMf threshold：

```text
t = 0.3
```

那么：

```text
D:   0.2 < 0.3  → 可能过滤
D′:  1.0 > 0.3  → 保留
```

看见了吗？

真正重要的不是：

> “weight 变了多少”

而是：

> **变化有没有跨过下游决策边界。**

这个思想非常通用。

以后你看任何论文，看到 representation compression / sampling / abstraction，都可以问：

> 上游 loss 是否跨过了 downstream decision boundary？

这比单纯问“信息有没有损失”强很多。

---

所以我们现在其实已经能把 T0 的核心对象说得很接近了：

> **研究 EdgeIM 的 feature-preserving sampling 是否在保留结构存在性的同时改变频次信息，以及这种频次失真在什么条件下会改变固定下游 IM/IMf 的行为。**

但还没正式拍板。

下一步该做的是 **attack**：

我们要问一个反方向的问题——

> 有没有可能频次被扭曲得非常厉害，但 IMf 最终模型完全不变？

如果答案是“有”，那我们就知道：
**频次失真本身不是充分条件。**

这一步很重要，因为它会逼我们从“相关现象”继续收缩到真正的机制条件。
