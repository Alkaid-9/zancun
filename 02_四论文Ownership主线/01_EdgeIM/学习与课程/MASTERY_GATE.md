## 0. 目标层级与一句话

旧模式的风险是"局部挖得深、整篇接不上"；这份计划把**认知 scope 的完整性**变成和**站序进度**平级的硬门槛，同时不推倒已经做完的 EX-00~EX-03。

| 层级 | 目标 | 当前正本 | 成功证据 |
|---|---|---|---|
| 学习主干 | 对 EdgeIM 形成可重建、可攻击、可审计的 ownership | 本档 + `BRIEF.md` + EX 站点 | 本人手算、实现、冷启动和六道门证据 |
| 研究邻域 | 围绕 sampling、representation、discovery、evaluation、genealogy 长出小而真实的比较/反例/实验闭环 | `FOUR_PAPER_TRAINING_LOOP.md`、受控卡和研究地图 | prediction → check → verdict → claim ceiling |
| 进组应用 | 把已核验、已有本人证据的能力转成 pitch、简历、T5、OE1 和追问材料 | `progress/projects/jinzu-sprint.md` | 对外表述与来源/证据逐条对应 |
| 长期背景 | 观察工业研究、开源资产和更宽领域生态的方向价值 | `WORLD / FIELD` 研究地图及独立任务 | 只作为选择约束，不改变当前站点 PASS |

核心原则：**实践 scope 可以窄；认知 scope 不能窄。进组是一个出口，不是整个学习系统的定义。**

## 1. 六道门（面试硬标准，取代旧的"学完各站即可"）

| # | 门 | 检验方法 |
|---|---|---|
| 1 | **Whole-paper reconstruction** | 关掉 PDF，从 event log 讲到 evaluation，每条箭头答"为什么需要/保存什么/丢了什么" |
| 2 | **Algorithm ownership** | 给一个新的小 event log，不看论文手工走完整条 pipeline（S/E/R → DFG → IM 递归切分 → Petri net） |
| 3 | **Formal-object mastery** | Event / Trace / Log / DFR / Weight / DFG / Process Tree / Petri Net 各自：定义→最小例子→下游为什么需要→丢了什么信息→何时两个日志会映射成同一表示 |
| 4 | **Claim–evidence audit** | 对每个论文大结论（zero loss / 通信开销低 / 隐私保护 / scalable / 质量接近 IM）能分清"实验直接支持"vs"作者解释"vs"证据不足" |
| 5 | **Attack mode** | 给一个新日志特性（高重复率/多环/噪声），预测 Algorithm 1 会怎样表现，再验证 |
| 6 | **Interview compression** | 同一篇论文能讲 30 秒 / 2 分钟 / 10 分钟 / 被追问 30 分钟四档，且能互相缩放 |

六道门内容表（formal-object 五层、claim-evidence 表、attack mode 清单、四档话术模板）全文见本文件末尾附录，与源框架一致，不重复展开。

## 2. 学习节奏：双线程（取代"一个点学完才回整篇"）

- **纵向线程**：当前节点往深吃——公式、算法、反例、toy example。
- **横向线程**：每学完一个节点，立刻回答"它在 EdgeIM 整体解决哪一段？输入从哪来？输出被谁消费？删掉它哪里断？"

**每节课收尾必答**："我今天学的东西，让我对整篇 EdgeIM 的理解改变了什么？"

不允许学成孤岛——这条对已经在做的 EX-04 之后各站同样生效，不是只对新内容生效。

每个被打开的研究节点还要留下同一条短回路：`paper design -> smallest example -> alternative or changed assumption -> prediction -> check -> verdict -> claim ceiling -> reconnect`。没有可证伪预测的联想停在 `PARKED`，不进入当前主线。

## 6. 进组应用层（建立在学习主干和研究邻域之上）

进组计划只回答“哪些已验证能力可以对外表达、还缺哪些材料、进组后如何承接”；它不重写 EdgeIM 学习目标，也不把尚未完成的 R1–R5 研究出口提前包装成成熟成果。

### 6.1 进组面试新最低线（七条，取代旧的"基础+自实现+小实验+脱稿讲清"）

```
□ EdgeIM 全文可重建（无论深度问什么都能接回整篇逻辑）
□ 核心算法可手推（给任意小日志能完整走一遍）
□ 最小实现可重建（pseudocode + 一个 toy example 的手工计算）
□ Claim 可审计（知道每个结论的证据边界）
□ Assumption 可攻击（能说出改哪个会坏、反例是什么）
□ 一个小研究问题跑完闭环（对应 EX-07 实验站）
□ 脱稿承受连续追问（30 分钟被问都不掉包）
```

"完整复现"依然不是硬门槛；"完整吃透"是硬门槛——这两件事不同。

### 6.2 进组前滚动窗口（从 2026-09-06 起，月底为软边界）

| 窗口 | 重点 | 必须留下的证据 | 进入条件 |
|---|---|---|---|
| W0 · 09-06 起 | Whole-Paper Diagnostic + 缺口地图 | 15 题原答、状态标注、2–4 个下一缺口 | 立即可做；不以旧游标阻塞 |
| W1 · 诊断后第一周 | 主脊柱重建：三阶段、DFG/IM/PN、claim 边界 | 一页整篇重建 + 至少一个新日志手推 | W0 已记录缺口 |
| W2 · 第二周 | 一个分枝纵深 + 一个横向镜头 | 比较/反例卡，含假设、指标和证据上限 | W1 的对应对象不再 OPEN |
| W3 · 第三周 | 研究闭环与面试压测 | 一个小问题的 prediction→check→verdict；四档话术 | W2 产物可脱稿解释 |
| W4 · 月底前剩余窗口 | 冷启动复测、材料收口、边界复核 | 至少一次延迟复测记录；pitch/简历只引用已过门内容 | 不把“月底”写成确定日期 |

窗口可以按实际进组日期缩短或合并，但顺序不变：诊断 → 主脊柱 → 受控分枝 → 小闭环 → 冷复测/材料。09-20 既有冻结日和“不扩 infrastructure”约束继续有效。

### 6.3 对外材料的证据消费规则

- `PAPER-TEXT`：可用于陈述论文做了什么，但仍需保留适用范围和指标语境。
- `USER-REPORTED`：只能描述用户报告的当前进度，不能替代 PASS、Ledger 或冷启动证据。
- `USER-INFERENCE`：可以作为个人观察或待验证问题，不能写成论文结论、导师方向或已完成研究。
- `UNKNOWN`：不用于支撑技术卖点；必要时明确说未知。

进组沟通可以先使用已核验的基础事实和既有展示物；涉及“我掌握/我实现/我发现”的句子，必须链接到本人新证据。小研究闭环是能力出口的加分与硬化门，不得倒过来压缩或改写学习主干。

## 7. 附录：六道门内容细节（与源框架一致）

### 7.1 Formal-Object 五层表

| 对象 | 五层掌握 |
|------|---------|
| Event | 定义 → 最小例子 → 为什么下游需要 → 丢失的信息 → 何时映射成同一表示 |
| Trace | 活动序列；记录 start/end → 相邻对顺序与重复 → 与日志的关系 |
| Event Log | 多条 trace 的多重集 → 事件总数与 trace 条数分开 → DFG 计数公式 |
| DFR | 相邻活动对集合 → 与 weight 的区别 → 为什么够给 IM |
| Weight | 相邻对出现次数 → 与 DFG 支持集合的关系 → 下游用途 |
| DFG | 节点=活动、边=DFR、权重=出现次数 → 与 Petri net 的区别 → 丢了什么 |
| Process Tree | IM 输出，代表控制流 → 与 Petri net 关系 → 为什么要递归切分 |
| Petri Net | (P,T,F,λ)；并发与同步 → soundness 直觉 → 为什么需要它 |

### 7.2 Claim–Evidence 审计表

| Claim | 实验直接支持？ | 作者解释？ | 证据充分度 |
|-------|---|---|---|
| 结构无损（zero loss at Stage 1） | ✓ (DFG 不变) | ✓ (相对 IMd) | partial（仅限采样后保持 DFR） |
| 通信开销低 | 理论分析 | ✓ | 无实际网络实验 |
| 隐私保护 | × | ✓ (仅边缘不传日志) | 无加密/差分隐私分析 |
| Scalable | ✓ (9 个公开日志上的 runtime) | ✓ | 仅限该 9 个日志 |
| 质量接近 IM | ✓ (fitness/precision/F-measure) | ✓ | 仅当 DFG 损失不大时 |

### 7.3 Attack Mode 清单

- 改 Algorithm 1 保留判据（"新增 S/E/R"→"固定 K"）→ 样本量不再内生 → 采样偏差风险
- 改 timestamp 处理（乱序→已有因果顺序）→ 算法变化
- 改分布（论文假定场景→热更新）→ 通信/质量 trade-off 变化
- 改下游（IM→Alpha Miner）→ DFG 是否仍足够

### 7.4 四档话术模板

**30 秒**：问题 + 核心 idea + 结果
**2 分钟**：三阶段 pipeline + 三个 contribution
**10 分钟**：Algorithm 1 完整推导 + DFG 损失与恢复 + 与 EdgeAlpha 差异 + 实验与局限
**30 分钟追问**：手推反例 + 改 assumption + 相关工作 + 自己的批评（sigRank 对比 / timestamp 冲突 / CrossEdgeIM 改架构理由 / 论文哪些没证明但声称）

### 7.5 面试模拟题库（按深度分层，来自源框架）

- 30 秒：一句话说 EdgeIM 是干什么的
- 2 分钟：完整讲三阶段 / 相对 IM 改了什么 / 相对 EdgeAlpha 的优势
- 5 分钟：Algorithm 1 保留判据为什么是"新增 S/E/R" / 为什么中心端收到 DFG 后还能跑 IM / 实验怎样证明"质量接近 IM"
- 10 分钟：给一个新日志手工走一遍 / 改成固定 K 采样会怎样 / DFG 丢了什么关键信息
- 30 分钟追问：为什么不用 sigRank / timestamp 冲突假设改变后算法还对吗 / CrossEdgeIM 为什么改模型组合 / 论文有哪些没证明但声称的东西 / 你最怀疑哪个 claim
