# Map 1：专业知识依赖图

- **用途**：这不是百科目录。它是一棵 task-driven（任务驱动）、evidence-driven（证据驱动）的研究树：主干随真实任务向前长，反复出现的关系再连成图；课程顺序和文件数量都不等于掌握。
- **读者**：第一次学过程挖掘的学习者，以及需要按证据安排下一步的批改者。
- **第一步**：先看“当前小视窗”，在自己的产出中找一份对应证据，再填写“当前节点更新单”；找不到就回到 [START_HERE.md](./START_HERE.md)，不要凭印象跳站。
- **当前游标**：这是课程游标，不是个人成绩。小视窗从带权 DFG（directly-follows graph，直接跟随图，边上记录相邻活动出现次数）走向 sequence cut（下一节点；正式定义留给 EX-02 按六步合同展开）。
- **暂时封存**：Petri net（佩特里网）的正式库所、变迁、令牌定义，soundness（健全性，模型能否正确结束且无残留死行为）和复杂 IMf（Inductive Miner-infrequent，带低频过滤的归纳式发现变体）规则。它们先记 `PARKED`，到真实任务需要且通过升级门时再开。

其他长期地图：[方法、谱系、迁移与探索环](./RESEARCH_MAPS.md)；[研究者能力证据图](./RESEARCHER_COMPETENCY_MAP.md)；[研究身份与匹配图](./RESEARCH_IDENTITY_MAP.md)；[研究轨迹图](./RESEARCH_TRAJECTORY_MAP.md)。整篇论文位置见 [PAPER_MAP.md](./PAPER_MAP.md)。

统一记录接口：[RESEARCH_NOTE_TEMPLATE.md](./RESEARCH_NOTE_TEMPLATE.md)。后续系统阅读或算法怀疑必须链接该模板，填写适用的 `System reading`、`Evidence audit`、`Evidence closure` 与 `Research hooks`；本图不复制模板。

## 主原则

1. 主干按真实研究任务向前长，不按百科分类补齐。
2. 前置知识按需补，采用 just-in-time prerequisite（即时前置，只在下一动作确实需要时打开）。
3. 旁枝先登记不追；有趣本身不足以升级。
4. 一个枝条反复出现，或新证据会改变判断，才通过升级门。
5. 每个知识节点锻造一个可迁移科研动作，例如“先列消费者输入”“先找最小反例”，而不只增加一个名词。

任何新节点必须先写它绑定主干的哪一项、服务哪个当前决定。答不出就记 `PARKED`，不进入当前学习队列。

## 即时前置：从现实过程到带权 DFG

```text
现实过程 -> event -> activity -> case / trace -> event log
         -> S / E / R -> directly-follows relation -> DFG support / weight
```

| 词 | 白话定义 | 怎样连到下一个对象 |
|---|---|---|
| 现实过程 | 现实中实际发生的一串工作，例如一件包裹从入库到出库 | 系统把其中一次发生记录为 event |
| event（事件） | 某个时刻发生的一次活动记录，是日志中的一行 | 该行用 activity 说明“发生了什么” |
| activity（活动） | 一类动作的名字；多次 event 可以有同一个 activity | 属于同一 case 的活动按时间排成 trace |
| case / trace（案例 / 轨迹） | case 是一个过程实例；trace 是该实例中 activity 的有序序列 | 多个 case 的记录组成 event log |
| event log（事件日志） | 多个 case 及其 event 的集合 | 可从每条 trace 提取起点 `S`、终点 `E` 和相邻对集合 `R` |
| `S / E / R` | 日志中出现过的起点集合、终点集合和相邻活动有序对集合 | `R` 中的有序对就是 directly-follows relation |
| directly-follows relation（直接跟随关系） | 一条 trace 中紧挨着的两个活动形成的有向关系 | 把活动画成节点、关系画成边，就得到 DFG support |
| DFG support / weight（支撑集 / 权重） | support 记哪些边存在；weight 记每条边在日志中出现多少次 | 作为 Stage 2 到 Stage 3 的待核接口 |

微例子只用于认对象：包裹 `p1 = <入库, 出库>`，`p2 = <入库, 复核, 出库>`。两个 case 构成一个 event log；逐条相邻活动生成 DFG 的边，再逐位置计数得到 weight。这里不推出任何站点答案。

## 任务主干：从树长成图

```text
EdgeIM Stage 1 过滤
  -> Stage 2 DFG support / weight
  -> Stage 3 中心合并与 Inductive Miner
  -> process tree
  -> Petri net

每一步同时挂一个 downstream sufficiency 问题：
“当前摘要是否保留了固定下游消费者实际读取的全部信息？”
```

Stage 1 指特征保留过滤；Stage 2 构造局部 DFG 的 support（支撑集，哪些边存在）和 weight（权重，每条边出现多少次）；Stage 3 合并局部特征并运行 Inductive Miner（IM，归纳式过程发现算法）；process tree（过程树）表达顺序、选择、并行和循环等结构。downstream sufficiency（下游充分性）只问：对一个固定消费者，当前摘要是否含有它实际读取的全部输入。这里不预填答案。

主干起初是一棵树：新前置和新问题挂到当前任务。只有当同一节点反复服务多个任务、出现跨枝依赖或迁移证据时，才加横向连线，变成可追溯的图。

| 主干节点 | 当前真实任务 | 交给下一步的对象 | 待检充分性问题 | 锻造的可迁移动作 |
|---|---|---|---|---|
| Stage 1 过滤 | 明确过滤器读什么、维护什么、交出什么 | 过滤日志与结构特征 | 下一步实际读取过滤日志、集合还是别的对象？ | 先恢复输入、状态、输出，再评价算法 |
| Stage 2 support / weight | 区分边存在与边出现次数 | 局部起止特征和带权关系 | 哪些字段被 Stage 3 消费，哪些只被传递？ | 对每个摘要先列消费者读取项 |
| Stage 3 IM | 追踪合并、cut 与递归发现的输入 | 候选过程树或模型 | 图、权重和原日志各在哪一步被读取？ | 把“看起来够”改成接口核查问题 |
| process tree | 检查模型允许哪些 trace | 可读的行为结构 | 有限 trace 检查能支持到哪一层？ | 把观察一致与语言等价分开 |
| Petri net | 当前只定位后继，不教学形式化 | 后续重放和质量分析对象 | `PARKED`：转换和健全性需要哪些新增信息？ | 未到决策点时保持 UNKNOWN |

## 横跨七图的两条硬约束

- `Epistemic Integrity`（认知诚信）：不知道就记 `UNKNOWN`（当前证据不足，暂不裁定）；negative evidence（负面证据，未观察到、失败或反例）不得删除；credit（贡献归属）要写清谁完成了什么；provenance（来源链）要能从主张回到原文、作答或原始输出。
- `Research Economy`（研究经济性）：每个新增节点先写 value of information（信息价值，这项信息可能改变哪个决定）、cost（成本，需要的时间、数据、计算或协作）和 decision impact（决策影响，结果不同会让下一步怎样变化）。不能改变决定的高成本问题先封存。

两条约束不增加一张“打分表”。它们是每次更新任一地图时都要回答的检查项。

## 六类枝条：每次只开 2 至 4 枝

每个节点只选 2 至 4 个训练点，不把七张图逐项刷一遍。

| 枝条类型 | 什么时候打开 | 例行产物 |
|---|---|---|
| just-in-time prerequisite（即时前置） | 不补就无法完成主干下一动作 | 六步概念节点 |
| horizontal methods（横向方法） | 至少两个方法处理同一明确接口 | Map 2 统一比较轴 |
| evidence-backed genealogy（证据支持的思想谱系） | idea 来源会影响归属或方法选择 | Map 3 引文链与重建标签 |
| cross-domain transfer（跨领域迁移） | 异领域结构相似能产生可检验新问题 | Map 4 六字段迁移单 |
| research competency（科研能力） | 当前产物能观察一个可撤脚手架的动作 | Map 5 行为证据 |
| research identity（研究身份） | 多轮行为开始影响长期问题、导师或工作方式选择 | Map 6 长期行为证据；单次表现不开 |

## 枝条生命周期与站点状态正交

| 枝条状态 | 含义 | 升级证据 |
|---|---|---|
| `SEEN` | 枝条已登记或材料出现过 | 不代表会用 |
| `OPEN` | 当前任务确实需要，已分配一个最小动作 | 写清绑定主干和决策 |
| `PARKED` | 暂不追；可能有趣，但未通过升级门 | 保留原因与重开条件 |
| `OWNED` | 学习者能独立解释、操作、改条件并诊断 | 必须有本轮新作答或新产物 |
| `TRANSFERRED` | 能在陌生但结构相关的问题上迁移，并守住类比上限 | 必须有新的陌生任务证据 |

枝条生命周期与站点证据状态是两套正交状态。站点仍只用 [START_HERE 的 `SEEN / SUBMITTED / PASS / RETAINED`](./START_HERE.md#四个状态词)：前者回答“这条枝怎样参与研究树”，后者回答“站点冻结条件验收到哪里”。同名 `SEEN` 也不能互相推导。`OWNED` 或 `TRANSFERRED` 不能由旧答案、AI 讲解或文件存在自动生成。

## 三个升级门

| 升级门 | 必答问题 | 通过证据 |
|---|---|---|
| Dependency（依赖门） | 主干下一动作没有它会卡在哪里？ | 指向一个具体输入、判断或操作缺口 |
| Repeated recurrence（重复出现门） | 它是否在两个以上真实任务中反复出现？ | 两个任务的路径与共同结构 |
| Research leverage（研究杠杆门） | 补它会改变主张、实验、取舍或资源决定吗？ | `若 A 则做什么；若 B 则做什么` |

满足任一门只表示可以评估升级；还要用研究经济性比较信息价值和成本。有趣、新颖或术语高级都不构成通过。

## 当前游标怎么落到证据

| 要检查的东西 | 可接受的可定位证据 | 只能记为什么 | 下一动作 |
|---|---|---|---|
| 直接跟随边与权重 | 自己画的 DFG、逐边次数表、自检算式，附路径或纸稿编号 | 有材料但未提交时至多是 `SEEN`；提交后才是 `SUBMITTED` | 逐边复核，并写清边是否存在与出现次数的区别 |
| 从图到 sequence cut | 运行前预测、4 节点小图上的手画分组、逐条理由 | 看过 cut 定义不等于会切 | 只做当前 README 已解锁的内容，不搜索后站答案 |
| 个人当前节点 | 当前站冻结条件对应的产出和最近一次批改矩阵 | 没有矩阵就不能自行写 `PASS` | 把证据按“路径 + 标题”提交批改 |
| 保持情况 | 到期后关掉旧稿，在新题或规定变体上独立完成 | 旧产出存在不等于 `RETAINED` | 按题面做冷启动复测 |

## 六步概念节点合同

以后每加入一个概念节点，都按同一顺序写。任何正式术语或公式不得越过它的前置。

1. **问题**：它解决什么问题；没有它会卡在哪里。
2. **微例子**：只用 2 至 4 个对象，且不能复用正式题答案。
3. **正式定义**：给出术语或公式，并逐个解释符号装的是什么。
4. **亲手动作**：让学习者数、画、切或跑一次，留下可检查产物。
5. **接回 EdgeIM**：写清输入、输出、上游供给者和下游消费者。
6. **研究追问**：写优化目标、保留与丢失、主张归属、反例、条件变化和思想来源；没有证据就保留为问题。

每个节点还必须同时记录：`已有证据 -> 当前节点 -> 前置依赖 -> 后继概念 -> 暂时封存`。
